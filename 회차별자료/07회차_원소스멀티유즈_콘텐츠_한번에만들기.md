# 7회차: 원소스 멀티유즈 — 원고 하나로 여러 콘텐츠 한 번에

> 잘 만든 원본 하나가 열 개의 산출물을 낳습니다.
> 원고는 사람이 붙잡고, 모양 바꾸기는 AI에게, 마지막 확인은 다시 사람이 합니다.

## 🗺️ 지금 어디쯤?

| 1 첫 출근 | 2 일 시키는 법 | 3 책상과 기억 | 4 세이브 포인트 | 5 정보 뽑기 | 6 숫자는 코드로 | **▶ 7 원소스 멀티유즈** | 8 도구 상자 | 9 스킬로 | 10 믿을 수 있는 위임 |

## Part 1: 원소스 멀티유즈 — 원본 하나, 산출물 여럿

### 1.1 원소스 = 잘 우린 육수 한 솥

🧩 **비유**: 좋은 육수 한 솥을 우려 두면 국수·찌개·전골을 금방 만듭니다. 맛이 이상하면 찌개마다 간을 고치지 않고 **육수를 고칩니다.** 원고가 육수, PPT·활동지·소식 글이 요리입니다.

**설명**
- **원소스(원본)**: 편집하기 쉬운 마크다운 원고 1개(`.md`). 내용을 고칠 때는 여기를 고칩니다.
- **산출물**: 원고에서 **매번 새로 만들어 내는** 파일들. 4회차의 "최종_진짜최종.pptx 탈출" 규칙과 같은 원리입니다.
- Claude는 **Python**(6회차에서 쓴 그 프로그램 언어)으로 이런 파일을 직접 만듭니다. 필요한 부품을 설치하겠다고 물어보면 승인하시면 됩니다.
- 8회차에서 공식 마켓의 문서 스킬(워드·PPT 관련)을 찾아 설치하면 결과가 더 좋아질 수 있습니다.

| 산출물 | 파일 형식 | 여는 프로그램 | 쓰임 |
|--------|----------|--------------|------|
| 수업·발표 자료 | `.pptx` | 파워포인트 | 수업, 설명회 |
| 활동지·안내문·가이드 | `.docx` | 워드 | 인쇄, 배포 |
| 웹 소식지 | `.html` | 인터넷 브라우저 | 이메일 소식지, 홈페이지 |
| 자막 | `.srt` | 영상 편집 도구(Vrew 등)·유튜브 | 쇼츠·영상 자막 |

**우리 단체 예시**
- 엘리온: STR 원고 1개 → 수업 PPT·학생 활동지·교사 가이드 (E2)
- 미션펀드: 선교사 편지 1통 → 모금 페이지 업데이트 글·쇼츠 대본·SNS 글 (M1·M2)
- 다교연: 연합단체 소식 모음 1개 → 이메일 소식지·홈페이지 공지 (G7)

💭 **확인 질문**: 활동지에서 성경 구절 번호가 틀린 것을 발견했습니다. 어디를 고치고, 그다음 무엇을 해야 할까요?

### 1.2 AI는 '바꾸기', 사람은 '결재'

🧩 **비유**: 슈퍼 스마트한 신입 동료는 밤새 초안 서른 장을 만들어 옵니다. 하지만 어느 것을 내보낼지 **결재**는 팀장이 합니다.

**설명**: AI가 가장 잘하는 일은 새로 지어내기보다 **이미 있는 내용의 모양을 바꾸는 일**(요약·형식 변환·말투 바꾸기·자막 만들기)입니다. 그래서 좋은 원고가 있으면 결과가 좋아집니다.

| 사람이 꼭 하는 일 | AI에게 맡기는 일 |
|------------------|-----------------|
| 목적·대상·핵심 메시지 정하기 | 구성안, 초안 여러 개 |
| 사실·성경 인용·과학 내용 확인 | PPT·Word·자막 파일 만들기 |
| 보여 주면 안 되는 것(보안·초상권·동의) 판단 | SNS별 말투 바꾸기, 해시태그, 썸네일 문구 |
| 최종 승인과 게시 버튼 누르기 | 민감어 가리기 **초안** + 바꾼 목록 |

**우리 단체 예시**: 미션펀드 소식 글은 AI가 몇 분 만에 초안을 만들지만, "이 사진을 공개해도 되는가"는 AI가 판단할 수 없습니다. 담당자가 결정합니다.

💭 **확인 질문**: 위 표에서 선생님 업무 중 '가장 먼저 AI에게 넘기고 싶은 일'은 무엇인가요?

## Part 2: 교육 콘텐츠 트랙 — STR '빛' 원고 하나로 세 가지 (엘리온 E2)

🎯 **목표**: 창조·타락·회복·완성 4막 구조의 원고 하나로 수업 PPT, 학생 활동지, 교사용 가이드를 만든다.

🛠 **준비**
- 실습 데이터 선택: ① 제공된 가상 원고(기본) ② 우리 단체 원고 양식에 가짜 내용을 채운 것 ③ 본인 실제 원고(학생 이름 등 개인정보가 없는지 먼저 확인)
- 원본: `실습자료/07_원고/STR_빛_원고.md` (과학: 빛의 성질·광합성 / 성경: 창 1:3 등)
- 4막 구조는 개혁주의 세계관의 **창조–타락–구속–완성**과 맞닿아 있습니다. 엘리온의 '회복'이 '구속'에 해당합니다.

👣 **단계**

1. 실습 파일을 복사합니다.
   ```
   실습자료/07_원고 폴더의 모든 파일을 실습공간/07회차/원고/로 복사해줘. 원본은 건드리지 마.
   ```
2. 원고부터 파악합니다. 이 표는 나중에 검수할 때 기준이 됩니다.
   ```
   실습공간/07회차/원고/STR_빛_원고.md를 읽고 표로 정리해줘.
   막(창조·타락·회복·완성)별 핵심 한 줄 | 과학 내용 | 성경 구절(장·절 그대로)
   원고에 없는 내용은 넣지 마.
   ```
3. **바로 만들지 말고 구성안부터** 받습니다. (1회차처럼 **Plan** 모드를 써도 됩니다.)
   ```
   실습공간/07회차/원고/STR_빛_원고.md 하나로 세 가지를 만들 거야. 바로 만들지 말고 구성안부터 보여줘.
   ① 빛_수업.pptx: 8~10장. 4막 순서를 지키고, 장마다 제목·핵심 문장 1~2개·그림 아이디어
   ② 빛_활동지.docx: 학생용 A4 2쪽 이내. 관찰하기·생각하기·적용하기 문항
   ③ 빛_교사가이드.docx: 수업 흐름과 시간 배분, 예상 질문과 답, 사용한 성경 구절 목록
   대상은 초등 5~6학년이야.
   규칙: 원고에 없는 사실이나 성경 구절은 새로 넣지 마. 필요하면 [제안]이라고 따로 표시해.
   ```
4. 구성안을 한 번 고쳐 봅니다. (예시)
   ```
   PPT 3번 장은 글자가 너무 많아. 핵심 문장 1개와 그림으로 바꿔줘.
   활동지 마지막 문항은 집에서 가족과 해 볼 수 있는 활동으로 바꿔줘.
   ```
5. 승인하고 만들게 합니다.
   ```
   좋아, 이 구성안대로 세 파일을 실습공간/07회차/산출물/에 만들어줘.
   그림이 들어갈 자리에는 '글자 없는 그림' 설명만 넣고, 글자는 슬라이드에 직접 써줘.
   다 만들면 파일마다 무엇이 들어갔는지 3줄로 알려줘.
   ```
   Claude가 부품 설치나 Python 실행을 물어보면 내용을 읽고 승인합니다.
6. 파일을 직접 열어 봅니다. 파일 탐색기(Mac은 Finder)에서 더블클릭하거나 "만든 파일 세 개를 열어줘"라고 합니다. 파일을 열어 둔 채로 다시 만들게 하면 저장이 안 될 수 있으니, 수정을 시킬 때는 파일을 닫습니다.

> 🖼️ **이미지 속 한글 깨짐(교진추 T6)**
> - AI 이미지 도구에 한글 문장을 그려 달라고 하면 글자가 깨지기 쉽습니다. **그림은 글자 없이, 글자는 PPT에서 얹습니다.**
> - 도표·흐름도는 Claude에게 "PPT 도형으로 그려줘"라고 하면 글자가 진짜 텍스트라 깨지지 않고 고치기도 쉽습니다.
> - Claude Code는 사진·일러스트를 직접 그리는 도구가 아닙니다. 그림이 필요하면 "장면별 이미지 설명 목록(글자 없이)을 이미지목록.md로 만들어줘"라고 해서, 쓰시던 이미지 도구에 넣습니다.
> - 슬라이드에서 그림이 찌그러지면 Shift를 누른 채 모서리를 끌어 비율을 고정하고, 글자 상자의 '자동 맞춤'을 끕니다.

✅ **이렇게 되면 성공**
- `산출물/` 안에 파일 3개가 있고 모두 열린다.
- PPT가 8~10장이고 창조 → 타락 → 회복 → 완성 순서로 흐른다.
- 교사 가이드에 성경 구절 목록이 있고, 단계 2의 표에 있는 구절과 같다.
- 한글이 네모(□)나 깨진 글자 없이 보인다.

🆘 **막히면**
- "Python이 없다"는 말이 나오면: `파이썬 설치돼 있는지 확인하고 없으면 설치해줘`
- 파일이 안 열리면: `이 파일이 열리지 않아. 원인을 찾아서 다시 만들어줘`
- 한글이 네모로 보이면: `글꼴을 이 컴퓨터에 있는 한글 글꼴로 바꿔서 다시 만들어줘`
- 너무 오래 걸리면: `PPT만 먼저 만들고 멈춰줘`처럼 하나씩 나눠 시킵니다.

## Part 3: 소식·홍보 트랙 — 선교사 편지 하나로 네 가지 (미션펀드 M1·M2)

🎯 **목표**: 선교지 소식 원자료 하나로 모금 페이지 업데이트 글, 60초 쇼츠 대본과 자막, SNS별 글을 만들고, 보안국가 버전을 안전하게 가린다.

🛠 **준비**
- 실습 데이터 선택: ① 제공된 가상 편지(기본) ② 실제 편지 양식에 가짜 내용을 채운 것 ③ 본인 실제 자료(일반 국가, 사진 사용 동의 확인 후, 5회차 원칙 적용). **보안국가 실제 자료는 ③으로 하지 않습니다.**
- 원본: `실습공간/07회차/원고/`의 `선교지소식_원자료_일반국가.md`, `선교지소식_원자료_보안국가.md` (Part 2에서 복사해 둠)
- 결과 폴더: `실습공간/07회차/소식/`

👣 **단계**

1. 원자료를 정리합니다.
   ```
   실습공간/07회차/원고/선교지소식_원자료_일반국가.md를 읽고 정리해줘: 핵심 소식 3가지, 감사 제목, 기도제목, 사진 설명 목록.
   원자료에 없는 사건·숫자·감정 표현은 지어내지 마.
   앞으로 이 트랙의 결과 파일은 모두 실습공간/07회차/소식/에 저장해줘.
   ```
2. **① 모금 페이지 업데이트 글** — 미션펀드 페이지 형식 그대로 만듭니다.
   ```
   이 원자료로 모금 페이지 업데이트 글을 써서 소식/업데이트_글.md로 저장해줘. 형식:
   - 첫 줄: #3 (세 번째 소식이라고 가정)
   - ▣ 로 시작하는 소제목 2~3개, 소제목마다 3~4문장
   - 마지막은 ▣ 기도제목 아래에 번호를 붙인 기도제목 3~5개
   후원자에게 쓰는 따뜻한 존댓말로. 과장하지 말고, 원자료에 없는 내용은 넣지 마.
   ```
3. **② 60초 쇼츠 대본 + 자막 파일**
   ```
   같은 원자료로 60초 쇼츠 대본을 표로 만들어 소식/쇼츠_대본.md로 저장해줘.
   열: 시간 | 화면(사진 번호) | 내레이션 | 자막
   구조: 처음 3초 시선 끌기 → 본론 → 마지막에 기도·후원 페이지 안내.
   그다음 자막만 뽑아 소식/쇼츠_자막.srt로 저장해줘. 자막 하나는 2줄 이내로 짧게.
   ```
   `.srt`는 번호·시간·문장이 반복되는 글자 파일입니다. Vrew 같은 편집 도구나 유튜브에 올리면 자막이 됩니다.
   ```
   1
   00:00:00,000 --> 00:00:03,000
   (첫 번째 자막 문장)

   2
   00:00:03,000 --> 00:00:06,500
   (두 번째 자막 문장)
   ```
4. **③ SNS별 글 + 해시태그 + 썸네일 문구**
   ```
   같은 원자료로 소식/SNS_글.md를 만들어줘.
   - 유튜브 설명(5줄 이내), 인스타 캡션(짧게, 줄바꿈 많이), 페이스북 글(조금 길게)
   - 플랫폼별 해시태그 5~10개
   - 썸네일 문구 3안(각 10자 안팎)
   - 사진 사용 동의를 확인해야 하는 항목은 맨 아래에 따로 표시
   ```
   💡 AI로 만든 **사실적인** 이미지·영상을 쓰면 유튜브·인스타·페이스북에서 AI 사용 표시가 필요합니다. AI 음성 내레이션만 쓴 경우 유튜브는 표시 대상이 아니지만, 설명란에 "내레이션: AI 음성"이라고 스스로 적기를 권합니다. 게시는 **예약까지만 자동으로, 마지막 게시 버튼은 사람이** 누릅니다. 이번 회차에서는 글까지만 만들고 게시하지 않습니다.
5. **④ 보안국가 버전** — 모금 페이지용 글만 만듭니다(보안국가 소식은 SNS에 올리지 않습니다).
   ```
   실습공간/07회차/원고/선교지소식_원자료_보안국가.md로 모금 페이지 업데이트 글을 만들되, 민감어를 가려줘. 규칙:
   1. 사람 실명 → 가명 (선교사, 가족, 현지 동역자 모두)
   2. 국가명 → 이니셜 ('V국'처럼). 도시·마을·지역 이름은 삭제
   3. 종교 용어 → 한 글자를 초성으로 (예: 기도→기ㄷ, 복음→ㅂ음, 교회→ㄱ회). 같은 단어는 늘 같은 표기로
   4. 얼굴이 드러나는 사진 설명, 위치를 짐작할 수 있는 정보(건물·간판·랜드마크·교회 이름 등)는 삭제
   5. 형식은 #번호, ▣ 소제목, 번호 붙인 기도제목. 소식/보안국가_업데이트_글.md로 저장
   6. 바꾼 목록은 소식/보안국가_바꾼목록.md에 따로 저장: 원래 표현 | 바꾼 표현 | 규칙 번호. 애매한 것은 '확인 필요'로 표시
   SNS용 글은 만들지 마.
   ```
6. 한 번 더 찾게 하고, **사람이 끝까지 읽습니다.**
   ```
   보안국가_업데이트_글.md만 다시 읽고, 아직 남아 있는 실명·국가·도시·종교 용어·위치 단서를 찾아 표로 보여줘. 없으면 '없음'이라고 해줘.
   ```

> ⚠️ **가리기 결과는 사람의 최종 확인을 대신하지 않습니다.**
> AI는 문맥 속 단서(예: 특정 명절, 현지 음식, 기후)를 놓칠 수 있습니다. 담당자와 보안 책임자 **두 사람이 한 줄씩 읽고 승인**합니다. 한 번 게시된 글은 캡처·보관되므로 삭제로 해결되지 않습니다.
> 실제 보안국가 자료는 AI에 넣지 않는 것이 원칙입니다(5회차 계명 ④). 실제 업무에 쓰려면 5회차 패턴(가짜 샘플로 가리기 도구를 만들고 → 실제 파일은 내 PC에서 처리 → AI에게는 건수만)을 씁니다. `바꾼목록` 파일에는 원래 이름이 들어 있으니 **공유하지 않습니다.**

✅ **이렇게 되면 성공**
- `소식/` 폴더에 파일 6개(업데이트 글, 쇼츠 대본, 자막 .srt, SNS 글, 보안국가 글, 바꾼 목록)가 있다.
- 업데이트 글이 `#3` → ▣ 소제목 → ▣ 기도제목(번호) 형식을 지킨다.
- 보안국가 글에 실명·국가명·도시명·종교 용어 원형이 남아 있지 않고, 바꾼 항목이 바꾼 목록에 빠짐없이 적혀 있다.

🆘 **막히면**
- 초성 표기가 들쭉날쭉하면: `종교 용어 표기표를 먼저 만들고, 그 표대로만 다시 바꿔줘`
- 자막 시간이 겹치거나 60초를 넘으면: `자막 시간이 겹치지 않게, 전체 60초 안에 들어오게 고쳐줘`
- 글이 과장되면: `감정 표현을 원자료 수준으로 낮추고, 원자료에 없는 문장은 빼줘`

> 🎬 **선택 심화 — 영상 자체 만들기**: Claude가 영상을 찍거나 그려 주지는 않지만, **코드로 영상을 만드는 방법**이 있습니다. 사진·자막·내레이션을 정해진 틀(템플릿)에 넣어 쇼츠를 뽑아내는 방식으로, 이런 일을 돕는 Claude Code용 스킬과 오픈소스 도구도 있습니다. 8회차에서 "코드로 영상 만드는 검증된 스킬 찾아줘"로 직접 찾아보고, 마음에 들면 설치해 시험해 봅니다. 그 전까지는 이번에 만든 `.srt`와 대본을 쓰시던 편집 도구에 넣어 쓰시면 됩니다.

## Part 4: 검수 — 작성자와 검수자 나누기 + 기준 예시 보관

### 4.1 쓴 사람과 보는 사람을 나눈다

🧩 **비유**: 내가 쓴 글의 오타는 내 눈에 잘 안 보입니다. 그래서 주보도 다른 사람이 한 번 더 교정을 봅니다.

**설명**
- 같은 대화에서 쓰고 검토하면 AI도 자기 글에 관대해집니다. 그래서 **검수 전담 팀원**을 따로 둡니다.
- 이 튜터 폴더에는 **reviewer**(검수자) 에이전트가 미리 들어 있습니다(`.claude/agents/reviewer.md`). 자기 책상에서 따로 읽고 **검토 보고서만** 가져오므로, 선생님의 대화(책상)도 덜 어지러워집니다.
- 5회차에서 서브에이전트를 잠깐 써 봤지요. 에이전트가 무엇이고 어떻게 만드는지는 **8회차**에서 자세히 다룹니다.

**우리 단체 예시**: 교진추의 청원 발표 PPT 논리 검토(T3)도 같은 원리입니다. 검토자에게 "주장-근거 대응표, 예상 반론, 논리 비약, 인용문 원문 대조"를 따로 맡기면 청원서와 발표의 신뢰도가 올라갑니다.

💭 **확인 질문**: 검수자에게 "문제를 전부 찾아줘" 대신 "정확성에 영향을 주는 문제만 찾아줘"라고 하는 이유는 무엇일까요?

### 4.2 실습: reviewer 검수 → 고치기 → 기준 예시 보관

🎯 **목표**: 검수자에게 따로 검토받아 고치고, 잘 된 1세트를 9회차 재료로 보관한다.

🛠 **준비**: Part 2(또는 Part 3)의 결과물. 더 깊게 한 트랙의 결과로 합니다.

👣 **단계**

1. 검수를 맡깁니다.
   ```
   reviewer 에이전트로 실습공간/07회차/산출물/의 빛_수업.pptx와 빛_활동지.docx를 원고(실습공간/07회차/원고/STR_빛_원고.md)와 비교해 검토해줘.
   검토 항목: ① 논리 흐름(4막 순서와 연결) ② 과학 사실 ③ 맞춤법 ④ 학년 수준(초등 5~6학년) ⑤ 성경 인용 정확성(장·절 번호, 원고와 글자 그대로 같은지, 원고에 없는 구절이 들어갔는지)
   정확성과 이해에 영향을 주는 문제만 표로: 위치 | 문제 | 근거 | 고칠 제안 | 확실/불확실
   ```
   소식 트랙이라면 검토 항목을 "원자료와 다른 사실, 과장, 형식(#번호·▣·기도제목 번호), 보안국가 글의 남은 민감어"로 바꿉니다.
2. 확실한 것부터 고칩니다.
   ```
   검토 결과에서 '확실'한 문제만 원고 기준으로 고쳐서 파일을 다시 만들어줘. '불확실'한 것은 하나씩 나에게 물어봐.
   ```
3. **성경 구절은 사람이 직접 대조합니다.** 선생님이 쓰시는 성경(책 또는 앱)을 펴고 구절 2개 이상을 장·절과 글자 그대로 확인합니다. AI가 기억으로 쓴 구절은 믿지 않습니다.
4. 잘 된 1세트를 보관합니다.
   ```
   지금 결과 중 가장 잘 된 1세트(원고, PPT, 활동지, 교사 가이드)를 실습공간/07회차/기준예시/에 복사해줘.
   그리고 기준예시/기준예시_설명.md를 만들어줘:
   이 세트가 좋은 이유, 검수에서 고친 점, 다음에 같은 걸 만들 때 꼭 지킬 규칙 5개.
   ```
   소식 트랙이면 업데이트 글·쇼츠 대본·자막·SNS 글을 보관합니다. **보안국가 `바꾼목록`은 기준예시에 넣지 않습니다.**

✅ **이렇게 되면 성공**
- 검토 표를 받았고, 확실한 문제는 고쳐졌다.
- 성경 구절 2개 이상을 직접 대조했다.
- `기준예시/` 폴더에 1세트와 `기준예시_설명.md`가 있다.

🆘 **막히면**
- "reviewer 에이전트를 찾을 수 없다"고 하면: `튜터 최신 버전으로 업데이트해줘` 후 다시 시도. 그래도 안 되면 **새 세션**(Ctrl+N / Mac Cmd+N)을 열고 `@실습공간/07회차/원고/STR_빛_원고.md`와 결과 파일을 붙여 "처음 보는 검토자로서 검토해줘"라고 합니다.
- 검수자가 PPT를 못 읽는다고 하면: `PPT와 활동지의 글자를 뽑아 검수용_텍스트.md로 저장한 다음, reviewer 에이전트에게 그 파일과 원고를 비교하게 해줘`
- 지적이 너무 많으면: `정확성에 영향을 주는 문제 5개만 중요한 순서로 다시 골라줘`

## 💬 이번 회차 딸깍 프롬프트 카드

**언제 쓰나**: 원고 하나로 여러 파일을 만들 때 (계획 먼저)
```
○○.md 하나로 PPT(8~10장)·활동지·교사용 가이드를 만들 거야. 바로 만들지 말고 구성안부터 보여줘. 원고에 없는 사실은 넣지 말고, 필요하면 [제안]으로 표시해.
```

**언제 쓰나**: 정해진 형식의 글로 바꿀 때 (모금 페이지 업데이트)
```
이 원자료로 모금 페이지 업데이트 글을 써줘. 첫 줄 #번호, ▣ 소제목 2~3개, 마지막 ▣ 기도제목에 번호 붙인 기도제목 3~5개. 원자료에 없는 내용은 넣지 마.
```

**언제 쓰나**: 영상용 대본과 자막이 필요할 때
```
이 내용으로 60초 쇼츠 대본을 표(시간 | 화면 | 내레이션 | 자막)로 만들고, 자막만 뽑아 .srt 파일로 저장해줘.
```

**언제 쓰나**: 보안이 필요한 소식을 가릴 때 (가상·가명 자료로만)
```
민감어를 가려줘: 실명→가명, 국가→이니셜('V국'), 종교 용어→초성(기ㄷ, ㅂ음), 얼굴·위치 정보 언급 삭제. 바꾼 목록은 별도 파일로 저장하고, 애매한 것은 '확인 필요'로 표시해줘.
```

**언제 쓰나**: 만든 결과를 다른 눈으로 검토받을 때
```
reviewer 에이전트로 ○○을 원본과 비교해 검토해줘. 논리 흐름·사실·맞춤법·대상 수준·인용 정확성. 정확성에 영향을 주는 문제만 표로(위치 | 문제 | 고칠 제안 | 확실/불확실).
```

**언제 쓰나**: 잘 된 결과를 다음에 다시 쓰고 싶을 때
```
이 결과 1세트를 기준예시 폴더에 보관하고, 좋은 이유·고친 점·꼭 지킬 규칙 5개를 기준예시_설명.md로 정리해줘.
```

## 📝 이해 점검 퀴즈

1. **(OX)** PPT에서 오타를 발견하면 PPT 파일만 고치면 충분하다.
2. **(객관식)** AI 이미지 속 한글이 자꾸 깨집니다. 가장 확실한 방법은?
   ① 프롬프트를 더 길게 쓴다 ② 해상도를 높인다 ③ 글자 없는 그림을 만들고 글자는 PPT에서 얹는다 ④ 다른 AI 이미지 도구로 다시 그린다
3. **(짧은 서술)** 보안국가 버전에서 '바꾼 목록'을 따로 받는 이유 한 가지와, 그래도 사람이 끝까지 읽어야 하는 이유 한 가지를 쓰세요.
4. **(객관식)** 글을 쓴 대화가 아니라 reviewer 에이전트에게 검수를 맡기는 가장 큰 이유는?
   ① 더 빨라서 ② 쓴 쪽은 자기 글에 관대해지기 쉬워서 ③ 요금이 싸서 ④ 맞춤법만 볼 수 있어서
5. **(OX)** 쇼츠 대본과 SNS 글을 다 만들었으니, 게시까지 Claude에게 자동으로 맡기는 것이 원칙이다.

### 퀴즈 정답과 해설
1. **X** — 원고(원소스)를 고치고 산출물을 다시 만들거나, 적어도 원고에도 똑같이 반영해야 합니다. 그래야 다음에 다시 만들 때 같은 오류가 되살아나지 않습니다.
2. **③** — 이미지 모델은 글자를 '문자'가 아니라 '그림'으로 그려서 한글이 깨지기 쉽습니다. 글자는 PPT·도형에서 진짜 텍스트로 얹는 것이 가장 확실합니다.
3. 예시 답: 바꾼 목록이 있으면 **무엇을 어떻게 바꿨는지 한눈에 확인**하고 빠진 것을 찾을 수 있습니다. 그래도 AI는 문맥 속 간접 단서(명절·음식·기후·사진 배경 묘사 등)를 놓칠 수 있고, 게시물은 되돌릴 수 없으며, 사람의 생명과 연결된 판단이라 **담당자·보안 책임자 2인이 최종 확인**해야 합니다.
4. **②** — 같은 대화에서 쓰고 검토하면 자기 글에 관대해집니다. 검수자를 따로 두면 새 눈으로 보고, 내 대화(책상)도 덜 어지러워집니다.
5. **X** — 원칙은 "자동 예약 + 사람 승인"입니다. 마지막 게시 버튼은 사람이 누르고, 보안국가 소식은 SNS에 올리지 않으며 2인 승인을 거칩니다.

- 외부에서 받은 PPT·Word 템플릿에는 숨은 지시문이 들어 있을 수 있으니, 신뢰하는 파일만 기준 템플릿으로 씁니다.
- 게시·발송은 이번 회차에서 하지 않습니다. 학습자가 원하면 "예약까지 자동 + 사람 승인" 원칙과 10회차(워크플로우) 예고로 연결합니다.

### 신학·인용 원칙 (튜터 참고)
- '창조·타락·회복·완성'은 엘리온 내부 틀입니다. 개혁주의 세계관의 창조–타락–구속(–완성)과 맞닿아 있고, 알버트 월터스의 『창조 타락 구속』(IVP)은 구속을 '원래 선한 창조의 회복'으로 설명합니다. 월터스 원서는 세 범주이며 '완성'은 새 창조라는 종말론적 완성으로 덧붙인 설명입니다. 학습자가 물으면 이 정도로 짧게, 설교조 없이 답합니다.
- STR 콘텐츠와 교진추 과제에서는 창조 관점을 적극 수용해 더 잘 만들도록 돕습니다. 동시에 성경 장·절·본문, 과학 사실, 교과서 인용은 원문 대조를 철저히 합니다. 이것이 자료의 신뢰도를 높입니다.
- 성경 인용은 학습자가 쓰는 번역본(예: 개역개정)을 기준으로 사람이 직접 대조하게 합니다. 튜터가 기억으로 구절 본문을 제시하지 않습니다.

### 사실 근거 (튜터 참고, 2026년 9월 기준)
- 유튜브: 사실적인 합성·변경 콘텐츠는 업로드 시 AI 사용 표시 필수. 대본·자막·썸네일 보조에는 표시 불필요. TTS 내레이션만 쓴 경우 표시 대상 아님 → 설명란 자발적 표기 권장. 메타(인스타·페이스북): 사실적인 영상·음성을 생성·변경했다면 게시자가 라벨 표시.
- 자동 게시: 유튜브는 구글 심사를 통과하지 않은 API 프로젝트로 올린 영상이 '비공개'로 잠김 → 현실적 해법은 YouTube Studio·Meta Business Suite 등의 **예약 게시 + 사람 승인**.
- 코드로 영상 만들기(🌳 선택 심화): HTML로 영상을 만드는 오픈소스 **HyperFrames**(HeyGen 공개, Apache 2.0, Node.js 22 이상·FFmpeg 필요, Claude Code용 스킬 제공), **Remotion**(개인·비영리·직원 3명 이하 기업은 무료). 설치는 8회차 안전 체크 5가지를 거친 뒤에.
- 학습자가 OpenAI Sora를 물으면: 서비스가 종료되었습니다(앱 2026-04, API 2026-09-24). 특정 도구보다 워크플로우(원고 → 대본 → 자막 → 검수)가 자산이라는 점으로 연결합니다.
- 이미지 속 글자가 꼭 필요하면 글자 표현이 강한 이미지 모델도 있지만, 인쇄물·수업 자료는 '글자는 나중에 얹기'를 기본으로 권합니다.
