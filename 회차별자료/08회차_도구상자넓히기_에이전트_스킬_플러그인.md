## Part 1: 사무실 비유로 보는 도구 6종 (20분)

### 1.1 신입 동료의 사무실 — 도구 6종 한눈에

🧩 **비유**
Claude라는 슈퍼 스마트한 신입 동료가 이제 일에 제법 익숙해졌습니다. 더 잘하게 하려면 사무실을 갖춰 줘야 합니다. 책장에 **업무 매뉴얼**을 꽂고, **전문 팀원**을 붙이고, 출입문에 **자동 규칙**을 달고, 바깥 기관과 **전화선**을 잇습니다. 이 모든 것을 한 상자에 담은 **업무 키트**를 들여오기도 합니다.

📖 **설명**

| 도구 | 사무실 비유 | 하는 일 | 어디에 있나 | 누가 부르나 |
|---|---|---|---|---|
| **스킬**(Skill) | 업무 매뉴얼 | 반복 업무의 절차·기준·양식을 적어 둠. 필요할 때만 펼쳐 봄 | `.claude/skills/이름/SKILL.md` | 내가 `/이름`으로, 또는 Claude가 상황을 보고 알아서 |
| **서브에이전트**(Subagent) | 자기 책상에서 일하고 보고서만 가져오는 전문 팀원 | 조사·검수처럼 따로 떼어 맡길 일을 처리하고 요약만 돌려줌 | `.claude/agents/이름.md` | "○○ 에이전트로 해줘", 또는 Claude가 판단해 맡김 |
| **커스텀 명령어** | 단축 버튼 | 자주 쓰는 지시를 `/이름` 한 번으로 | 지금은 **스킬로 통합**(스킬을 만들면 `/이름`이 생김) | 나 |
| **훅**(Hook) | 반드시 지키는 자동 규칙(출입문 보안 게이트) | 정해진 순간(예: 파일을 고친 직후, 명령을 실행하기 직전)에 프로그램이 **매번** 자동 실행 | 설정 파일(`settings.json`) | 자동(아무도 안 불러도) |
| **커넥터**(MCP) | 외부 연결(바깥 기관과 잇는 전화선) | 구글 캘린더·드라이브·Gmail 같은 외부 서비스와 연결 | **+ → Connectors** | Claude가 필요할 때 |
| **플러그인**(Plugin) | 업무 키트 | 위 부품들을 한 상자로 묶어 설치·공유 | 마켓플레이스(플러그인 가게)에서 설치 | 설치 후 `/플러그인이름:스킬이름` |

- **스킬과 CLAUDE.md의 차이**: 3회차의 CLAUDE.md는 '책상 앞에 붙여 둔 수칙'이라 늘 보입니다. 스킬은 '책장의 매뉴얼'이라 평소엔 제목(설명)만 보이고, 필요할 때만 펼쳐서 책상(컨텍스트)을 거의 차지하지 않습니다.
- **커스텀 명령어**: 예전에는 따로 만들었지만, 지금은 스킬과 합쳐졌습니다. `/compact`처럼 앱에 원래 들어 있는 명령도 있고, 여러분이 만든 스킬도 `/이름`으로 부릅니다.
- **훅이 특별한 이유**: CLAUDE.md나 스킬의 규칙은 Claude가 '지키려고 노력하는 부탁'이라 가끔 놓칠 수 있습니다. 훅은 프로그램이 매번 실행하는 장치라서 잊는 일이 없습니다. 이 과정에서는 직접 만들지 않고 개념만 알아 둡니다.
- **MCP**(Model Context Protocol, AI가 바깥 서비스와 연결하는 표준 규격 — 전기 콘센트 규격처럼 모양이 맞으면 꽂힘)로 연결한 것을 앱에서는 **커넥터**라고 부릅니다.

🏢 **우리 단체 예시** — 미션펀드가 '분기 선교지 소식 키트'를 꾸린다면

| 부품 | 들어갈 내용 |
|---|---|
| 스킬 | 소식 글 작성 매뉴얼(`#번호`, ▣ 소제목, 번호 붙인 기도제목 형식) |
| 서브에이전트 | 보안 점검 팀원 — 실명·국가명·종교 용어가 남았는지 따로 검사해 보고 |
| 훅 | 파일을 저장할 때마다 보안국가 민감어 목록을 자동 검사 |
| 커넥터 | 구글 드라이브의 선교사 편지 폴더 읽기 |
| 플러그인 | 위 모두를 묶어 다른 간사 컴퓨터에도 똑같이 설치 |

💭 **확인 질문**
"매달 소식지를 만들 때마다 같은 형식 설명을 붙여 넣는다"면 여섯 도구 중 무엇이 떠오르나요? 그리고 "보안국가 선교사 실명이 파일에 절대 남으면 안 된다"는 규칙이라면요?

### 1.2 서브에이전트 — 내 책상이 덜 어지러워지는 이유

🧩 **비유**
3회차의 '책상'을 떠올려 보세요. 50쪽짜리 자료 세 개를 내가 직접 다 읽으면 책상이 서류로 뒤덮이고, 처음에 정한 중요한 결정이 서류 밑에 깔립니다. 옆 팀원에게 "이 자료 읽고 1쪽 요약만 가져와 줘"라고 맡기면, 팀원은 **자기 책상**에서 일하고 내 책상엔 보고서 한 장만 올라옵니다.

📖 **설명**
- 서브에이전트는 **자기만의 컨텍스트**(AI가 한 번에 기억하며 보는 대화·자료의 양 = 책상)에서 일합니다. 조사하며 읽은 파일과 검색 결과는 팀원 책상에 남고, 메인 대화에는 요약만 돌아옵니다.
- 그래서 메인 대화가 덜 어지럽고, 오래 일해도 앞의 결정을 잘 기억합니다. 여러 팀원에게 **동시에** 나눠 맡길 수도 있습니다(5회차 "단원별로 나눠 동시에 분석해줘").
- 역할이 다른 팀원 여럿이 함께 일하는 방식을 **멀티 에이전트**라고 합니다. 예: 조사 담당 + 작성 담당 + 검수 담당. 7회차의 '작성자와 검수자 나누기'가 바로 이것입니다.
- 주의: 팀원은 우리 대화를 듣지 못했습니다. 무엇을·왜·어떤 형식으로 가져올지 분명해야 합니다(2회차 위임 브리핑). 보통은 Claude가 지시서를 써서 맡기지만, 중요한 일은 "무엇을 가져오게 할지 먼저 보여줘"라고 확인하세요.

🏢 **우리 단체 예시** — 교과서진화론개정추진회(교진추) 청원 근거 조사
서브에이전트 세 명이 문헌을 나눠 조사하고, 각자 "문헌명·쪽수·원문 인용·출처 URL" 표만 가져옵니다. 메인 대화는 표 세 장으로 청원 논거를 정리하고, 마지막에 reviewer가 인용문을 원문과 글자 그대로 대조합니다. 교진추의 관점을 살린 논거가 **정확한 인용** 위에 서게 되어 청원서의 신뢰도가 올라갑니다.

💭 **확인 질문**
긴 PDF 다섯 개를 비교해야 할 때, 메인 대화에서 직접 다 읽게 하는 것과 서브에이전트에게 나눠 맡기는 것은 '책상' 관점에서 어떻게 다를까요?

> 💡 눈으로 확인하고 싶다면: 조사를 맡기기 전과 후에 모델 선택기 옆 **사용량 링**을 눌러 컨텍스트 사용량을 비교해 보세요.

### 1.3 해부 실습 — 우리 튜터는 무엇으로 만들어졌을까?

🎯 **목표**: 지금까지 함께한 튜터가 **스킬 + 출력 스타일 + 서브에이전트 + 설정**으로 조립되어 있음을 직접 확인합니다.

🛠 **준비**
- 이 튜터 폴더(`gea-claude-tutor`)를 연 세션. 권한 모드는 **Manual** 또는 **Plan** 권장.
- 이번 실습은 **읽기만** 합니다. 이 파일들을 고치면 튜터 동작이 달라질 수 있습니다.
- 📂 실습 데이터: 이번 실습은 튜터 설정 파일만 읽으므로 개인정보가 없습니다.

👣 **단계**
1. 폴더 구조부터 봅니다.
   ```text
   이 튜터 폴더의 .claude 폴더 안에 어떤 파일이 있는지 나무 모양으로 보여주고, 각 파일이 사무실 비유로 어떤 역할인지 한 줄씩 설명해줘. 파일은 절대 고치지 마.
   ```
2. 튜터 본체 매뉴얼을 엽니다.
   ```text
   .claude/skills/gea-tutor/SKILL.md 를 열어서 맨 위 --- 사이의 앞머리(name, description)와 아래 본문이 각각 무슨 역할인지 쉽게 설명해줘. 내가 매 회차 겪은 "한 번에 한 Part", "퀴즈는 힌트부터" 규칙이 어디에 적혀 있는지도 찾아줘.
   ```
3. 3회차에 쓴 `/handoff`의 정체를 봅니다: `.claude/skills/handoff/SKILL.md`. 앞머리의 **description**이 "언제 이 매뉴얼을 꺼내는지"를 알려 주는 표지 역할입니다. (자세한 해부는 9회차)
4. 검수 팀원을 봅니다.
   ```text
   .claude/agents/reviewer.md 를 열어서 앞머리의 name, description, tools 가 각각 무슨 뜻인지 설명해줘. 이 팀원이 파일을 고칠 수 있는지 없는지, 왜 그렇게 만들었을지도 말해줘.
   ```
5. 응대 수칙을 봅니다: `.claude/output-styles/gea-tutor.md`와 `.claude/settings.json`. 매 응답 첫 줄의 🗺️ 위치 표시와 쉬운 말투가 여기서 나옵니다. 출력 스타일은 사무실의 **응대 수칙**(전화 받는 말투·첫 인사 규칙)쯤 됩니다.
6. 정리를 부탁합니다.
   ```text
   방금 본 파일들을 "파일 | 부품 종류 | 사무실 비유 | 내가 겪은 장면" 표로 정리해줘.
   ```

✅ **이렇게 되면 성공**

| 파일 | 부품 | 사무실 비유 | 내가 겪은 장면 |
|---|---|---|---|
| `.claude/skills/gea-tutor/SKILL.md` | 스킬 | 튜터 업무 매뉴얼 | "N회차 시작" → 한 Part씩 진행 |
| `.claude/skills/handoff/SKILL.md` | 스킬 | 인수인계 매뉴얼 | 3회차 `/handoff` |
| `.claude/agents/reviewer.md` | 서브에이전트 | 검수 전문 팀원(읽기만, 보고만) | 7회차 PPT·활동지 검수 |
| `.claude/output-styles/gea-tutor.md` | 출력 스타일 | 응대 수칙 | 첫 줄 🗺️ 위치 표시 |
| `.claude/settings.json` | 설정 | 사무실 운영 규정 | 학습기록 저장 승인 생략, 튜터 말투 자동 적용 |

이 표를 보며 "우리 튜터 = 매뉴얼 2권 + 검수 팀원 1명 + 응대 수칙 + 운영 규정"이라고 말할 수 있으면 성공입니다.

🆘 **막히면**
- 파일 탐색기·Finder에서 `.claude`가 안 보여요 → 이름이 점(.)으로 시작하는 폴더는 (특히 Mac에서) **숨김 폴더**로 취급됩니다. Claude에게 보여 달라고 하면 충분합니다. (직접 보려면 Windows 파일 탐색기 **보기 → 표시 → 숨긴 항목**, Mac Finder **Cmd+Shift+.** — 화면 문구는 조금 다를 수 있습니다.)
- 내용이 교재 설명과 조금 달라요 → 튜터 버전에 따라 문장이 바뀔 수 있습니다. 구조(앞머리 + 본문)와 역할만 확인하면 됩니다.
- Claude가 파일을 고치겠다고 해요 → **Reject**를 누르고 "읽기만 해줘"라고 다시 말합니다.

## Part 2: 공식 마켓에서 설치하기 — skill-creator (20분)

### 2.1 마켓플레이스와 설치 범위

🧩 **비유**
**마켓플레이스**는 업무 키트를 파는 가게입니다. Anthropic이 운영하는 **공식 마켓**(`claude-plugins-official`)은 앱에 기본으로 들어 있습니다. 키트를 사 오면 어디에 둘지도 정해야 합니다. 내 책상 서랍에 두면 어느 방에서든 꺼내 쓰고, 팀 공용 캐비닛에 두면 팀원 모두가 쓰고, 이 방에만 두면 이 방에서만 씁니다.

📖 **설명** — 설치 범위 3가지

| 범위 | 비유 | 누가, 어디서 쓰나 | 이럴 때 |
|---|---|---|---|
| **내 계정**(user) | 내 책상 서랍 | 나만, **모든 폴더**에서 | 어디서나 쓰는 도구(skill-creator, gea-toolkit) |
| **이 프로젝트**(project) | 팀 공용 캐비닛 | 이 폴더를 함께 쓰는 모두(단, 각자 한 번은 설치 필요) | 팀이 Git으로 같이 쓰는 폴더의 공통 도구 |
| **이 폴더만**(local) | 이 방에만 | 나만, 이 폴더에서만 | 한 업무에만 필요한 도구를 시험해 볼 때 |

- 설치하면 입력창에 `/`를 쳤을 때 `/플러그인이름:스킬이름` 형태로 보입니다. 이름 앞에 플러그인 이름표가 붙어서, 같은 이름의 스킬이 있어도 헷갈리지 않습니다.
- 플러그인의 설명(제목)도 책상 한쪽을 조금씩 차지합니다. 많이 설치할수록 좋은 게 아니라, **쓰는 것만** 켜 두는 게 좋습니다(3회차 책상 정리와 같은 원리).

🏢 **우리 단체 예시**
- skill-creator → 어느 폴더에서든 스킬을 만들 테니 **내 계정**.
- 다교연 법인 서류 폴더에서만 쓸 문서 도구 → 먼저 **이 폴더만**으로 시험, 좋으면 넓히기.
- 엘리온에듀학원 선생님들이 같은 STR 콘텐츠 폴더를 Git으로 함께 쓴다면 → **이 프로젝트**.

💭 **확인 질문**
처음 보는 GitHub 도구를 시험 삼아 설치할 때는 세 범위 중 무엇이 가장 안전할까요? 이유도 한 줄로 말해 보세요.

### 2.2 실습: 공식 마켓에서 skill-creator 설치

🎯 **목표**: 공식 마켓에서 **skill-creator**(스킬 만들기를 도와주는 플러그인, 9회차에 사용)를 **내 계정** 범위로 설치하고, 설치 확인과 관리 위치를 익힙니다.

🛠 **준비**
- 이 튜터 폴더를 연 세션(환경 **Local**). 인터넷 연결.
- 📂 실습 데이터: 파일을 다루지 않는 실습입니다.

👣 **단계**
1. 입력창 옆 **+** 버튼 → **Plugins** → **Add plugin**을 누릅니다. 플러그인 브라우저가 열리고 공식 마켓의 플러그인 목록이 보입니다.
2. 목록을 1~2분 둘러봅니다. 어떤 종류의 키트가 있는지 구경만 합니다.
3. **skill-creator**를 찾아 선택하고 설명을 읽습니다. 설명이 영어라 어렵다면 Claude에게 물어봅니다.
   ```text
   공식 마켓의 skill-creator 플러그인이 무엇을 하는지, 설치하면 무엇이 추가되는지 초등학생도 알게 설명해줘. 모르는 부분은 추측하지 말고 모른다고 해줘.
   ```
4. 설치 범위로 **내 계정**(user)을 고르고 설치합니다. 화면 문구는 조금 다를 수 있습니다.
5. 설치를 확인합니다. 입력창에 `/skill`까지 입력해 보세요. `/skill-creator:`로 시작하는 항목이 보이면 설치된 것입니다. (지금 실행하지는 않습니다 — 9회차에 씁니다.)
6. 관리 위치를 확인합니다. **+ → Plugins → Manage plugins**에서 skill-creator가 목록에 있는지 보고, 켜기·끄기·삭제 버튼 위치만 눈으로 익힙니다. 사이드바의 **Customize**에서도 커넥터·스킬·플러그인을 한곳에서 볼 수 있습니다.
7. (둘러보기) 목록에서 엑셀·워드·PPT·PDF 같은 **문서 관련** 플러그인이 보이면 이름만 메모해 두세요. 설치는 Part 3의 안전 체크를 배운 뒤 실전 과제에서 합니다.

✅ **이렇게 되면 성공**
- `/`를 입력했을 때 `/skill-creator:…` 항목이 보입니다.
- **Manage plugins** 목록에 skill-creator가 있고, 범위가 내 계정으로 되어 있습니다.

🆘 **막히면**
- **Plugins** 메뉴나 플러그인 브라우저가 안 보여요 → 세션 환경이 **Local**인지 확인하세요. 클라우드 세션에서는 플러그인 브라우저를 쓸 수 없습니다. 새 세션(**Ctrl+N** / Mac **Cmd+N**)에서 다시 해 봅니다.
- 설치했는데 `/`에 안 보여요 → 새 세션을 열어 다시 `/skill`을 입력해 보세요.
- skill-creator를 못 찾겠어요 → Claude에게 "공식 마켓에서 skill-creator 플러그인을 내 계정 범위로 설치하도록 도와줘. 무엇을 바꾸는지 먼저 알려줘"라고 부탁합니다. Claude가 명령 실행이나 설정 변경을 물어보면 설명을 듣고 승인합니다.
- 팀(Team) 플랜에서 설치가 막혀요 → 단체 관리자 설정으로 제한되어 있을 수 있습니다(확인 필요). 단체 관리자에게 문의하세요.

## Part 3: 먼저 찾고, 안전하게 설치하기 (20분)

### 3.1 도구를 찾는 순서 — 바퀴를 다시 만들지 않기

🧩 **비유**
눈치 빠른 신입은 새 업무를 받으면 먼저 "혹시 선배들이 만들어 둔 양식 있어요?"라고 묻습니다. 없으면 그때 직접 만들고, 한 번 쓰고 끝날 일이면 간단히 만들어 쓰고 치웁니다. 같은 일이 자꾸 돌아오면 그제야 정식 매뉴얼로 만들어 책장에 꽂습니다.

📖 **설명** — 도구의 순환(원 자료의 Flywheel 사이클 재구성)

```text
필요가 생김 → ① 이미 가진 도구 확인 → ② 공식 마켓 → ③ GitHub 등 공개 도구(안전 체크)
            → ④ 없으면 Claude에게 만들게 함 → 사용 → 반복되면 스킬로 보관(9회차) / 아니면 버림
```

- **일회용 도구**(디스포저블 앱): 한 번의 일을 위해 Claude가 10~30분 만에 만들어 주고, 일이 끝나면 버려도 되는 작은 프로그램입니다. 6회차의 후원 점검 스크립트도 처음엔 이런 도구였습니다. 필요하면 또 만들면 되니 관리 부담이 없습니다.
- **보관할 때**: 같은 일을 세 번째 하고 있다면 도구로 만들어 둘 시점입니다. 9회차에서 스킬로 보관합니다.
- 찾는 문장은 2회차 메타프롬프트 ⑥입니다: "이 일을 해주는 검증된 도구나 플러그인이 이미 있는지 먼저 찾아줘."

🏢 **우리 단체 예시**
미션펀드가 한글(HWP) 신청서를 다룰 때(M3): ① 5회차처럼 "다른 이름으로 저장 → docx"로 되는지 확인 → ② 공식 마켓에 관련 도구가 있는지 → ③ GitHub에 HWP를 읽는 공개 도구가 있는지 안전 체크와 함께 비교 → ④ 없으면 Claude에게 이번 분기용 일회용 변환 도구를 만들어 달라고 합니다.

💭 **확인 질문**
지난 회차들에서 선생님이 세 번 이상 반복한 일이 있었나요? 그 일은 '일회용 도구'와 '보관할 도구' 중 어느 쪽에 가까운가요?

### 3.2 설치 전 안전 체크 5가지

🧩 **비유**
외부 업체 직원을 사무실에 들이기 전에 확인하는 것과 같습니다. 어느 회사 사람인지, 지금도 영업 중인지, 와서 무슨 일을 하는지, 어느 방까지 들어가는지, 우리 서류를 들고 나가는지.

📖 **설명**

| # | 체크 | 무엇을 보나 | Claude에게 이렇게 묻기 | 🚩 빨간불 |
|---|---|---|---|---|
| 1 | **출처** | 누가 만들었나(공식 마켓·알려진 회사·개인), 별(★) 수, 사용자 수 | "이 도구를 만든 곳과 신뢰할 만한 근거를 알려줘" | 만든 사람을 알 수 없음, 복사본·가짜 이름 |
| 2 | **최근 업데이트** | 마지막 수정 날짜, 문제 신고(이슈)에 답하는지 | "마지막 업데이트가 언제고, 관리되고 있는지 확인해줘" | 1~2년 넘게 방치, 버그 신고에 무응답 |
| 3 | **실행 내용 요약** | 설치하면 무엇이 추가되고 실행되나(스킬·에이전트·훅·커넥터·프로그램 설치) | "설치하면 내 컴퓨터에서 무엇이 실행되는지 쉬운 말로 요약해줘" | 설명과 실제 내용이 다름, 이유 없는 프로그램 설치 |
| 4 | **권한** | 어떤 파일을 읽고 쓰는지, 어떤 명령을 실행하는지, 어떤 계정 접근을 요구하는지 | "이 도구가 필요로 하는 권한을 표로 정리해줘" | 하는 일에 비해 과한 권한(전체 폴더 삭제, 비밀번호 요구 등) |
| 5 | **개인정보 전송** | 내 파일·내용이 외부 서버로 나가는지 | "내 파일이나 내용이 외부로 전송되는지, 어디로 가는지 확인해줘" | 외부 서버 업로드인데 설명이 없음 |

- 플러그인은 훅(자동 실행 규칙)과 커넥터(외부 연결)를 함께 담을 수 있어서, **공식 마켓이라도 설명은 꼭 읽고** 설치합니다.
- Claude의 점검 결과도 '추측'이 섞일 수 있습니다. "확실/불확실/추측을 표시해줘"를 붙이고, 🚩가 하나라도 있으면 설치하지 않거나 **이 폴더만** 범위에서 가상 데이터로만 시험합니다.
- 이 튜터의 일상 실습에 들어 있는 **블로그 도우미 확장**처럼 '개발자 모드'로 직접 설치하는 브라우저 확장도 같은 5가지로 봅니다(어디에 접속하는지·무엇을 읽는지).

🏢 **우리 단체 예시**
교진추가 찾은 PDF 분석 도구가 "문서를 외부 서버에 올려 글자를 읽는다"고 합니다. 공개된 교과서 PDF라면 괜찮을 수 있지만, 같은 도구를 미션펀드 신청서(실명·연락처)에 쓰면 5번에서 🚩입니다. 같은 도구라도 **어떤 자료에 쓰느냐**에 따라 답이 달라집니다.

💭 **확인 질문**
별이 아주 많은 인기 도구인데, 2년째 업데이트가 없고 설치 때 별도 프로그램을 내려받는다고 합니다. 5가지 중 어디에 걸리고, 선생님이라면 어떻게 하시겠어요?

### 3.3 실습 A: GitHub에서 찾아 비교표 받기

🎯 **목표**: 메타프롬프트 ⑥으로 공개 도구를 찾아 비교표를 받고, 안전 체크 5가지를 적용해 봅니다. **이번엔 설치하지 않습니다.**

🛠 **준비**
- 이 튜터 폴더 세션 또는 새 세션. 결과 저장 폴더 `실습공간/08회차/`.
- 📂 실습 데이터: 검색만 하므로 파일을 넣지 않습니다. 나중에 도구를 시험할 때는 ① 가상 샘플(기본) ② 실제 양식 기반 가상 데이터 ③ 본인 실제 파일(5회차 점검 먼저) 중 고르되, **새로 설치한 도구는 반드시 ①로 먼저** 시험합니다.

👣 **단계**
1. 주제를 고릅니다. 기본 주제는 모든 단체가 겪는 "한글(HWP) 파일 읽기"입니다. 관통 프로젝트와 관련된 주제로 바꿔도 좋습니다.
2. 아래 문장을 붙여 넣습니다.
   ```text
   한글(HWP) 파일을 읽거나 docx·pdf로 바꿔 주는 검증된 Claude Code 플러그인이나 스킬, 오픈소스를 GitHub에서 찾아 3~5개 비교표로 보여줘.
   열: 이름 | 만든 곳 | 별 수 | 최근 업데이트 | 무엇을 실행하는지 | 필요한 권한 | 외부 전송 여부 | 주의점.
   각 칸에 확실/불확실/추측을 표시하고, 링크를 붙여줘. 설치는 하지 마.
   결과는 실습공간/08회차/도구비교_HWP.md 로 저장해줘.
   ```
3. 표에서 마음에 드는 후보 하나를 골라 안전 체크를 더 깊이 해 봅니다.
   ```text
   이 중 ○번 도구를 설치 전 안전 체크 5가지(출처, 최근 업데이트, 실행 내용 요약, 권한, 개인정보 전송)로 점검해줘. 🚩 빨간불이 있으면 먼저 알려줘.
   ```
4. 링크 한두 개를 직접 열어 별 수와 최근 업데이트 날짜가 표와 맞는지 확인합니다(2회차 할루시네이션 검증).

✅ **이렇게 되면 성공**
- `실습공간/08회차/도구비교_HWP.md`에 비교표가 저장되어 있습니다.
- 후보 하나에 대해 5가지 체크 결과를 선생님 말로 설명할 수 있고, 링크 1개 이상을 직접 확인했습니다.

🆘 **막히면**
- 찾은 도구가 하나도 없대요 → "Claude Code 전용이 아니어도 되니, 파이썬 라이브러리 같은 일반 오픈소스까지 넓혀서 찾아줘"라고 범위를 넓힙니다.

### 퀴즈 정답과 해설

1. **②** 서브에이전트. 자기 컨텍스트에서 읽고 요약만 돌려주므로 메인 대화가 덜 어지럽습니다. 스킬은 절차를 알려 주는 매뉴얼일 뿐, 읽은 자료는 여전히 메인 책상에 쌓입니다.
2. **O**. 스킬을 만들면 `/이름`이 생기고, 예전 방식의 명령어 파일도 계속 동작합니다.
3. **①** 내 계정. '이 프로젝트'·'이 폴더만'은 그 폴더에서만 켜집니다.
4. **훅**. CLAUDE.md는 Claude가 지키려 노력하는 부탁이라 놓칠 수 있지만, 훅은 정해진 순간 프로그램이 매번 실행합니다. (힌트 순서: "사람이 잊어도 지켜지는 규칙은 어느 쪽일까요?")
5. **바로 쓰면 안 됩니다.** 5번(개인정보 전송)에 걸리고, 실명·연락처가 외부 서버로 나갑니다. 대안: 가상 샘플로만 시험, 내 PC 안에서 처리하는 도구 찾기, 또는 5회차 패턴(가짜 샘플로 AI가 스크립트를 만들고 실제 파일은 내 PC에서 처리). 별 수(1번 출처)만으로 안전을 판단하지 않는다는 점도 짚습니다.

### 실전 과제 검수 기준

- 비교표에 후보 2개 이상, 각 후보에 출처·최근 업데이트·실행 내용·외부 전송 여부가 있고 확실/불확실/추측 표시가 있다.
- 안전 체크 5가지를 설치할 도구에 모두 적용했고, 🚩가 있으면 설치하지 않았거나 이유를 적었다.
- 새 도구는 **가상 샘플로 먼저** 시험했다(실제 파일을 썼다면 5회차 점검 기록이 있다).
- 채택/미채택과 그 이유가 `내_프로젝트.md` 또는 과제 폴더에 남아 있다.
- 교진추 과제: 인용문 대조가 글자 단위로 되어 있고, 불일치는 그대로 표시했다. 청원 관점은 적극 살리되, 인용·쪽수의 정확성은 엄격히 봅니다.
- SHINE 과제: 영상 도구가 추가 프로그램을 설치한다면 무엇을 설치하는지 기록했다.
- 검수는 reviewer 에이전트나 `/gea-toolkit:self-review`를 써도 좋고, 최종 판단은 학습자가 합니다.

### 안전·개인정보 주의

- 공개 도구를 설치할 때는 항상 **안전 체크 5가지**를 먼저 합니다. 플러그인은 훅과 커넥터를 담을 수 있어 설치 즉시 무언가가 자동 실행될 수 있습니다. 🚩가 있으면 설치를 권하지 않습니다.
- 새로 설치한 도구로 실제 파일(후원자·신청서·학생 정보)을 처리하기 전에 5회차 개인정보 5계명을 상기시킵니다. **보안국가 선교사 정보는 어떤 도구·커넥터에도 넣지 않습니다.**
- 커넥터로 읽은 일정·메일·드라이브 내용도 전송·처리됩니다. 필요한 서비스만 연결하고, 쓰지 않으면 **설정 → Connectors**에서 끊도록 안내합니다. 로그인과 권한 허용은 학습자가 직접 합니다.
- 튜터 폴더의 `.claude/` 파일은 해부 실습에서 **읽기만** 합니다. 학습자가 고치고 싶어 하면, 9회차에서 자기 폴더에 새 스킬을 만드는 쪽으로 안내합니다.
- 비교표의 별 수·날짜·기능 설명은 Claude의 요약이므로 링크를 직접 열어 확인하게 합니다(2회차 할루시네이션 3단계 검증).
