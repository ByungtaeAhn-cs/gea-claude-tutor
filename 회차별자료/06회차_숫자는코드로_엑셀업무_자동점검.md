> AI에게 숫자를 '말'하게 하지 말고, 계산하는 '도구'를 만들게 하세요.
> 기준은 사람이 정하고, 계산은 코드가 하고, 마지막 확인(검산)은 사람이 합니다.

## Part 1: 왜 AI 암산은 위험한가

### 1.1 암산하는 신입 vs 계산기를 만들어 주는 신입

🧩 **비유**
신입 두 명에게 "9월 후원금 합계 좀 알려줘"라고 부탁했습니다.
- **신입 A**는 장부를 쓱 훑어보고 "183만 원입니다!"라고 바로 말합니다. 대개 맞지만 가끔 틀리고, 어떻게 셌는지 보여 줄 수 없습니다. 다시 물으면 다른 숫자가 나올 때도 있습니다.
- **신입 B**는 "계산하는 엑셀 서식(또는 작은 프로그램)을 만들어 두었습니다. 누르면 계산되고, 계산 과정도 보입니다. 다음 달에도 파일만 바꿔 쓰시면 됩니다"라고 말합니다.

후원금을 맡긴다면 누구를 믿으시겠어요? Claude를 **신입 B처럼** 쓰는 것이 이번 회차의 전부입니다.

**설명**
2회차에서 배웠듯 AI는 "다음에 올 말을 예측하는 기계"입니다. 숫자도 **그럴듯하게** 만들어 낼 수 있습니다. 60명 × 3개월처럼 줄이 많으면 한 줄을 빠뜨리거나 두 번 세는 실수도 생길 수 있습니다. 반면 스크립트(작은 계산 프로그램)나 엑셀 수식은 **같은 입력이면 매번 같은 결과**를 냅니다.

| 비교 | AI가 말로 답한 숫자 | AI가 만든 스크립트·수식이 계산한 숫자 |
|------|--------------------|-------------------------------------|
| 같은 결과가 나오나 | 물을 때마다 다를 수 있음 | 매번 같음(재현 가능) |
| 과정을 볼 수 있나 | 어렵다 | 코드·수식을 열어 보면 보임 |
| 검산할 수 있나 | 무엇과 대조할지 막막 | 원본 합계·표본과 대조 가능 |
| 다음 달에는 | 처음부터 다시 | 파일만 바꿔 다시 실행 |
| 개인정보 | 파일을 통째로 읽혀야 함 | 가짜 샘플로 만들고 실제 파일은 내 PC에서 처리(5회차) |

실제 사례도 있습니다. Microsoft는 엑셀 셀 안에서 AI가 답을 내는 **COPILOT 함수**를 내놓으면서 "정확성이 필요한 계산에는 쓰지 말라"고 안내했고, 이 함수는 2026년 9월 14일 제공이 끝났습니다. AI 회사들도 **"계산은 계산 도구로"**라고 말하는 셈입니다.

**우리 단체 예시**
다교연은 매달 미션펀드에서 후원자 내역 엑셀을 받습니다. "이 파일 성공 몇 건이야?"라고 물으면 신입 A가 됩니다. "성공·실패를 세는 **스크립트를 만들어 실행**하고, 결과는 실행한 값으로만 알려줘"라고 하면 신입 B가 됩니다.

💭 **확인 질문**: Claude가 "9월 실입금액 합계는 1,830,000원입니다"라고 답했습니다. 똑같이 한 번 더 물었더니 같은 숫자가 나왔습니다. 이제 믿어도 될까요? 왜 그렇게 생각하시나요?

### 1.2 판단은 사람이, 계산은 코드가

🧩 **비유**
팀장이 "두 달 연속 미납이면 전화 드리자"라고 **기준**을 정해 주면, 신입은 그 기준대로 명단을 뽑습니다. 그런데 신입이 기준까지 마음대로 정하면 어떨까요? 나중에 "왜 두 달이야?"라고 물었을 때 아무도 설명하지 못합니다.

**설명**
"몇 번 실패해야 장기 실패인가"는 **계산 문제가 아니라 업무 판단**입니다. 후원자와의 관계, 연락할 수 있는 인력, 단체 방침에 따라 달라지기 때문입니다. 그래서 역할을 이렇게 나눕니다.

| 누가 | 무엇을 |
|------|--------|
| 🙋 사람(선생님) | 판정 기준 정하기, 애매한 경우 판단, 누구에게 연락할지 최종 결정 |
| 🤖 Claude | 기준을 정하도록 **질문(인터뷰)**, 스크립트·수식 작성, 결과 설명 |
| ⚙️ 코드(스크립트·수식) | 정해진 기준대로 계산·분류·집계 — 매번 똑같이 |
| 🙋 사람 + 다른 도구 | 검산: 원본 합계 대조, 무작위 3명 직접 확인 |

정한 기준은 **파일(`판정기준.md`)로 남깁니다.** 스크립트는 그 파일을 따르고, 기준이 바뀌면 파일만 고치면 됩니다.

**우리 단체 예시**
같은 '실패'라도 사유가 다릅니다. **잔액부족** 1회는 다음 달에 저절로 해결될 수 있지만, **계좌해지·카드만료**는 후원자가 정보를 바꾸지 않으면 다음 달에도 실패합니다. 이것을 "바로 연락"으로 볼지 "한 달 기다림"으로 볼지는 단체가 정할 일입니다.

💭 **확인 질문**: "카드만료로 한 번 실패한 후원자를 바로 연락 명단에 넣을지"는 누가 정해야 할까요? Claude에게 맡기면 어떤 문제가 생길까요?

## Part 2: 후원 엑셀 자동 점검 (다교연 G2·G3, 미션펀드)

> **실습 데이터 선택**: 튜터가 먼저 묻습니다 — ① 제공된 가상 샘플(기본) ② 실제 양식 기반 가상 데이터(빈 양식을 주시면 가짜 내용을 채워 만듦) ③ 본인 실제 파일(개인정보 점검 먼저). ③이라면 AI가 파일을 직접 열지 않는 5회차 패턴(열 이름 + 가짜 샘플로 스크립트 → 실제 파일은 내 PC에서 → AI에겐 개수·합계만)으로 진행합니다. 처음이라면 ①로 한 바퀴 돌린 뒤 실전 과제에서 ③을 권합니다.

### 2.1 파일 구조 파악과 판정 기준 정하기 (10분)

🎯 **목표**: 후원 파일 3개의 구조를 확인하고, 일시/장기 실패 기준을 **선생님이 직접** 정해 `판정기준.md`로 남긴다.

🛠 **준비**
- 실습자료: `실습자료/06_후원데이터/후원내역_2026-07.xlsx`, `후원내역_2026-08.xlsx`, `후원내역_2026-09.xlsx` (가상 후원자 60명 내외, 가명)
- 열: 후원자ID, 이름, 연락처, 후원상품, 약정금액, 결제수단, 출금일, 결제상태, 실패사유, 실입금액
- 권한 모드: **Manual** 또는 **Accept edits** (Bypass permissions는 쓰지 않음)

👣 **단계**

1. 파일을 복사하고 구조부터 보게 합니다. 아래를 입력하세요.

```
실습자료/06_후원데이터/ 폴더의 후원내역_2026-07.xlsx, 후원내역_2026-08.xlsx, 후원내역_2026-09.xlsx 세 파일을 실습공간/06회차/로 복사해줘.
그다음 복사본의 구조를 설명해줘: 시트 이름, 열 이름, 파일별 행 수, 각 열에 들어 있는 값의 종류(예: 결제상태와 실패사유에 어떤 값들이 있는지).
이름·연락처 같은 개인정보 열은 '개인정보 열'이라고 표시만 하고 실제 내용은 보여주지 마.
```

2. Claude가 엑셀 파일을 읽으려고 파이썬 명령을 실행하겠다고 물어보면, 무엇을 하는 명령인지 읽어 보고 승인합니다. 필요한 도구(엑셀 파일을 읽는 파이썬 부품)를 설치하겠다고 하면 그것도 승인합니다.
3. 설명을 읽으며 확인합니다: 결제상태는 `성공/실패`, 실패사유는 `잔액부족/계좌해지/카드만료/한도초과/기타`, 결제수단은 `CMS/카드`인가요?
4. 이제 **판정 기준을 정합니다.** Claude는 질문만 하고, 결정은 선생님이 합니다.

```
후원 점검에서 '일시 실패'와 '장기 실패'를 나누는 기준을 정하려고 해. 기준은 내가 정할 거야.
실습공간/06회차/의 7~9월 파일 구조를 참고해서, 기준을 정하는 데 필요한 질문을 하나씩 해줘. 선택지가 있으면 보여줘.
꼭 물어볼 것: 몇 개월 연속 실패부터 장기로 볼지, 실패 사유(계좌해지·카드만료 등)에 따라 다르게 볼지, 신규 후원자는 어떻게 정의할지, 지난달엔 있었는데 이번 달 파일에 없는 후원자는 어떻게 볼지.
다 정해지면 내가 답한 그대로 실습공간/06회차/판정기준.md에 정리해줘. 네가 제안만 하고 내가 확정하지 않은 부분은 '[미확정]'으로 표시해.
```

5. 질문에 답합니다. 잘 모르겠으면 "선택지별 장단점을 알려줘"라고 되물어도 됩니다. 저장된 `판정기준.md`를 열어 **내가 정한 그대로인지** 확인합니다.

예를 들어 이렇게 정할 수 있습니다(정답은 없습니다 — 단체 방침대로).

```
# 후원 점검 판정 기준 (정한 사람: 나 / 2026-09)
- 일시 실패: 이번 달 실패, 지난달은 성공(또는 지난달 기록 없음)
- 장기 실패: 2개월 이상 연속 실패
- 정보 변경 필요: 실패사유가 계좌해지·카드만료이면 개월 수와 관계없이 별도 표시
- 신규 후원자: 이번 달 파일에 있고 이전 두 달 파일에는 없는 후원자ID
- 빠진 후원자: 지난달 파일에는 있는데 이번 달 파일에 없는 후원자ID (해지 추정 → 사람이 확인)
```

✅ **이렇게 되면 성공**
- `실습공간/06회차/`에 xlsx 3개가 복사되어 있고, 원본 `실습자료/`는 그대로다.
- 구조 설명에 이름·연락처의 **실제 내용이 나오지 않았다.**
- `판정기준.md`에 선생님이 정한 기준이 있고, `[미확정]` 항목이 없다(있다면 지금 정하기).

🆘 **막히면**
- "python을 찾을 수 없다"는 식의 오류 → 1회차처럼 `파이썬 설치돼 있는지 확인하고 없으면 설치해줘`라고 말합니다. 설치 후에도 인식이 안 되면 새 세션을 열거나 앱을 다시 켠 뒤 시도해 보세요.
- 열 이름이 위 목록과 조금 다르면(예: `이름(가명)`) → 괜찮습니다. **파일에 실제로 있는 열 이름**을 기준으로 진행합니다.
- 기준을 못 정하겠으면 → `다른 후원 단체들은 보통 어떻게 나누는지 선택지 3개와 장단점만 보여줘. 결정은 내가 할게.`

### 2.2 점검 스크립트 만들고 실행하기 (12분)

🎯 **목표**: 판정 기준대로 계산하는 스크립트를 Claude가 만들고 실행해, `실습공간/06회차/후원점검보고서_2026-09.xlsx`를 받는다.

🛠 **준비**: 2.1에서 만든 `판정기준.md`, 복사한 xlsx 3개. Python 설치 확인.

👣 **단계**

1. 아래 프롬프트를 그대로 입력합니다.

```
실습공간/06회차/의 후원내역_2026-07.xlsx, 후원내역_2026-08.xlsx, 후원내역_2026-09.xlsx 세 파일과 판정기준.md를 바탕으로 9월 후원 점검 스크립트를 파이썬으로 만들어 실행해줘.

[계산할 것]
1. 9월 요약: 전체 건수, 성공 건수, 실패 건수, 약정금액 합계, 실입금액 합계

[저장]

[규칙]
```

2. Claude가 스크립트를 만들고 실행하겠다고 물어보면 승인합니다. 중간에 애매한 데이터 질문이 오면 **선생님이 판단해서** 답합니다.

- 보고서 저장 중 오류(권한·파일 사용 중) → 엑셀에서 보고서 파일을 닫고 `다시 실행해줘`.
- Claude가 스크립트 없이 숫자를 말로 먼저 답했다 → `그 숫자는 어디서 나왔어? 스크립트 실행 결과로 다시 보여줘.`
- 오류가 계속 나면 → 오류 문장을 그대로 두고 `이 오류가 무슨 뜻인지 쉽게 설명하고 고쳐줘.` 두 번 고쳐도 안 되면 인수인계 메모를 남기고 새 세션에서 다시(3회차 습관).

### 2.3 검산하기 — 원본 합계 대조 + 무작위 3명 확인 (13분)

> 은행 창구 직원은 돈을 기계로 센 다음에도 손으로 한 번 더 셉니다. 기계가 틀리는 일은 드물지만, **틀리면 큰일인 돈**이기 때문입니다. 검산은 "AI를 못 믿어서"가 아니라 **"후원자의 돈이라서"** 합니다.

🎯 **목표**: 보고서 숫자를 **다른 도구(엑셀)와 내 눈**으로 확인해, 믿어도 되는지 판단하고 `검산기록.md`로 남긴다.

🛠 **준비**: 엑셀, `후원내역_2026-09.xlsx`(복사본), `후원점검보고서_2026-09.xlsx`, 메모할 곳

👣 **단계**

1. **건수 대조**: 보고서 '요약' 시트에서 `전체 건수 = 성공 + 실패`인지 직접 더해 봅니다.
2. **원본 합계 대조**: 엑셀로 `실습공간/06회차/후원내역_2026-09.xlsx`를 엽니다.
   - 실입금액 열의 알파벳(열 머리글)을 누르면 엑셀 창 **아래쪽 상태 표시줄**에 합계가 보입니다.
   - 또는 데이터가 없는 열(예: L열)의 빈 칸에 수식을 넣습니다. 실입금액이 J열, 결제상태가 H열인 경우의 예입니다 — 실제 열 알파벳을 확인하고, J열·H열 안에는 넣지 마세요(자기 자신을 세는 오류가 납니다).

```
=SUM(J:J)
=COUNTIF(H:H,"성공")
=COUNTIF(H:H,"실패")
```

   - 이 세 값을 보고서의 실입금액 합계·성공 건수·실패 건수와 비교합니다. **차이가 0**이어야 정상입니다. 확인 후 원본은 **저장하지 않고** 닫습니다.
3. **무작위 3명 수작업 확인**: 9월 파일에서 선생님이 직접 3명을 고릅니다(예: 3번째 줄, 20번째 줄, 마지막 줄의 후원자ID). 보고서 '연속실패' 시트에 있는 사람이 한 명 끼어 있으면 더 좋습니다.
   - 7월·8월·9월 파일을 차례로 열어 **Ctrl+F**(Mac은 Cmd+F)로 그 후원자ID를 찾고, 결제상태와 실패사유를 적습니다.
   - `판정기준.md`대로 **내가 손으로** 판정한 뒤 보고서와 비교합니다.
4. 결과를 기록합니다.

```
실습공간/06회차/검산기록.md 파일을 만들어줘. 내용은 내가 불러주는 대로 적어줘.
- 건수 대조: 보고서 전체 ○건 = 성공 ○ + 실패 ○ → 일치/불일치
- 합계 대조: 원본 실입금액 합계 ○원, 보고서 ○원 → 차이 ○원
- 3명 확인: (후원자ID | 7월 | 8월 | 9월 | 내 판정 | 보고서 판정 | 일치?)
```

5. **다르게 나온 곳이 있으면** 바로 "고쳐줘" 하지 말고 원인부터 묻습니다.

```
후원자ID ○○○가 보고서에서는 '장기 실패'인데, 내가 원본을 보니 '일시 실패'야.
스크립트가 이 사람을 어떻게 판정했는지 7~9월 데이터와 함께 단계별로 설명해줘. 고치기 전에 원인부터 알려줘.
```

   - 원인이 **기준이 애매해서**라면 → 선생님이 기준을 분명히 하고 `판정기준.md`부터 고칩니다.
   - 원인이 **스크립트 실수**라면 → 고치게 하고, 다시 실행하고, **다시 검산**합니다.

✅ **이렇게 되면 성공**
- 건수·합계 차이가 0이고, 3명이 모두 일치한다. `검산기록.md`가 있다.
- 또는 불일치를 **찾아내고** 원인을 확인해 고친 뒤 다시 맞췄다 — 이것도 검산의 성공입니다. 검산은 틀린 곳을 찾으려고 하는 일입니다.

🆘 **막히면**
- 엑셀이 없다 → Claude에게 `원본 9월 파일의 실입금액 합계와 성공·실패 건수를 후원점검.py와 다른 방법으로 계산하는 짧은 검산 스크립트를 따로 만들어 실행해줘`라고 합니다. 다만 3명 확인은 꼭 **선생님 눈으로** 합니다.
- 합계가 안 맞는다 → 흔한 원인: 실패 건에도 실입금액이 적혀 있음, 빈 칸, 숫자가 글자로 저장됨(셀 왼쪽 위 초록 삼각형), 같은 후원자ID가 두 줄. `합계 차이가 나는 원인을 찾는 스크립트를 만들어 실행해줘. 원인이 되는 행의 후원자ID와 개수만 보여줘.`
- 상태 표시줄에 합계가 안 보인다 → 상태 표시줄을 오른쪽 클릭해 '합계'를 켜거나 위의 `=SUM` 수식을 쓰세요(화면 문구는 조금 다를 수 있습니다).

## Part 3: 엑셀 수식 부탁하는 법 (미션펀드 M4)

### 3.1 수식 부탁 '5종 세트'

🧩 **비유**
양복을 맞출 때 "양복 한 벌 주세요"라고만 하면 기성복이 나옵니다. 치수표, 원단 견본, 원하는 모양, "왼쪽 어깨가 조금 낮아요" 같은 특이사항을 알려 줘야 몸에 맞는 옷이 나옵니다. 그리고 반드시 **가봉(입어 보기)**을 합니다. 엑셀 수식도 똑같습니다.

**설명**
"정산 수식 만들어줘"라고만 하면 **우리 파일에 안 맞는** 수식이 나옵니다. 아래 5종 세트에 **정답을 아는 테스트 케이스**(가봉)를 더해 부탁합니다.

| 세트 | 무엇을 | 예 |
|------|--------|-----|
| ① 시트 구조 | 시트 이름, 머리글 위치, 엑셀 버전 | '9월'·'8월' 시트, 1행 머리글, Microsoft 365 |
| ② 열 이름 | 정확한 열 이름 | 후원자ID, 결제상태, 실입금액 … |
| ③ 샘플 5행 | **가명·가짜 번호로 바꾼** 예시 5줄 | D0001 · 후원자A · 010-0000-0001 … |
| ④ 원하는 결과 | 어느 칸에 무엇이 나와야 하나 | "8월 결제상태를 옆 칸에 가져오기" |
| ⑤ 예외 케이스 | 까다로운 경우 목록 | 신규(지난달 없음), 빈 칸, 같은 ID 두 줄 |
| ➕ 테스트 케이스 | 내가 **손으로 확인한** 정답 | "D0007 → 장기 실패" |

- **엑셀 버전을 꼭 적습니다.** XLOOKUP·FILTER·LET은 Excel 365/2021/2024에서, LAMBDA는 365/2024에서만 됩니다. 2016/2019라면 "INDEX·MATCH 같은 옛 함수로 짜줘"라고 부탁합니다.
- **수식과 함께 설명·테스트 방법을 받습니다.** 이해가 안 되는 수식은 적용하지 않습니다.
- 엑셀 안에서 직접 Claude와 작업하는 **Claude for Excel**(엑셀 추가 기능)도 2026년 5월부터 유료 플랜에서 제공됩니다. 다만 Anthropic 안내도 "검증 없이 감사용 계산에 쓰는 것"은 권하지 않습니다. 어떤 도구를 쓰든 **테스트와 검산**은 사람 몫입니다.

**우리 단체 예시**
미션펀드는 매달 **수천 개 함수**가 든 엑셀로 정산합니다. 대개는 **같은 수식 몇 종류가 수천 줄에 복사**된 경우입니다. 그래서 먼저 수식 종류부터 뽑으면 검토할 대상이 수십 개로 줄어들고, 매달 반복되는 일이라면 구조 자체를 바꾸는 방법도 물어볼 수 있습니다.

```
우리 정산 파일에는 같은 수식이 수천 줄에 복사돼 있어. 먼저 이 파일에 쓰인 수식 종류만 목록으로 뽑아줘(후원자 이름 같은 값은 출력하지 말고 수식만).
그다음 ① 표 + 동적 배열 수식 ② 피벗 테이블·파워 쿼리 ③ 파이썬 스크립트 중 우리 일에 맞는 구조를 장단점과 함께 비교해줘. 바꾸는 건 내가 결정할게.
```

💭 **확인 질문**: 수식을 받은 뒤 Claude에게 "이 수식 맞아?"라고 묻는 것과, 정답을 아는 3명으로 엑셀에서 직접 확인하는 것. 어느 쪽이 진짜 검증일까요?

### 3.2 실습: 수식 받고 엑셀에서 테스트하기

🎯 **목표**: 5종 세트로 수식을 부탁하고, Part 2에서 손으로 확인한 3명을 테스트 케이스로 써서 엑셀에서 확인한다.

👣 **단계**

2. 5종 세트로 수식을 부탁합니다. `○○` 자리에는 `검산기록.md`의 3명을 적으세요.

```
[역할] 너는 엑셀 수식 선생님이자 검산 담당자야.
[맥락] 월별 후원 결제 결과를 점검하는 연습이야. 엑셀 버전: Microsoft 365 (Windows). 매크로·VBA는 쓰지 않아.
[시트 구조] 실습공간/06회차/수식연습.xlsx — '9월' 시트와 '8월' 시트, 1행은 머리글, 2행부터 데이터.
[열 이름] 후원자ID | 이름 | 연락처 | 후원상품 | 약정금액 | 결제수단 | 출금일 | 결제상태 | 실패사유 | 실입금액
[샘플 5행] '9월' 시트의 위 5줄을 봐도 돼(가상 데이터야).
[원하는 결과]
 ① '9월' 시트 새 열 '8월결과': 같은 후원자ID의 8월 결제상태. 8월 기록이 없으면 "8월없음"
 ② '9월' 시트 새 열 '판정': 판정기준.md 기준으로 "장기 실패" / "일시 실패" / 성공이면 빈칸
 ③ 후원상품별로 결제상태가 '성공'인 실입금액 합계
 ④ 9월 실패자 후원자ID 목록
[예외 케이스] 9월 신규(8월 없음), 빈 칸, 숫자가 글자로 저장된 칸, 같은 후원자ID가 두 줄
[테스트 케이스와 정답] (내가 손으로 확인한 것)
 ○○ → 8월결과 ○○, 판정 ○○ / ○○ → … / ○○ → …
[제약] XLOOKUP, FILTER, SUMIFS 같은 Excel 365 함수를 써. 값을 수식에 직접 적어 넣지 마.
[출력] 1) 넣을 셀과 수식 2) 부분별 한 줄 설명(엑셀 초보자용) 3) 예외 케이스별 동작 4) 검산 수식 1개 5) 이 수식이 틀린 값을 낼 수 있는 입력
[주의] 결과 숫자를 네가 계산해서 말하지 마. 애매한 가정은 '가정:'으로 표시하고 먼저 나에게 물어봐.
```

3. 받은 수식을 엑셀에 붙입니다. 예를 들어 이런 모양의 답이 올 수 있습니다(**예시일 뿐**입니다. 열 위치와 기준이 다르면 수식도 달라지고, 맞는지는 테스트로 확인합니다).

```
(9월 시트 K1에 '8월결과', K2에 넣고 아래로 채우기)
=XLOOKUP(A2, '8월'!A:A, '8월'!H:H, "8월없음")

(L1에 '판정', L2에 넣고 아래로 채우기 — '2개월 연속 실패 = 장기'로 정한 경우)
=IF(H2<>"실패", "", IF(K2="실패", "장기 실패", "일시 실패"))

(N2에 후원상품 이름을 적고, O2에 그 상품의 '성공' 실입금액 합계)
=SUMIFS(J:J, D:D, N2, H:H, "성공")

(Q2에 — 9월 실패자 후원자ID 목록이 아래 칸으로 자동으로 펼쳐짐)
=FILTER(A2:A200, H2:H200="실패", "없음")

(S2에 — 검산: 0이면 정상, 전체 줄 수 = 성공 + 실패)
=COUNTA(A2:A200) - COUNTIF(H2:H200, "성공") - COUNTIF(H2:H200, "실패")
```

4. **테스트 케이스 확인**: 3명의 `8월결과`·`판정`이 내 정답과 같은지 봅니다. 9월 신규 후원자 1명을 찾아 `8월없음`이 나오는지도 확인합니다.
5. **한 단계씩 보기**: 이해가 안 되는 칸을 선택하고 엑셀 **[수식] → [수식 분석] → [수식 계산]**을 누르면 수식이 한 단계씩 계산되는 모습을 볼 수 있습니다.
6. **교차 확인**: 수식의 '장기 실패' 개수와 Part 2 보고서의 장기 실패 인원을 비교합니다. **서로 다른 도구(엑셀 수식과 파이썬 스크립트)가 같은 답**을 내면 믿을 근거가 훨씬 강해집니다.

✅ **이렇게 되면 성공**
- 테스트 케이스 3명 + 신규 1명이 모두 기대한 값으로 나온다.
- 검산 수식 결과가 0이다.
- 각 수식이 무엇을 하는지 한 줄씩 말로 설명할 수 있다.

🆘 **막히면**
- `#NAME?` → 엑셀 버전이 XLOOKUP·FILTER를 지원하지 않을 수 있습니다. `내 엑셀은 2019야. 같은 결과를 INDEX·MATCH·SUMIFS로 짜줘.`
- `#SPILL!` → FILTER 결과가 펼쳐질 아래 칸이 비어 있지 않습니다. 아래를 비우거나 다른 열에 넣습니다.
- 테스트가 틀리면 → `○○의 결과가 내 정답(○○)과 달라. 이 수식이 이 사람에 대해 어떻게 계산했는지 단계별로 보여줘.`
- 수식 판정과 보고서가 다르면 → 기준(2개월 vs 3개월)을 수식과 스크립트가 **같게** 해석했는지부터 확인합니다.

## Part 4: 매달 반복 준비 — '점검 키트'로 만들기

### 4.1 한 번 만든 도구는 다음 달에도

🧩 **비유**
잘 만든 **결재 서식 파일**은 매달 날짜만 바꿔 씁니다. 매번 빈 종이에 표를 새로 그리지 않지요. 이번에 만든 스크립트도 매달 쓰는 서식입니다.

**설명**
이번 회차에서 만든 것들을 한 세트, **'점검 키트'**로 묶어 둡니다.

| 파일 | 역할 | 누가 만들었나 |
|------|------|--------------|
| `판정기준.md` | 무엇을 '장기 실패'로 볼지 | 🙋 사람 |
| `후원점검.py` | 기준대로 계산하는 도구 | 🤖 Claude가 작성, ⚙️ 코드가 계산 |
| `사용법.md` | 다음 달에 어떻게 쓰는지 | 🤖 Claude |
| `검산기록.md` | 합계 대조 + 3명 확인 결과 | 🙋 사람 |

다음 달에는 새 파일을 폴더에 넣고 **"10월 파일 넣었어. 같은 점검 돌려줘"**면 됩니다. 기준이 바뀌면 `판정기준.md`만 고치고 "기준이 바뀌었으니 스크립트에 반영해줘"라고 합니다.

**우리 단체 예시**
다교연은 매달 미션펀드 엑셀을 받습니다(G2). 신규 후원자 확인(G3)도 같은 키트 안에 있습니다. 9회차에서는 이 과정을 `/후원점검`처럼 불러내는 **스킬**로, 10회차에서는 정해진 날 자동으로 도는 **예약 작업**으로 키웁니다.

💭 **확인 질문**: 같은 9월 파일로 스크립트를 한 번 더 돌렸는데 숫자가 달라졌다면, 무엇이 잘못된 신호일까요?

### 4.2 실습: 다음 달에도 돌아가게 만들기

🎯 **목표**: 스크립트가 "점검할 달"만 바꿔 다시 쓸 수 있는지 확인하고, 사용법을 남긴다.

🛠 **준비**: `후원점검.py`, 판정기준·검산기록 파일

👣 **단계**

1. 다시 쓰기 좋게 고칩니다.

```
후원점검.py를 다음 달에도 쓸 수 있게 고쳐줘.
- 점검할 달(예: 2026-10)만 알려주면, 그 달과 앞의 두 달 파일을 실습공간/06회차/에서 찾아 점검해줘. 없는 달 파일은 건너뛰고 화면에 알려줘.
- 보고서 파일 이름은 후원점검보고서_점검할달.xlsx로 저장해줘.
- 보고서에 '검산' 시트를 넣어줘: 원본 행 수와 보고서 전체 건수의 차이, 원본 실입금액 합계와 보고서 합계의 차이(둘 다 0이어야 정상).
- 사용법을 실습공간/06회차/사용법.md에 초보자용으로 적어줘.
```

2. **재현 시험**: `2026-09로 다시 점검해서, 아까 보고서와 숫자가 모두 같은지 비교해줘.` → 같아야 정상입니다.
3. **다른 달 시험**: `2026-08로도 점검해줘.` → 6월 파일이 없으니 "건너뜀" 안내와 함께 `후원점검보고서_2026-08.xlsx`가 생기면 성공입니다.
4. 마지막으로 폴더를 확인합니다.

```
실습공간/06회차/
├── 후원내역_2026-07.xlsx · 후원내역_2026-08.xlsx · 후원내역_2026-09.xlsx  (복사본)
├── 판정기준.md                 ← 사람이 정한 기준
├── 후원점검.py                 ← 계산 도구
├── 후원점검보고서_2026-09.xlsx ← 결과
├── 후원점검보고서_2026-08.xlsx ← 재사용 시험 결과
├── 검산기록.md                 ← 사람의 확인
├── 수식연습.xlsx
└── 사용법.md
```

✅ **이렇게 되면 성공**
- 9월 재실행 결과가 처음과 **완전히 같다.**
- 8월 보고서가 만들어지고, 없는 파일 안내가 나왔다.
- 보고서에 '검산' 시트가 있고 차이가 0이다.

🆘 **막히면**
- 재실행 결과가 다르다 → `처음 실행과 이번 실행의 결과가 다른 이유를 찾아줘. 그사이 바뀐 파일이나 코드가 있는지 확인해줘.`
- 스크립트 '검산' 시트는 **스크립트가 스스로 한 확인**입니다. 매달 원본 합계 대조와 3명 확인은 계속 사람이 합니다(1~2분이면 충분).

```
○○의 판정 기준을 정하려고 해. 기준은 내가 정할 거야. 필요한 질문을 선택지와 함께 하나씩 해주고, 다 정해지면 내가 답한 그대로 판정기준.md에 정리해줘.
```

```
숫자를 머리로 계산해서 말하지 마. 계산하는 스크립트를 만들어 실행하고, 결과는 실행한 값으로만 보고해. 화면에는 개수와 합계만 출력하고 이름·연락처는 출력하지 마.
```

```
이 결과를 검산하고 싶어. 원본과 대조할 합계·건수 목록과, 내가 무작위로 고른 3명을 손으로 확인할 때 쓸 확인표(ID | 달별 결과 | 내 판정 | 보고서 판정 | 일치?)를 만들어줘.
```

```
엑셀 수식을 부탁할게. [시트 구조] … [열 이름] … [샘플 5행(가명)] … [원하는 결과] … [예외 케이스] … [테스트 케이스와 정답] … 엑셀 버전은 ○○야. 수식, 부분별 한 줄 설명, 검산 수식, 틀릴 수 있는 입력을 알려줘. 결과 숫자는 네가 계산해서 말하지 마.
```

**언제 쓰나**: 다음 달 같은 점검을 돌릴 때
```
○월 파일 넣었어. 사용법.md대로 같은 점검 돌려주고, 검산 시트 결과(차이가 0인지)만 먼저 알려줘.
```

### 퀴즈 정답과 해설

1. **X** — 같은 숫자가 두 번 나와도 과정은 보이지 않고, 둘 다 틀릴 수 있습니다. 숫자는 스크립트·수식으로 계산하고 원본과 대조해야 합니다(1.1).
2. **②** — 판정 기준은 업무 판단입니다. Claude는 질문으로 돕고, 결정은 사람이 하며, 파일로 남겨 스크립트가 따르게 합니다(1.2).
3. 모범 답: "바로 고쳐 달라고 하지 않고 **원인부터** 찾게 한다." 예: 차이 나는 행을 찾는 스크립트(ID와 개수만 출력) → 흔한 원인(실패 건에 금액 기입, 같은 ID 두 줄, 글자로 저장된 숫자) 확인 → 기준 문제면 사람이 정하고, 스크립트 문제면 고친 뒤 **다시 검산**. "그냥 다시 돌린다"만 답하면 힌트를 주고 원인 찾기로 유도합니다.
4. **④** — 수식에는 구조와 가짜 샘플 5행이면 충분합니다. 실제 명단은 보내지 않습니다(5회차).
5. 모범 답: **개수와 합계만.** 스크립트의 화면 출력도 AI에게 전달되기 때문에, 이름·연락처가 출력되면 가명 처리한 의미가 사라집니다. 명단은 파일로만 저장하고 AI에게 다시 보여 주지 않습니다.

### 실전 과제 검수 기준

- **공통**: ① 기준 파일이 있고 **사람이 정한 것**임이 드러난다 ② 숫자는 스크립트·수식 결과이며, 대화 속 숫자와 파일 숫자가 일치한다 ③ 검산기록에 원본 대조와 표본 3건 확인이 있다 ④ 사용법이 있어 다음 달에 다시 쓸 수 있다.
- **개인정보(다교연·다니엘·엘리온)**: 화면 출력·대화에 실명·연락처가 없다. 원본 파일은 작업 폴더 밖 또는 AI가 열지 않았다. 스크립트는 가짜 샘플로 만들었다. 대응표는 별도 보관.
- **미션펀드**: 엑셀 버전이 적혀 있다. 테스트 케이스 5건이 **손으로 확인한 정답**과 함께 있다. 학습자가 수식을 한 줄씩 설명할 수 있다. 원본이 아니라 **사본**에서 테스트했다.
- **교진추**: 청원 논거를 강화하는 방향의 통계 작업을 적극 돕습니다. 건수는 스크립트로, 표본 3건은 **PDF 원문·쪽수와 글자 그대로** 대조했는지 확인합니다 — 인용 정확성이 청원서 신뢰도를 높입니다.
- **SHINE**: 집계는 코드, "잘 된 영상의 공통점" 같은 해석은 사람의 가설로 구분되어 있으면 통과.

### 안전·개인정보 주의

- 실습 데이터는 모두 **가상**입니다. 실제 파일은 실전 과제에서만, **5회차 패턴**으로: 열 이름 + 가짜 샘플로 스크립트 작성 → 실제 파일은 내 PC에서 스크립트가 처리 → AI에게는 개수·합계만.

- **후원상품 열 주의**: 샘플의 후원상품 열에는 가상 선교사 이름과 보안 사역 표기가 들어 있습니다. 실제 파일에서는 상품별 합계를 출력하는 순간 선교사 실명·보안국가 사역명이 AI에 보입니다. 실제 파일로 할 때는 후원상품을 코드(예: P01)로 바꾼 대응표를 내 PC에만 두고, 보안국가 사역은 합계에서 따로 빼게 합니다.
