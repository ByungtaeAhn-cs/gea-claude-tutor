## Part 1: Git = 게임 세이브 포인트

### 1.1 Git은 세이브 포인트, 커밋은 '저장 + 메모'

🧩 **비유**: 게임에서 보스 방 앞에서 저장해 두면, 져도 그 지점부터 다시 시작합니다. Git(깃, 파일이 바뀐 기록을 남기는 프로그램)은 선생님의 폴더에 이런 세이브 포인트를 만들어 줍니다.

**설명**
- **저장소(repository)** = Git이 기록을 관리하는 폴더입니다. 폴더 안에 숨은 기록장(`.git` 폴더)이 생기는데, 지우면 기록이 사라지니 건드리지 않습니다.
- **커밋(commit)** = 저장 버튼 + 한 줄 메모입니다. "10월 소식지 기도제목 추가"처럼 무엇을 했는지 함께 남깁니다.
- **기록 보기** = 세이브 목록입니다. 언제, 무엇을 바꿨는지 차례로 보입니다.
- **되돌리기** = 원하는 세이브 지점의 내용으로 돌아가기입니다. 파일 하나만 되돌릴 수도, 폴더 전체를 되돌릴 수도 있습니다.

**우리 단체 예시**
- 엘리온에듀학원: STR '빛' 원고를 고치다가 "지난주 원고가 더 좋았는데" 싶으면 지난주 세이브로 돌아갑니다.
- 교진추: 청원서 초안을 여러 번 고쳐도 "처음 초안과 지금 무엇이 달라졌나"를 한 번에 봅니다.
- 다니엘칼리지: '대니' 설정 문서를 바꿨더니 답이 이상해졌다면, 바꾸기 전 설정으로 돌립니다.

💭 **확인 질문**: 선생님 컴퓨터에 `최종`, `수정본`, `v2`가 붙은 파일이 있나요? 그중 진짜 최신본을 바로 고를 수 있나요?

### 1.2 명령어는 몰라도 됩니다 — 말로 시키는 Git

🧩 **비유**: 은행 창구에서 전산 코드를 몰라도 "이 통장 거래 내역 뽑아 주세요"라고 하면 됩니다. Git 명령어는 신입 동료(Claude)가 알고, 선생님은 원하는 일을 말하면 됩니다.

| 하고 싶은 일 | Claude에게 이렇게 말하기 | 부르는 이름 |
|---|---|---|
| Git 관리 시작 | "이 폴더를 Git으로 관리해줘" | 저장소 만들기 |
| 지금 상태 저장 | "지금 상태 저장해줘" | 커밋(commit) |
| 무엇이 바뀌었나 | "마지막 저장 이후 뭐가 바뀌었는지 보여줘" | 변경 비교(diff) |
| 저장 기록 보기 | "저장 기록을 표로 보여줘" | 기록(log) |
| 되돌리기 | "어제 버전으로 되돌려줘. 기록은 지우지 마" | 되돌리기 |
| 예전 내용 보기 | "이 파일의 첫 버전을 보여줘. 파일은 바꾸지 마" | — |
| 인터넷 금고에 올리기 | "GitHub에 올려줘" | 푸시(push) |
| 최신본 받아 오기 | "GitHub에서 최신 내용 가져와줘" | 풀(pull) |

**설명**
- Claude가 이 일을 하려면 git 명령을 실행해야 해서 "이 명령을 실행해도 될까요?"라고 묻습니다. **Manual** 모드라면 무엇을 하려는지 읽고 승인하세요.
- 되돌리기를 부탁할 때는 **"기록은 지우지 마"**를 꼭 붙이세요. 기록이 남아 있어야 마음이 바뀌었을 때 다시 앞으로 올 수 있습니다.
- **화면 복습**: Claude가 파일을 고치면 `+12 -1` 같은 변경 표시가 뜹니다(12줄 추가, 1줄 삭제). 누르면 무엇이 바뀌었는지(diff) 보입니다. 이것이 '지금 바뀐 것'을 보는 창이라면, Git은 그 변경에 메모를 붙여 **날짜별로 계속 쌓아 두는 장부**입니다.

**우리 단체 예시**: 미션펀드 간사님이 분기 선교지 소식 글을 고친 뒤 "지난 저장과 뭐가 달라졌는지 문단별로 보여줘"라고 하면, 바뀐 문단만 뽑아 줍니다.

💭 **확인 질문**: 되돌리기를 부탁할 때 "기록은 지우지 마"를 붙이는 이유는 무엇일까요?

### 1.3 GitHub = 인터넷 금고이자 공유 캐비닛

🧩 **비유**: Git이 내 책상 서랍의 세이브 장부라면, GitHub(깃허브)는 은행 대여금고입니다. 컴퓨터가 고장 나도 금고의 사본은 안전하고, 열쇠를 준 사람과만 함께 볼 수 있습니다.

**설명**
- 내 PC의 기록을 GitHub에 올리는 것을 **푸시(push)**, GitHub에서 받아 오는 것을 **풀(pull)**이라고 합니다.
- 저장소는 **Public(공개)**과 **Private(비공개)** 중 고릅니다. 단체 업무 자료는 **항상 Private**입니다.
- 이 튜터도 GitHub에 공개로 올라가 있습니다. 1회차에 Claude에게 받아 달라고 요청하는 방법으로 받았다면, "튜터 최신 버전으로 업데이트해줘"가 바로 풀(pull)입니다.

**우리 단체 예시**: SHINE행복한학교의 영상 기획서·대본 폴더를 비공개 저장소에 올려 두면, 노트북을 바꿔도 받아서 그대로 이어 갑니다. 9회차에서는 이 방법으로 내가 만든 스킬을 동료와 나눕니다.

💭 **확인 질문**: 선교지 소식 원고 폴더를 GitHub에 올린다면 Public과 Private 중 무엇을 골라야 할까요? 이유는요?

## Part 2: 실습 — 세이브하고, 망가뜨리고, 되돌리기

🎯 **목표**: 연습 폴더에 세이브 포인트를 2~3개 만들고, 일부러 망가뜨린 파일을 되살립니다.

🛠 **준비**
- 권한 모드는 **Manual**을 권합니다. Claude가 git 명령을 실행할 때마다 무엇을 하는지 읽고 승인하는 연습입니다.
- 연습 폴더 `실습공간/04회차/소식지_연습/`은 Claude와 함께 새로 만듭니다. `실습자료/`에 따로 준비된 파일은 없습니다.
- **실습 데이터 선택**: ① Claude가 만드는 가상 소식지 파일(기본, 권장) ② 내 실제 소식지 양식에 가짜 내용을 채운 파일 ③ 내 실제 파일(개인정보가 없는지 먼저 점검 — 5회차 원칙). 일부러 망가뜨리는 단계가 있으니 ①을 권합니다.
- GitHub 사용자 이름을 옆에 적어 두세요(이메일 설정에 씁니다).

👣 **단계**

1. **연습 폴더와 샘플 파일 만들기**
   ```
   실습공간/04회차/소식지_연습 폴더를 만들고, 연습용 가상 파일 3개를 만들어줘.
   ① 소식지_원고.md: 다음세대교육연합 10월 소식지 초안(인사말과 연합 소식 2개, 10줄 이내)
   ② 기도제목.md: 기도제목 3개
   ③ 일정.md: 10월 일정 3개
   실제 사람 이름이나 연락처는 넣지 말고 가상으로 만들어줘.
   ```
2. **Git 관리 시작 + 이름·이메일 설정**
   ```
   실습공간/04회차/소식지_연습 폴더를 Git으로 관리해줘. 튜터 폴더 전체가 아니라 이 폴더만이야.
   git 사용자 이름과 이메일이 설정돼 있는지 먼저 확인하고, 없으면 설정을 도와줘.
   이메일은 개인 메일 대신 GitHub noreply 주소로 설정해줘. 내 GitHub 사용자 이름은 ○○○야.
   ```
   - 이름은 저장 기록에 남고, GitHub에 올리면 다른 사람도 볼 수 있습니다. 실명이 부담되면 영문 이름도 괜찮습니다.
   - **noreply 주소**(노리플라이, GitHub가 계정마다 주는 '가림용' 이메일 주소)를 쓰면 저장 기록에 개인 메일이 남지 않습니다.
3. **첫 저장**
   ```
   지금 상태를 저장해줘. 메모는 "첫 저장: 소식지 연습 파일 3개"로 해줘.
   ```
4. **고치고, 비교하고, 저장하기**
   ```
   소식지_원고.md에 '11월 교사 연수 안내' 문단을 3줄로 추가해줘.
   ```
   변경 표시(`+3 -0` 같은 숫자)가 보이면 눌러 바뀐 내용을 눈으로 확인한 뒤 이어서 보냅니다. 표시가 안 보이면 "방금 바뀐 내용 보여줘"라고 요청하세요.
   ```
   마지막 저장 이후 뭐가 바뀌었는지 쉬운 말로 알려주고, 저장해줘. 메모는 네가 한 줄로 써줘.
   ```
5. **일부러 망가뜨리기**
   ```
   연습이야. 기도제목.md 내용을 전부 지우고 "실수로 지움" 한 줄만 남겨줘.
   ```
6. **되돌리기**
   ```
   기도제목.md를 마지막 저장 상태로 되돌려줘. 저장 기록은 지우지 마.
   ```
7. **기록 보기와 예전 버전 보기**
   ```
   지금까지 저장 기록을 표로 보여줘(순서, 메모, 바뀐 파일).
   그리고 첫 저장 때의 소식지_원고.md 내용을 보여줘. 파일은 바꾸지 말고 보여주기만 해.
   ```
8. (🌿🌳 도전) **앞선 세이브로 돌아가기**
   ```
   소식지_원고.md를 첫 저장 때 내용으로 되돌려줘. 기록은 지우지 말고, 되돌린 것을 새 저장으로 남겨줘.
   ```

✅ **이렇게 되면 성공**
- 저장 기록 표에 저장이 2개 이상 보이고, 메모만 읽어도 무엇을 했는지 알 수 있습니다.
- 5단계에서 지운 기도제목 3개가 6단계 뒤 그대로 돌아왔습니다.
- 첫 저장 때 원고에는 '11월 교사 연수 안내' 문단이 없다는 것을 확인했습니다.
- (도전) 저장 기록 맨 위에 '되돌림' 저장이 새로 생겼습니다.

| 이름·이메일이 없어서 저장이 안 된다는 오류 | 2단계 프롬프트를 다시 보내기 |

| 되돌리기가 이상하게 됨 | 멈추고(**Esc**) "지금 상태와 저장 기록부터 보여줘"로 상황을 먼저 확인 |

## Part 3: GitHub에 비공개로 백업하기 (🌿🌳 권장 · 🌱 선택)

> 처음 해 보는 분께는 선택입니다. 설치나 로그인에서 막히면 **"건너뛰기"**라고 말씀하세요. 9회차(스킬을 팀과 공유)에서 다시 해 봅니다.

### 3.1 왜 비공개 백업인가

🧩 **비유**: 중요한 법인 서류를 사무실 캐비닛에만 두면, 불이 나면 끝입니다. 그래서 은행 금고에 사본을 하나 더 둡니다.

**설명**: 세이브 포인트(Git)는 내 PC 안에만 있습니다. PC가 고장 나거나 잃어버리면 기록도 함께 사라집니다. GitHub 비공개 저장소에 올려 두면 다른 PC에서 그대로 받아 이어 갈 수 있습니다.


## Part 4: 최신본 관리 규칙 — '최종_진짜최종.pptx' 탈출 (엘리온 E1)

### 4.1 원본은 하나, 나머지는 '산출물'

🧩 **비유**: 교회 주보를 떠올려 보세요. 원판 파일은 하나이고, 인쇄본·게시판 사진·단톡방 이미지는 거기서 뽑아냅니다. 오타는 인쇄본이 아니라 원판에서 고칩니다.

**설명**
- 주제마다 사람이 고치는 파일은 **원고 1개**(마크다운 `원고.md`, 글자만 있는 가벼운 문서)뿐입니다.
- PPT·활동지·교사 가이드(Word)는 원고에서 **다시 만들어 내는 산출물**입니다. 산출물을 따로 고치기 시작하면 최신본이 여러 개가 됩니다.
- 원고를 마크다운으로 두는 이유: Git은 글자 파일이면 "어느 줄이 바뀌었는지" 보여 줍니다. PPT·Word 파일은 버전은 보관되지만 무엇이 바뀌었는지 내용 비교는 보여 주지 못합니다.

**우리 단체 예시**: 엘리온 STR '빛' 수업은 창조·타락·회복·완성 4막 `원고.md` 하나에서 `빛_수업.pptx`, `빛_활동지.docx`, `빛_교사가이드.docx`가 나옵니다(7회차에서 실제로 만듭니다). 교사가 활동지 오타를 발견하면 원고를 고치고 활동지를 다시 만듭니다.

💭 **확인 질문**: 활동지에서 오타를 발견했습니다. 어느 파일을 고쳐야 할까요?

### 4.2 폴더 규칙과 버전 없는 파일 이름

🧩 **비유**: 도서관은 책을 분류 번호 자리에 꽂습니다. 사서가 바뀌어도 같은 자리에서 찾습니다. CLAUDE.md에 폴더 규칙을 적어 두면 Claude도 매번 그 자리에 저장합니다.

**설명**
- 기본 네 칸: **원본**(사람이 고치는 원고) / **산출물**(원고에서 만든 PPT·Word·PDF) / **참고자료**(읽기만 하는 자료) / **보관**(끝난 것 — 지우지 않고 옮김).
- 파일 이름에 `v2`, `최종`, `수정본`을 붙이지 않습니다. 버전은 Git 저장 기록이 기억합니다.
- 호수·날짜는 넣어도 됩니다. `소식지_2026-10.md`와 `소식지_2026-11.md`는 같은 문서의 버전이 아니라 서로 다른 문서입니다.

**우리 단체 예시 — 엘리온 콘텐츠 폴더**
```
엘리온콘텐츠/                 ← 내 PC 작업 폴더 (Git으로 관리, Drive 동기화 폴더 밖)
├── CLAUDE.md                 ← 폴더·파일 이름 규칙
├── 00_기준자료/              ← PPT 템플릿, 활동지 양식, 교사 가이드 양식
├── STR/
│   └── 빛/
│       ├── 원고.md           ← 원본 (사람이 고치는 유일한 파일)
│       ├── 이미지/
│       └── 산출물/           ← 빛_수업.pptx, 빛_활동지.docx, 빛_교사가이드.docx
├── 참고자료/                 ← 과학 자료·성경 인용 근거 (읽기만)
├── 보관/                     ← 더 이상 쓰지 않는 주제
└── 콘텐츠목록.md             ← Claude가 갱신하는 색인 (과목·학년·주제·산출물·수정일)
```

CLAUDE.md에 적을 규칙 예시:
```
## 폴더 규칙
- 사람이 고치는 파일은 각 주제의 원고.md 하나뿐이다.
- PPT·활동지·교사 가이드는 산출물/ 에 만든다. 산출물을 직접 고치지 말고 원고를 고친 뒤 다시 만든다.
- 파일 이름에 v1, v2, 최종, 수정본을 붙이지 않는다. 버전은 Git 저장 기록으로 관리한다.
- 쓰지 않는 주제는 지우지 말고 보관/ 으로 옮긴다.
- 학생 이름·연락처·성적이 든 파일은 이 폴더에 두지 않는다.
- 작업 한 단계가 끝나면 저장(커밋)하고, 메모는 한국어 한 줄로 쓴다.
- 새 콘텐츠를 만들면 콘텐츠목록.md를 갱신한다.
```

### 4.3 개인정보 파일은 저장소에 넣지 않기 (.gitignore)

🧩 **비유**: 복사기 옆에 붙은 "이 서류는 복사 금지" 목록입니다. `.gitignore`(깃이그노어)는 Git에게 주는 **'못 본 척 목록'**입니다. 목록에 있는 파일은 폴더에 그대로 있지만, 세이브에도 GitHub 업로드에도 들어가지 않습니다.

**설명**
- 목록은 **처음 저장하기 전에** 만듭니다. 한 번 저장된 파일은 나중에 목록에 올려도 예전 기록에 남아 있습니다.
- .gitignore는 Claude가 파일을 **읽는 것까지 막지는 않습니다.** AI에게 아예 보여 주지 않는 방법은 5회차에서 배웁니다.
- 가장 좋은 방법은 개인정보 파일을 처음부터 작업 폴더 밖에 두는 것입니다. .gitignore는 실수를 막는 두 번째 울타리입니다.

**우리 단체 예시**: 미션펀드의 후원자 명단·선교사 신청서, 다교연의 후원 엑셀, 다니엘칼리지의 학부모 연락처, 엘리온의 학생 성적·출결 파일이 '못 본 척 목록' 대상입니다.

💭 **확인 질문**: .gitignore에 적은 파일은 폴더에서 사라질까요?

### 4.4 Google Drive와 함께 쓰는 법

🧩 **비유**: 요리는 부엌(작업 폴더)에서 하고, 완성된 음식만 식탁(공유 폴더)에 올립니다. 식탁 위에서 요리하지 않습니다.

**설명**
- **Git 폴더를 Google Drive 동기화 폴더 안에 두지 않습니다.** Drive 동기화가 Git 기록장(`.git`) 속 파일을 건드려 저장소가 손상된 사례가 보고되어 있습니다.
- 작업은 **내 PC 폴더(Git)**에서 하고, 완성본만 **Drive 공유 폴더로 복사**해 동료들과 나눕니다.
- 큰 영상·고해상도 사진은 Git에 넣지 않습니다. 50MB가 넘는 파일은 올릴 때 경고가 나오고, GitHub는 100MB가 넘는 파일을 막습니다. 이런 파일은 Drive에 두고 원고에는 파일 이름이나 링크만 적습니다.
- 한 문장으로: **"PC 작업 폴더에서 만들고, Git으로 저장하고, 완성본만 Drive로."**

**우리 단체 예시**: 엘리온 교사들은 Drive 배포 폴더에서 PPT·활동지를 받아 씁니다. 원고와 수정 기록은 담당자 PC의 Git 폴더에만 있습니다. SHINE도 영상 원본은 Drive에, 기획서·대본만 Git에 둡니다.

- 명단 파일이 이미 저장돼 버림 → 가상 파일이니 걱정하지 않으셔도 됩니다. 튜터에게 "명단 파일이 저장돼 버렸어"라고 말하면 함께 정리합니다.

- 계획이 마음에 안 듦 → "사진은 참고자료가 아니라 원본 안 이미지 폴더로"처럼 고칠 점을 말하고 계획을 다시 받습니다.

## 📌 오늘의 요약

- Git은 폴더의 **세이브 포인트**, 커밋은 **저장 + 메모**입니다. 명령어는 몰라도 말로 시키면 됩니다.
- 되돌릴 때는 **"기록은 지우지 마"**를 붙입니다. 기록이 남아야 다시 앞으로 올 수 있습니다.
- GitHub는 **인터넷 금고**입니다. 단체 자료는 항상 **Private**, 올린 뒤 비공개인지 확인합니다.
- **원본은 하나(원고.md), 나머지는 산출물.** 파일 이름에 버전을 붙이지 않습니다.
- 개인정보 파일은 **.gitignore**로 빼고, Git 폴더는 **Drive 동기화 폴더 밖**에 둡니다. 완성본만 Drive로.

### 퀴즈 정답과 해설

1. **X**. 버전은 Git 저장 기록이 기억합니다. 이름에 버전을 붙이면 "어느 것이 최신인가" 문제가 다시 생깁니다. 단, 호수·날짜(10월호, 11월호)는 서로 다른 문서이므로 이름에 넣어도 됩니다.
2. **②**. Drive 동기화가 `.git` 속 파일을 건드려 저장소가 손상된 사례가 보고되어 있습니다. 공유 드라이브도 동기화 폴더입니다. "PC에서 만들고, Git으로 저장하고, 완성본만 Drive로."
3. **②**. 파일은 폴더에 그대로 있고 Git 저장과 업로드에서만 빠집니다. ④는 흔한 오해입니다. Claude가 읽는 것을 막으려면 5회차의 방법(읽기 금지 설정, 폴더 밖에 두기)을 씁니다.
4. 기록이 남아 있어야 되돌린 뒤에도 마음이 바뀌면 다시 앞으로 돌아올 수 있고, 무엇을 왜 되돌렸는지도 기록으로 남기 때문입니다. 기록을 지우는 방식은 되살릴 길을 없앱니다.
5. `원고.md`(원본)를 고치고, 활동지(산출물)를 원고에서 다시 만듭니다. 그다음 저장(커밋)합니다. 활동지만 고치면 원고와 PPT·교사 가이드에는 오타가 남아 최신본이 갈라집니다.

**힌트 순서(소크라테스식)**: 바로 정답을 주지 말고 → 비유로 되묻기("게임에서 세이브를 지우면?", "주보 오타는 어디서 고치죠?") → 본문 해당 절 안내 → 그래도 어려우면 해설.

- 저장 기록이 3개 이상이고, 메모만 읽어도 무엇을 했는지 알 수 있다.
- `.gitignore`가 있고, Claude에게 확인시킨 결과 **저장 기록 전체에 개인정보 파일이 0건**이다.
- 작업 폴더가 Google Drive(및 기타 동기화) 폴더 밖에 있다.
- CLAUDE.md에 폴더·파일 이름 규칙이 3줄 이상 있다.
- GitHub에 올렸다면 **Private 표시 + 시크릿 창 404**를 확인했다.
- 되돌리기를 최소 1회 해 봤다(다니엘은 필수).
- 엘리온: 재설계안에 ① 원본/산출물/기준자료/보관 구조 ② 파일 이름 규칙 ③ Drive 배포 흐름 ④ 주제별 원고 편집 담당자(여러 교사가 같은 원본을 동시에 고치면 충돌)가 모두 있다.
- 교진추: 변경 요약이 논점별로 정리되어 있고, 인용문을 고친 경우 원문 대조 여부가 표시되어 있다.
- SHINE·교진추: 50MB가 넘는 파일이 저장 기록에 없다.

### 안전·개인정보 주의

- 이 회차 실습 데이터는 **모두 가상**입니다. 실제 업무 폴더를 Git으로 관리하기 전에는 반드시 "개인정보가 있을 만한 파일 목록"부터 확인하게 합니다(5회차 원칙 예고).
- **GitHub 저장소는 항상 Private.** 개인정보가 든 파일이 Public 저장소에 올라갔다면 비공개로 바꿔도 이미 복제되었을 수 있으므로 유출로 보고, 단체 책임자에게 알리도록 안내합니다. 기록에서 지우는 작업은 튜터가 단계별로 설명하고 학습자 승인 뒤에만 진행합니다.
- 보안국가 선교 관련 원자료(실명·국가·얼굴·교회명·종교 용어)는 비공개라도 **Git 저장소와 GitHub에 넣지 않습니다.**
- **비밀번호·토큰은 대화창에 받지 않습니다.** 학습자가 붙여 넣으려 하면 멈추게 하고 브라우저 로그인으로 안내합니다.
- 되돌리기에서 **기록이나 파일을 지울 수 있는 명령**(저장 기록 강제 초기화, 강제 푸시, 저장 안 된 파일 일괄 삭제 등)은 쓰지 않습니다. 기록을 남기는 방식(되돌린 내용을 새 저장으로)을 씁니다.
- git 이메일은 **noreply 주소**를 권합니다. 이미 개인 메일로 저장한 기록을 GitHub에 올렸다면 기록에 메일이 남는다는 점을 알려 줍니다(특히 Public 저장소).
- 공용 PC라면 작업 후 "GitHub 로그아웃해줘"를 안내합니다. 데스크탑 앱은 대화 기록도 PC에 남깁니다.
