## Part 1: 좋은 스킬의 조건 — 업무 매뉴얼을 읽는 눈

### 1.1 왜 '한 바퀴 돌린 뒤'에 스킬로 만드나

🧩 **비유**: 신입 동료에게 첫 달에는 옆에 앉아 하나하나 설명합니다. 그런데 둘째 달에도 똑같은 설명을 반복하면 둘 다 지칩니다. 잘 된 첫 달의 과정을 **업무 매뉴얼**로 적어 두면, 다음 달엔 "매뉴얼대로 해 주세요" 한마디면 됩니다. 요리로 치면 한 번 맛있게 만들어 본 뒤 적어 두는 **레시피 카드**입니다.

**설명**
- **스킬**은 `.claude/skills/스킬이름/SKILL.md` 파일 하나로 된 업무 매뉴얼입니다(8회차 복습). 평소엔 제목과 설명만 보이고, **필요할 때만 본문을 꺼내 읽으므로** 동료의 책상(컨텍스트)을 늘 차지하지 않습니다.
- 스킬로 만들 때: **같은 설명·체크리스트를 두 번째 붙여 넣고 있을 때**입니다.
- 한 바퀴 먼저 돌리는 이유: 머릿속으로만 쓴 매뉴얼은 실제 함정을 모릅니다. 7회차에 직접 고치고 검수받은 경험(글자 깨짐, 형식, 원고에 없는 구절 등)이 바로 매뉴얼의 재료입니다.
- **플라이휠(돌릴수록 쉬워지는 바퀴)**: 한 번 돌림 → 스킬로 저장 → 다시 돌리며 고침 → 더 빠르고 좋아짐. 처음 미는 게 가장 무겁고, 그다음부터는 점점 가벼워집니다.

| 7회차에 모은 재료 | 스킬에서 하는 역할 |
|-------------------|-------------------|
| 내가 쓴 프롬프트들(구성안 먼저, 원고에 없는 것 금지…) | 단계와 금지 사항 |
| reviewer 검토 표에서 고친 점 | 검수 체크리스트 |
| `기준예시/` 1세트 + `기준예시_설명.md`의 '꼭 지킬 규칙 5개' | 기준 예시와 출력 형식 |

**우리 단체 예시**: 미션펀드는 분기마다 선교지 소식을 올릴 때 "첫 줄 `#번호`, ▣ 소제목, 번호 붙인 기도제목…"을 매번 다시 설명합니다. 이것을 `mission-update` 스킬로 만들면 `/mission-update 새편지.md` 한 줄이면 됩니다. 엘리온도 STR 주제가 바뀔 때마다 같은 지시를 반복하던 것을 `/str-content`로 바꿀 수 있습니다.

💭 **확인 질문**: 선생님 업무 중 "매번 같은 설명을 하고 있는 일"을 하나 떠올려 보세요. 그 일은 한 바퀴 제대로 돌려 본 적이 있나요?

### 1.2 좋은 스킬의 조건 7가지 (체크리스트)

🧩 **비유**: 좋은 업무 매뉴얼이란 **처음 온 신입이 읽고 혼자 해낼 수 있는 매뉴얼**입니다. 언제 펴 보는지, 무엇을 받아서, 어떤 순서로, 어떤 모양으로 내고, 무엇을 확인하고, 무엇은 절대 하면 안 되는지, 그리고 "이 정도면 합격"인 실물 견본이 있어야 합니다.

**설명** — 스킬을 만들거나 받을 때 이 7칸을 체크합니다.

| ☐ | 조건 | 매뉴얼이 답해야 할 질문 | 예: `str-content` | 빠지면 생기는 일 |
|---|------|------------------------|-------------------|------------------|
| ☐ | ① 언제 쓰는지(설명) | 어떤 요청일 때 이 매뉴얼을 꺼내나? | "STR 원고로 수업 PPT·활동지·교사 가이드를 만들 때" | 필요할 때 안 꺼내거나 엉뚱할 때 꺼냄 |
| ☐ | ② 입력 | 무엇을 받아서 시작하나? 없으면? | 원고 파일, 대상 학년(없으면 먼저 물음) | 되묻기 반복, 또는 추측으로 시작 |
| ☐ | ③ 단계 | 어떤 순서로? 사람 확인은 어디서? | 원고 읽기 → 구성안 승인 → 생성 → 검수 → 보고 | 할 때마다 순서가 달라 품질이 들쭉날쭉 |
| ☐ | ④ 출력 형식 | 무엇을 어떤 모양·이름으로 어디에? | PPT 8~10장·활동지·교사 가이드, `주제_수업.pptx` | 파일 이름·구성이 제각각 |
| ☐ | ⑤ 검수 체크리스트 | 끝내기 전에 무엇을 확인? | 4막 순서, 성경 장·절, 학년 수준, 이미지 속 글자 없음 | 틀린 채로 "완료" 보고 |
| ☐ | ⑥ 금지 사항 | 절대 하지 말 것은? | 원고에 없는 구절·사실 추가 금지 | 같은 실수가 되풀이됨 |
| ☐ | ⑦ 기준 예시 | "이 정도면 합격"의 실물은? | 7회차 `기준예시/` 사본 | 말로만 된 기준 → 결과가 점점 멀어짐 |

- ①은 스킬 맨 위의 **설명(description)**에 씁니다. Claude는 이 설명을 보고 "지금 이 매뉴얼을 꺼낼 때구나"를 스스로 판단합니다. 그래서 선생님이 **실제로 쓰는 말**("선교지 소식", "분기 업데이트")을 넣어야 잘 꺼내 씁니다.
- ②~⑦은 그 아래 **본문**에 씁니다.

**우리 단체 예시**: 다니엘칼리지의 학부모 FAQ 답변 스킬은 ⑥ 금지 사항(학생 개인정보 언급 금지, 확답할 수 없는 약속 금지 등)이 가장 중요합니다. 교진추의 교과서 분석 스킬은 ⑤ 검수 체크리스트(인용문을 원문과 글자 그대로 대조)가 생명입니다.

💭 **확인 질문**: 7가지 중 선생님 단체의 스킬에서 가장 중요한 칸은 무엇이고, 왜 그럴까요?

### 1.3 SKILL.md 해부 — 표지 라벨과 속지

🧩 **비유**: 매뉴얼 바인더에는 **표지 라벨**(이름·언제 쓰는지)과 **속지**(실제 지침)가 있습니다. `SKILL.md`도 똑같이 두 부분입니다.

**설명**
- **앞머리(표지 라벨)**: 파일 맨 위 `---`와 `---` 사이. `name`(부르는 이름), `description`(무엇을·언제 쓰는지)이 핵심입니다. `argument-hint`는 `/이름` 뒤에 무엇을 쓰면 되는지 보여 주는 힌트입니다.
- **본문(속지)**: 그 아래 마크다운(제목·목록으로 된 글). 신입이 읽고 따라 할 지침입니다.
- 7조건을 다 갖춘 스킬은 대략 이런 모양입니다(예시).

```markdown
---
name: str-content
description: STR 원고(창조·타락·회복·완성 4막)로 수업 PPT·학생 활동지·교사 가이드를 한 번에 만듭니다. "STR 콘텐츠 만들어줘", "○○ 주제 수업 자료", "원고로 PPT랑 활동지" 같은 요청에 사용합니다.
argument-hint: "[원고 파일 경로 또는 주제]"
---

# STR 콘텐츠 한 세트 만들기

## 입력
- 이번 요청: $ARGUMENTS
- 대상 학년이 없으면 먼저 묻습니다.

## 단계
1. examples/의 기준 예시를 먼저 읽습니다.
2. 세 산출물의 구성안을 보여 주고 승인을 받습니다.
3. PPT → 활동지 → 교사 가이드 순서로 만듭니다.
4. 검수 체크리스트로 점검하고 결과를 보고합니다.

## 출력 형식
- 주제_수업.pptx(8~10장), 주제_활동지.docx(A4 2쪽 이내), 주제_교사가이드.docx
- 저장 위치: 사용자가 말한 폴더, 없으면 원고와 같은 폴더의 산출물/

## 검수 체크리스트
- [ ] 세 파일 모두 4막 순서
- [ ] 성경 장·절이 원고와 같음
- [ ] 학년 수준 어휘
- [ ] 그림 속 글자 없음(글자는 PPT에서)

## 금지 사항
- 원고에 없는 성경 구절·과학 사실을 새로 넣지 않습니다([제안]으로 따로 표시).

## 기준 예시
- examples/ 폴더(7회차 기준예시 사본)와 examples/기준예시_설명.md
```

> 🏷️ **스킬 이름 짓기**: **영문 소문자와 하이픈(-)만** 쓰는 것을 권장합니다. `/` 뒤에 입력하기 쉽고, 다른 컴퓨터나 플러그인으로 옮길 때도 탈이 적습니다. 폴더 이름과 `name`을 같게 맞춥니다.
> - 좋은 예: `str-content`, `mission-update`, `monthly-newsletter`, `parent-faq-draft`
> - 피할 예: `STR 콘텐츠`(한글·띄어쓰기), `Mission_Update_v2`(대문자·밑줄·버전 번호 — 버전은 Git이 기억합니다)

**우리 단체 예시**: 이 튜터 폴더의 `/handoff`(인수인계 메모)도 이런 스킬입니다. 3회차에 쓰신 그 도구를 이제 매뉴얼을 쓰는 사람의 눈으로 열어 봅니다.

💭 **확인 질문**: 앞머리의 `description`을 대충 "소식 스킬"이라고만 쓰면 어떤 일이 생길까요?

### 1.4 실습: handoff 스킬 해부 (5분)

🎯 **목표**: 실제 스킬 파일을 7조건 체크리스트로 점검해 본다.

🛠 **준비**: 튜터 세션 그대로. 파일은 `.claude/skills/handoff/SKILL.md`입니다. (Mac의 Finder에서는 점(.)으로 시작하는 폴더가 숨겨져 보이지 않을 수 있습니다. Claude에게 보여 달라고 하면 됩니다.)

👣 **단계**
1. 파일을 열어 달라고 합니다.
   ```
   .claude/skills/handoff/SKILL.md를 열어서 앞머리(---사이)와 본문을 나눠 보여줘. 앞머리의 각 줄이 무슨 뜻인지 쉽게 설명해줘.
   ```
2. 7조건으로 점검합니다. **먼저 선생님이 예상**해 본 뒤 요청하세요.
   ```
   이 스킬을 좋은 스킬 7조건(언제 쓰는지·입력·단계·출력 형식·검수 체크리스트·금지 사항·기준 예시)으로 점검해서 표로 보여줘. 칸마다 있음/부족/없음과 근거 문장을 적어줘.
   ```
3. 하나만 개선안을 받아 봅니다(파일은 아직 고치지 않습니다).
   ```
   '부족'이나 '없음'인 칸 하나를 골라, 어떻게 보완하면 좋을지 2~3줄 제안만 해줘. 파일은 고치지 마.
   ```

✅ **이렇게 되면 성공**: 앞머리의 `name`·`description`이 무엇인지 말할 수 있고, 7칸 점검표를 받아 내 예상과 비교했다.

🆘 **막히면**
- 파일이 없다고 하면: `튜터 최신 버전으로 업데이트해줘` 후 다시 시도합니다.
- 표가 어려우면: `쉽게` 또는 `이 표를 초등학생도 알게 다시 설명해줘`

## Part 2: skill-creator로 7회차 작업을 스킬로

🎯 **목표**: skill-creator에게 인터뷰를 받아 7회차 작업을 이 폴더 전용 스킬로 만들고, **새 주제로 실행 → 기준 예시와 비교 → 고치기 → 다시 실행**까지 한 바퀴 돌린다.

🛠 **준비**
- **skill-creator 확인**: 입력창에 `/`를 치면 나오는 목록에 `skill-creator`가 보이는지 확인합니다. 없으면 **+** → **Plugins** → **Add plugin** → `skill-creator` 설치(8회차 Part 2와 같음).
- **기준 예시 확인**: `실습공간/07회차/기준예시/`에 1세트와 `기준예시_설명.md`가 있어야 합니다.
- **실습 데이터 선택**: ① 7회차 기준예시(가상 샘플, 기본) ② 실제 양식 기반 가상 데이터(우리 단체 실제 틀에 가짜 내용을 채운 것) ③ 본인 실제 파일 — 5회차 원칙을 먼저 적용합니다. **스킬 폴더에 들어간 예시는 나중에 동료와 공유될 수 있으니** 개인정보·보안국가 정보가 없는 것만 씁니다.
- **범위**: 이번 스킬은 **이 프로젝트(튜터 폴더) 범위**로 만듭니다. 이 폴더를 열었을 때만 쓰이고, 다른 폴더에서 쓰는 법은 Part 4에서 다룹니다.

👣 **단계**

1. 실습 폴더를 만들고 재료를 확인합니다.
   ```
   실습공간/09회차/ 폴더를 만들어줘. 그리고 실습공간/07회차/기준예시/에 어떤 파일이 있는지, 기준예시_설명.md의 '꼭 지킬 규칙'은 무엇인지 요약해줘.
   ```
2. skill-creator를 부릅니다. **트랙 A(STR)** 예:
   ```
   skill-creator로 7회차에 한 STR 콘텐츠 제작 과정을 스킬로 만들어줘.
   - 스킬 이름: str-content (이 폴더의 .claude/skills/str-content/ 에 만들기)
   - 참고 예시: 실습공간/07회차/기준예시/ 를 스킬 폴더 안 examples/ 로 복사해서 기준 예시로 넣어줘
   - 만들기 전에 먼저 나를 인터뷰해서 기준을 정해줘. 한 번에 한 질문씩, 선택지로 물어봐줘
   - 스킬에 7가지가 다 들어가게: 언제 쓰는지·입력·단계·출력 형식·검수 체크리스트·금지 사항·기준 예시
   - 기준예시_설명.md의 '꼭 지킬 규칙'은 검수 체크리스트와 금지 사항에 반영해줘
   - description은 한국어로, 내가 실제로 쓰는 말("STR 콘텐츠", "수업 자료")을 넣어줘
   - 테스트 평가(eval)나 브라우저 보고서는 이번엔 생략해줘. 실행은 내가 새 세션에서 직접 해 볼게
   ```
   **트랙 B(선교지 소식)**는 첫 세 줄만 바꿉니다.
   ```
   skill-creator로 7회차에 한 선교지 소식 제작 과정을 스킬로 만들어줘.
   - 스킬 이름: mission-update (이 폴더의 .claude/skills/mission-update/ 에 만들기)
   - 모드 두 가지: 일반(기본) / 보안국가(모금 페이지 글만 — SNS 글·쇼츠는 만들지 않기, 민감어 가리기 + 바꾼 목록은 별도 파일, 기준 예시에는 넣지 않기)
   ```
   (나머지 줄 — 참고 예시·인터뷰·7가지·규칙 반영·한국어 설명·평가 생략 — 은 A와 똑같이 붙입니다.)
3. 인터뷰에 답합니다. skill-creator는 만들기 전에 **어떤 경우에 쓰는지, 입력·출력 형식, 성공 기준, 예외 상황**을 묻습니다. 모르는 건 `추천해줘. 이유도 한 줄로`라고 답해도 됩니다.

   | Claude가 물을 만한 것 | 답 예시 (A. STR) | 답 예시 (B. 선교지 소식) |
   |----------------------|------------------|--------------------------|
   | 언제 쓰나요? | 매달 새 STR 주제로 수업 자료 만들 때 | 분기마다 선교사 편지가 오면 |
   | 무엇을 받나요? | 4막 원고 파일 + 대상 학년 | 편지·사진 설명 파일 + 모드 |
   | 결과물은? | PPT 8~10장, 활동지, 교사 가이드 | 업데이트 글, 쇼츠 대본+`.srt`, SNS 글 |
   | 잘 된 기준은? | 기준예시처럼 막마다 슬라이드 2장 | `#번호`·▣ 소제목·번호 기도제목 |
   | 하면 안 되는 것은? | 원고에 없는 구절 추가, 그림 속 한글 | 원자료에 없는 사건·숫자, 과장 |
   | 사람 확인은 어디서? | 구성안 단계 | 게시 전 담당자 확인(보안국가는 2인) |
4. 만들어진 스킬을 확인합니다.
   ```
   만든 SKILL.md를 보여주고, 좋은 스킬 7조건으로 점검한 표도 같이 보여줘. 빠진 칸이 있으면 채워줘.
   ```
   입력창에 `/`를 쳐서 목록에 `str-content`(또는 `mission-update`)가 보이는지 확인합니다.
5. **새 주제 재료**를 만듭니다. (같은 원고로 돌리면 제대로 된 시험이 아닙니다.)
   A(STR):
   ```
   연습용 가상 STR 원고를 '물' 주제로 짧게 만들어 실습공간/09회차/원고/STR_물_원고.md로 저장해줘. 7회차 빛 원고처럼 창조·타락·회복·완성 4막, 초등 5~6학년. 성경 구절은 장·절만 적고 옆에 [사람 확인 필요]를 붙여줘.
   ```
   B(선교지 소식):
   ```
   연습용 가상 선교사 편지를 하나 만들어 실습공간/09회차/원고/선교지소식_새원자료.md로 저장해줘. 일반 국가, 가명, 사진 설명 3개, 기도제목 3개.
   ```
6. **새 세션에서** 실행합니다. 튜터 세션은 그대로 두고, 새 세션(**Ctrl+N** / Mac **Cmd+N**)을 열어 폴더가 `gea-claude-tutor`인지 확인한 뒤 입력합니다.
   ```
   /str-content 실습공간/09회차/원고/STR_물_원고.md
   ```
   (B는 `/mission-update 실습공간/09회차/원고/선교지소식_새원자료.md`)
   > 왜 새 세션인가요? 스킬을 만든 세션은 이미 사정을 다 알고 있어서, 스킬에 빠진 내용을 대화 기억으로 메워 버립니다. **동료가 처음 쓰는 상황**과 같게 해야 빈틈이 보입니다.
7. 기준 예시와 비교합니다(같은 새 세션에서, B는 경로의 `str-content`를 `mission-update`로).
   ```
   이번 결과를 .claude/skills/str-content/examples/의 기준 예시와 항목별로 비교해 표로 보여줘: 항목 | 기준 예시 | 이번 결과 | 같음/다름/기준보다 못함
   ```
8. 튜터 세션으로 돌아와 고쳐 달라고 합니다. 다른 점 **한두 가지만** 골라 구체적으로 말합니다. (B 예: "기도제목에 번호가 빠졌어. 출력 형식과 검수 체크리스트에 '번호 붙인 기도제목 3~5개'를 넣어줘")
   ```
   str-content 스킬을 고쳐줘. 이번 결과에서 교사 가이드에 성경 구절 목록이 빠졌고, PPT가 12장으로 길어졌어.
   출력 형식에 '교사 가이드 마지막에 성경 구절 목록'을, 검수 체크리스트에 'PPT 8~10장인지 센다'를 넣어줘. 바꾼 줄을 보여줘.
   ```
9. 다시 새 세션에서 실행해 좋아졌는지 확인합니다(1~2회 반복). 시간이 없으면 `PPT만 만들어줘`처럼 고친 부분만 다시 만들어 봐도 됩니다.

✅ **이렇게 되면 성공**
- `.claude/skills/str-content/SKILL.md`(또는 `mission-update`)와 `examples/` 폴더가 있다.
- `/` 목록에 내 스킬이 보이고, 새 세션에서 **새 주제로** 실행됐다.
- 기준 예시와의 비교 표를 받았고, 스킬을 한 번 이상 고친 뒤 다시 실행해 나아진 점을 확인했다.

🆘 **막히면**

| 증상 | 이렇게 해 보세요 |
|------|-----------------|
| `/` 목록에 skill-creator가 없음 | **+** → **Plugins** → **Manage plugins**에서 켜져 있는지 확인, 없으면 **Add plugin**으로 설치 |

## Part 3: 단축 명령처럼 쓰기 — 주제 넘기기·검수자·템플릿

### 3.1 주제 넘기기(인자) — 주문서의 빈칸

🧩 **비유**: 매뉴얼은 그대로 두고, **이번 달 주제만 주문서 빈칸에 적어** 건넵니다. "매뉴얼대로, 이번엔 '물'로요."

**설명**
- `/str-content 물`처럼 스킬 이름 뒤에 쓴 말을 **인자**(스킬에 넘기는 재료)라고 합니다.
- 스킬 본문에 `$ARGUMENTS`라고 적힌 자리에 그 말이 그대로 들어갑니다. 그런 자리가 없어도 Claude는 뒤에 붙은 말을 함께 읽습니다.
- 앞머리의 `argument-hint`는 `/` 목록에서 "뒤에 무엇을 쓰면 되는지" 보여 주는 힌트입니다.
- 설명(description)을 잘 써 두면 `/` 없이 "'물' 주제로 STR 수업 자료 만들어줘"라고만 해도 Claude가 알아서 이 스킬을 꺼내 씁니다.

**우리 단체 예시**
- 미션펀드: `/mission-update 보안국가 실습공간/09회차/원고/선교지소식_새원자료.md` → 스킬이 '보안국가'라는 말을 보고 가리기 모드로 진행
- 다교연: `/monthly-newsletter 2026-10` → 10월호 소식지

💭 **확인 질문**: `/str-content 물`에서 '물'은 스킬 파일의 어느 자리에 들어갈까요?

### 3.2 실습: 검수자와 템플릿 붙이기

🎯 **목표**: 내 스킬에 ① 주제만 줘도 시작하는 입력 규칙 ② 마지막 reviewer 검수 ③ 템플릿·예시 파일을 붙인다.

🛠 **준비**: Part 2에서 만든 스킬. 튜터 세션에서 요청하고, 실행은 새 세션에서 합니다. B 트랙은 `str-content`를 `mission-update`로 바꾸고, 1단계를 "모드(일반/보안국가)가 없으면 먼저 묻기", 3단계 템플릿을 `templates/업데이트글_틀.md`(#번호·▣·기도제목)로 바꿔 요청합니다.

👣 **단계**
1. 입력 규칙을 넣습니다(사람 확인 지점이 하나 생깁니다).
   ```
   str-content 스킬의 입력을 이렇게 바꿔줘.
   - 원고 파일 경로가 오면 그 원고로 진행
   - 주제만 오면 4막 원고 초안을 먼저 만들어 보여주고 내 승인을 받은 뒤 진행
   - 아무것도 없으면 주제와 대상 학년을 먼저 물어보기
   argument-hint도 "[원고 파일 경로 또는 주제]"로 넣어줘.
   ```
2. 검수자를 붙입니다(7회차에서 쓴 `reviewer` 에이전트).
   ```
   str-content 스킬 단계 끝에 이 단계를 넣어줘:
   "완성하면 reviewer 에이전트로 원고·기준 예시와 비교해 검수받는다. '확실'한 문제는 고치고, '불확실'한 것은 나에게 묻는다. 마지막 보고에 확실/불확실/추측을 나눠 표시한다."
   ```
3. 템플릿과 예시 파일을 스킬 폴더에 둡니다.
   ```
   str-content 스킬 폴더를 이렇게 정리해줘.
   - templates/활동지_틀.md: 관찰하기·생각하기·적용하기 문항 틀
   - examples/: 지금 있는 기준 예시 그대로
   SKILL.md에는 "활동지를 만들 때 templates/활동지_틀.md를 따른다", "시작 전에 examples/를 읽는다"처럼 언제 어떤 파일을 보는지 적어줘.
   ```
   결과 폴더는 대략 이렇게 됩니다.
   ```
   .claude/skills/str-content/
   ├── SKILL.md          ← 표지 라벨 + 지침(핵심만)
   ├── templates/        ← 빈 양식(틀)
   │   └── 활동지_틀.md
   └── examples/         ← 합격 견본(7회차 기준예시)
   ```
4. 새 세션에서 **주제만** 넘겨 실행해 봅니다.
   ```
   /str-content 소리
   ```

✅ **이렇게 되면 성공**
- 주제만 넣었을 때 원고 초안을 먼저 보여 주고 승인을 기다렸다.
- 결과 끝에 reviewer 검수표와 확실/불확실/추측 표시가 나왔다.
- 스킬 폴더에 `templates/`와 `examples/`가 있고, SKILL.md에 언제 볼지 적혀 있다.

🆘 **막히면**
- reviewer를 못 찾는다고 하면: `튜터 최신 버전으로 업데이트해줘`. 그래도 안 되면 단계를 "새 눈으로 다시 읽고 검수표를 만든다"로 바꿔 달라고 합니다.
- 원고 초안에서 멈추지 않고 끝까지 가 버리면: `원고 초안 뒤에 '승인을 기다린다'가 확실히 지켜지게 스킬 문장을 고쳐줘`
- SKILL.md가 너무 길어지면: `긴 설명은 별도 파일로 옮기고 SKILL.md에는 핵심 지침만 남겨줘`

## Part 4: 팀과 공유 — 내 매뉴얼을 동료 책상에

### 4.1 공유하는 세 가지 방법

🧩 **비유**: 매뉴얼을 복사해 동료 책상마다 놓아두면, 고칠 때마다 다시 돌려야 하고 어느 게 최신인지 헷갈립니다. **공유 캐비닛**(GitHub 비공개 저장소)에 한 부를 두고, 새 판이 나오면 모두 같은 판을 꺼내 쓰는 편이 낫습니다.

**설명**

| 방법 | 누가 쓰나 | 난이도 |
|------|----------|--------|
| ① 스킬이 든 폴더를 Git 저장소로 → GitHub **비공개** 저장소 → 동료가 받아서 그 폴더를 열고 사용 (이번 실습) | 초대한 동료 | 🌱🌿 |
| ② 내 **개인 스킬**로 복사(사용자 폴더의 `.claude/skills/`) → 내 컴퓨터의 **어느 폴더에서든** 사용 | 나 혼자 | 🌿 |
| ③ 🌳 **플러그인**으로 묶어 마켓으로 배포 → 동료는 한 번 설치하면 어디서나 `/플러그인:스킬` | 팀 전체 | 🌳 |

- 4회차에서 배운 Git(세이브 포인트)과 GitHub(인터넷 금고)을 그대로 씁니다. 스킬도 결국 **폴더와 글 파일**이기 때문입니다.
- 비공개 저장소도 "비밀 금고"는 아닙니다. **개인정보는 처음부터 넣지 않습니다.**

**우리 단체 예시**: 엘리온 강사들이 같은 `/str-content`를 쓰면 반마다 수업 자료 품질이 고르게 됩니다. 미션펀드는 담당자가 바뀌어도 `mission-update` 저장소를 넘겨주면 그것이 곧 인수인계입니다.

💭 **확인 질문**: 스킬을 고쳤을 때 ① 방법에서는 동료가 새 판을 어떻게 받게 될까요?

### 4.2 실습: GitHub 비공개 저장소로 공유하기

🎯 **목표**: 내 스킬을 공유용 폴더에 담아 GitHub 비공개 저장소에 올리고, 동료가 받아 쓰는 방법을 안다.

🛠 **준비**
- GitHub 계정(사전 설치 가이드). 4회차 Part 3에서 GitHub 로그인을 건너뛰었다면 이번에 Claude가 필요한 도구 설치와 브라우저 로그인을 안내합니다. 🌱은 막히면 1~2단계까지만 해도 됩니다.
- 저장소 이름도 **영문 소문자·하이픈**으로 정합니다. 예: `elion-ai-skills`, `missionfund-ai-skills`. 아래 예시의 엘리온 이름은 선생님 단체·스킬 이름으로 바꿔 쓰세요.

👣 **단계**
1. 공유용 폴더를 만듭니다. (튜터 폴더 자체를 올리지 않고, 내 스킬만 따로 담습니다.)
   ```
   실습공간/09회차/elion-ai-skills/ 폴더를 만들고, .claude/skills/str-content/ 폴더를 통째로 그 안의 .claude/skills/str-content/로 복사해줘.
   README.md도 만들어줘: 이 저장소의 스킬 목록, 동료가 받아서 쓰는 방법, /str-content 사용 예시.
   복사한 파일에 개인정보나 보안국가 정보가 없는지 점검해서 알려줘.
   이 폴더를 Git으로 관리하고 첫 저장(커밋)까지 해줘.
   ```
   💡 이 작업 뒤에 `/`를 쳤을 때 `str-content`가 두 번 보일 수 있습니다. 하나는 원본, 하나는 공유용 복사본이라 정상입니다. 고칠 때는 **원본**(`.claude/skills/str-content/`)을 고치고, 공유 폴더에는 "공유 폴더에도 반영해줘"로 복사합니다.
2. GitHub에 **비공개**로 올립니다.
   ```
   이 폴더를 GitHub에 비공개(Private) 저장소 elion-ai-skills로 올려줘. 다 되면 저장소 주소와 비공개인지 확인 결과를 알려줘.
   ```
   Claude가 도구 설치·로그인·업로드 명령을 실행하겠다고 물으면 내용을 읽고 승인합니다.
3. 동료를 초대합니다. (보내기 전에 한 번 더 확인합니다.)
   ```
   GitHub 아이디 ○○○인 동료를 이 저장소에 협업자로 초대하고 싶어. 초대를 보내기 전에 무엇을 할지 먼저 보여줘.
   ```
   동료는 이메일이나 GitHub 알림으로 온 초대를 수락합니다. (GitHub 저장소 페이지의 **Settings**에서도 초대할 수 있습니다. 화면 문구는 조금 다를 수 있습니다.)
4. **동료 쪽**에서 받아 씁니다. 1회차에 튜터를 받던 방법과 같습니다.
   - Code 탭에서 **Select folder**로 '문서' 폴더를 열고: `https://github.com/내아이디/elion-ai-skills 를 이 폴더에 받아줘`
   - 받은 `elion-ai-skills` 폴더를 **Select folder**로 다시 열고, 입력창에 `/`를 쳐서 `str-content`가 보이면 성공입니다.
   - 동료가 자기 작업 폴더에서 쓰고 싶으면: `elion-ai-skills/.claude/skills/str-content 폴더를 이 폴더의 .claude/skills/로 복사해줘`
5. 고친 판을 나눕니다.
   - 나: `str-content 스킬을 고쳤어. 공유 폴더에도 반영하고 저장(커밋)해서 GitHub에 올려줘`
   - 동료: `이 폴더를 GitHub의 최신 버전으로 받아줘`

> 💡 나 혼자 어느 폴더에서나 쓰고 싶다면(방법 ②): `str-content 스킬을 내 개인 스킬 폴더(사용자 폴더의 .claude/skills)로 복사해줘`. 다만 같은 이름이 두 곳에 있으면 헷갈리니, 고칠 곳을 한 곳으로 정해 둡니다.

✅ **이렇게 되면 성공**
- GitHub에 **Private** 표시가 된 저장소가 있고, 안에 `.claude/skills/스킬이름/SKILL.md`와 `README.md`가 있다.
- 동료가 받는 순서(받기 → 그 폴더 열기 → `/` 확인)를 말할 수 있다.

🆘 **막히면**
- GitHub 로그인이 안 되면: `GitHub 로그인이 막혔어. 지금 상태를 점검하고 한 단계씩 안내해줘`. 계속 막히면 오늘은 1단계(공유 폴더 + 커밋)까지만 하고, 과제 때 다시 합니다.
- 동료가 `/` 목록에서 스킬을 못 찾으면: 받은 폴더를 **Select folder**로 연 **새 세션**인지 확인합니다.
- 동료가 초대 메일을 못 받았으면: 동료의 GitHub 아이디(이메일 아님)를 다시 확인합니다.
- 동료가 저장소를 못 받으면: 비공개 저장소라 동료도 초대를 수락하고 GitHub에 로그인되어 있어야 합니다. 동료가 `GitHub 로그인부터 도와줘`라고 하면 됩니다.

### 4.3 🌳 플러그인으로 묶기 — 개요

여러 스킬과 에이전트를 **업무 키트 하나**로 묶어, 동료가 한 번 설치하면 **어느 폴더에서든** 쓰게 하는 방법입니다. 이 튜터 레포가 그대로 예시입니다.

```
gea-claude-tutor/
├── .claude-plugin/marketplace.json      ← "이 저장소는 마켓입니다" + 플러그인 목록
└── plugins/gea-toolkit/
    ├── .claude-plugin/plugin.json       ← 플러그인 이름표
    └── skills/
        ├── handoff/SKILL.md
        ├── research-first/SKILL.md
        ├── eli5/SKILL.md
        └── self-review/SKILL.md
```

- **plugin.json**(플러그인 이름표): `name`이 꼭 필요하고, 설명·버전 등은 선택입니다. 최소 예:
  ```json
  {
    "name": "elion-toolkit",
    "description": "엘리온에듀 STR 콘텐츠 제작 도구 모음",
    "version": "0.1.0"
  }
  ```
- **skills/**: 지금까지 만든 스킬 폴더를 그대로 옮겨 넣습니다.
- **marketplace.json**: 저장소 맨 위 `.claude-plugin/`에 두고, 어떤 플러그인이 어느 폴더에 있는지 적습니다. 이 튜터의 `.claude-plugin/marketplace.json`을 열어 보면 `gea-toolkit`이 `./plugins/gea-toolkit`에 있다고 적혀 있습니다.
- 동료는 8회차에서 한 것처럼 마켓을 추가(`내아이디/elion-ai-skills`)하고 설치하면 `/elion-toolkit:str-content`로 어디서나 씁니다.
- 비공개 저장소를 마켓으로 쓸 때 동료 컴퓨터에 필요한 조건(GitHub 로그인 등)은 `비공개 저장소를 플러그인 마켓으로 추가하려면 동료 PC에 뭐가 필요해? 공식 문서로 확인해줘`라고 먼저 확인합니다.
- 시작 문장:
  ```
  elion-ai-skills 저장소를 이 튜터 레포의 plugins/gea-toolkit 구조처럼 플러그인 마켓으로 바꾸고 싶어. 바로 하지 말고 계획부터 보여줘.
  ```

## 💬 이번 회차 딸깍 프롬프트 카드

**언제 쓰나**: 한 바퀴 돌려 본 일을 스킬로 만들 때
```
skill-creator로 방금(또는 ○회차에) 한 작업을 스킬로 만들어줘. 이름은 영문 소문자와 하이픈으로. 먼저 나를 인터뷰해서 기준을 정하고, 7가지(언제 쓰는지·입력·단계·출력 형식·검수 체크리스트·금지 사항·기준 예시)가 다 들어가게 해줘. 이 폴더의 .claude/skills/에 만들어줘.
```

**언제 쓰나**: 스킬 파일이 잘 만들어졌는지 점검할 때
```
.claude/skills/○○/SKILL.md를 좋은 스킬 7조건으로 점검해서 표로 보여줘. 칸마다 있음/부족/없음과 근거 문장, 보완 제안 한 줄.
```

**언제 쓰나**: 스킬 결과가 기준에 맞는지 볼 때 (새 세션에서)
```
이번 결과를 스킬 폴더의 examples/ 기준 예시와 항목별로 비교해 표로 보여줘: 항목 | 기준 예시 | 이번 결과 | 같음/다름/기준보다 못함
```

**언제 쓰나**: 결과가 마음에 안 들어 스킬을 고칠 때
```
○○ 스킬을 고쳐줘. 이번 결과에서 (다른 점 1~2개)가 기준과 달랐어. 이게 다시 안 생기도록 단계나 검수 체크리스트를 고치고, 바꾼 줄을 보여줘.
```

**언제 쓰나**: 스킬 끝에 검수를 붙일 때
```
○○ 스킬 마지막 단계에 reviewer 에이전트 검수를 넣어줘. 확실한 문제는 고치고, 불확실한 것은 나에게 묻고, 보고에 확실/불확실/추측을 나눠 표시하게.
```

**언제 쓰나**: 스킬을 동료와 나눌 때
```
○○ 스킬을 공유용 폴더에 담아 README를 쓰고, 개인정보가 없는지 점검한 뒤 GitHub 비공개 저장소로 올려줘. 올리기 전에 계획부터 보여줘.
```

내 프로젝트에서 **반복되는 부분**을 스킬로 만들고, **2회 이상 실행한 기록**을 `내_학습기록/내_프로젝트.md`에 남깁니다.

```
내 프로젝트(내_학습기록/내_프로젝트.md)에서 반복되는 작업을 skill-creator로 스킬로 만들고 싶어. 7회차 기준예시(실습공간/과제/내프로젝트/기준예시/)와 '9회차 메모'의 규칙 3가지를 반영해줘. 먼저 나를 인터뷰해줘.
```

- 스킬 위치: 내 프로젝트 폴더를 **Select folder**로 연 세션에서 만들면 그 폴더의 `.claude/skills/`에 생깁니다. 프로젝트 폴더를 Git으로 관리 중이면 만든 뒤 "지금 상태 저장해줘".
- `내_프로젝트.md`에 추가할 칸:

```markdown
## 9회차: 스킬로 만들기
- 스킬: /○○-○○ (위치: 실습공간/과제/내프로젝트/.claude/skills/○○-○○/)
- 7조건 점검: 언제 ✅ / 입력 ✅ / 단계 ✅ / 출력 ✅ / 검수 ✅ / 금지 ✅ / 기준 예시 ✅
- 실행 기록
  | 회 | 날짜 | 입력(주제·파일) | 결과 요약 | 고친 점 |
  |----|------|----------------|----------|--------|
  | 1 | | | | |
  | 2 | | | | |
- 공유: 안 함 / GitHub 비공개 저장소(이름)
- 10회차에 이어갈 것: 사람 승인 지점, 예약 실행 여부
```

프로젝트가 계산 위주(예: 후원 점검)라면 6회차 스크립트를 스킬이 실행하게 하고, 검산 단계를 검수 체크리스트에 넣습니다.

## 📌 오늘의 요약

- 스킬 = 한 바퀴 돌려 본 일을 적은 **업무 매뉴얼**. 두 번째부터는 설명하지 말고 `/스킬이름`으로 불러냅니다.
- 좋은 스킬 7조건: 언제 쓰는지·입력·단계·출력 형식·검수 체크리스트·금지 사항·기준 예시. 이름은 영문 소문자·하이픈.
- skill-creator에게 **인터뷰 먼저** 받고 만들고, **새 세션·새 주제**로 실행해 기준 예시와 비교한 뒤 고칩니다.
- 주제는 `/스킬이름 주제`로 넘기고, 끝에는 reviewer 검수를 붙입니다.
- 공유는 GitHub **비공개** 저장소로. 스킬 폴더에는 개인정보를 넣지 않습니다.

### 해부 실습(1.4) 예상 답 — 2026-09 기준 handoff 파일
| 조건 | handoff에서 찾은 곳 | 판정 |
|------|--------------------|------|
| ① 언제 | `description`의 "인수인계", "새 세션으로 넘어가자" 등 | 있음 |
| ② 입력 | 이번 세션 대화·작업 파일 + 주제(`$ARGUMENTS`, 선택) | 있음 |
| ③ 단계 | 본문 '순서' 1~4 | 있음 |
| ④ 출력 형식 | '메모 형식' 틀 + 파일 이름 `YYYY-MM-DD_주제.md` | 있음 |
| ⑤ 검수 | "추측으로 채우지 말고 '확인 필요'" 정도 | 부족 |
| ⑥ 금지 | '지켜야 할 것'(개인정보 옮겨 적지 않기, 40줄 안팎) | 있음 |
| ⑦ 기준 예시 | 빈 틀은 있으나 완성된 견본은 없음 | 부족 |

파일이 업데이트로 바뀌었을 수 있으니, 실제 파일을 읽고 판단합니다. 정답 맞히기보다 "근거 문장을 찾아 가리키는 연습"이 목적입니다.

### 퀴즈 정답과 해설
1. **X** — 영문 소문자와 하이픈이 권장됩니다(`mission-update`). `/` 뒤에 입력하기 쉽고, 다른 컴퓨터·플러그인으로 옮길 때 탈이 적습니다. 버전 번호도 이름에 붙이지 않습니다(Git이 기억).
2. **②** — Claude는 스킬 목록의 이름과 `description`을 보고 언제 꺼낼지 판단합니다. 본문은 꺼낸 뒤에 읽습니다. 그래서 설명에 실제로 쓰는 말을 넣어야 합니다.
3. 예시 답: 만든 세션에는 인터뷰 내용과 사정이 이미 대화에 남아 있어서, 스킬 파일에 빠진 내용을 Claude가 기억으로 메워 버립니다. 새 세션은 **스킬 파일만 보고** 일하므로, 동료가 처음 쓸 때처럼 빈틈이 드러납니다. (3회차 '1업무 1세션'과 같은 원리)
4. **③** — 본문의 `$ARGUMENTS` 자리에 그대로 들어갑니다. 그런 자리가 없으면 Claude가 뒤에 붙은 말을 함께 읽습니다. 이름이나 설명은 바뀌지 않습니다.
5. 예시 답(두 가지 이상, 이유 포함이면 정답): ① 실명·연락처 등 **개인정보**(공유 저장소는 여러 사람이 받아 가고, 비공개여도 한 번 올라가면 되돌리기 어렵다) ② **보안국가 선교사 정보와 바꾼 목록(치환표)**(가린 글과 치환표가 같이 있으면 가린 의미가 없어지고 사람의 안전과 직결) ③ 실제 후원자 파일·학부모 문의 원문(목적에 필요 없는 정보, 5회차 1계명).

### 실전 과제 검수 기준
- **공통**: 이름이 영문 소문자·하이픈 / 앞머리에 `name`·`description`(실제 쓰는 말 포함) / 7조건 모두 있음(점검표 첨부) / **새 세션에서 서로 다른 입력으로 2회 이상** 실행한 기록 / 1회 이상 고친 이력과 나아진 점 / `examples/`·`templates/`에 개인정보 없음 / 끝에 reviewer 검수 또는 자기 검수 + 확실/불확실/추측 표시.
- **미션펀드**: `#번호`·▣·번호 기도제목 형식이 스킬에 명시. 보안국가 모드의 가리기 규칙(실명→가명, 국가→이니셜, 종교 용어→초성, 얼굴·위치 삭제)이 있고, 바꾼 목록은 별도 파일이며 `examples/`와 공유 저장소에 없음. 보안국가 모드는 SNS 글·쇼츠를 만들지 않음. 게시 전 담당자 확인, 보안국가는 2인 승인 단계. 실제 보안국가 자료를 쓰지 않았음.
- **다교연**: 호 번호·날짜를 인자로 받음, 소식지 순서 고정, 날짜·숫자·단체명 원자료 대조 단계, 사진 게시 동의 확인 칸, 구독자 명단은 스킬 폴더에 없음.
- **엘리온**: 4막 순서, 파일 이름 규칙(주제_수업/활동지/교사가이드), 학년 입력, 성경 구절 사람 대조 단계, 그림 속 글자 금지(4회차 원소스·산출물 폴더 규칙과 연결되면 가산).
- **교진추**: 교진추 관점(반진화론·창조과학)을 적극 수용해 논거를 힘 있게 쓰도록 스킬에 명시하되, 인용문은 원문과 **글자 그대로**, 쪽수·출판사·판 표기, 원문에 없는 인용 생성 금지, reviewer로 주장-근거 대응 점검. 예상 반론을 가장 강한 형태로 받는 단계가 있으면 가산.
- **다니엘**: 가드레일이 금지 사항에 구체적으로(다른 학생 정보 언급 금지, 성적·합격 보장 금지, 의료·법률 판단 금지, 확답 못 할 것은 "담당자 확인 후 안내"), 모든 초안에 "사람 확인 필요" 표시, 시험 문의 5개 결과표. D3 '대니' 설정값과 같은 원리(규칙을 파일로 고정)임을 짚어 주면 좋음.
- **SHINE**: 장면마다 촬영/AI 생성 구분, "실존 인물은 찍고, 상징은 생성" 원칙, 영상 도구 예시에 Sora 제외(서비스 종료).

### 안전·개인정보 주의
- **스킬 폴더는 공유될 수 있는 곳**입니다. `examples/`·`templates/`·SKILL.md에 실명·연락처·실제 후원 내역·학부모 문의 원문·보안국가 정보를 넣지 않게 합니다. 가리기 규칙에는 "국가→이니셜"처럼 **규칙만** 쓰고, 실제 국가명·인명 목록(치환표)은 넣지 않습니다.
- 비공개 저장소도 초대받은 사람은 모두 봅니다. 공유 전 "개인정보 점검"을 반드시 거치게 합니다(4.2 단계 1).
