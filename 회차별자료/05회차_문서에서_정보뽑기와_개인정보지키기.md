## Part 1: AI와 개인정보 5계명 (15분)

### 1.1 AI가 '읽은' 서류는 어디로 가나

🧩 **비유** — 우리 신입 동료는 내 PC 폴더 안에서 일하는 것처럼 보이지만, **두뇌는 미국 본사**에 있습니다. 서류를 "읽어 봐"라고 건네면 그 사본이 본사 책상으로 가서 읽힙니다.

**설명**
- 파일 자체는 내 PC에 그대로 있습니다(**Local** 환경 기준). 하지만 Claude가 파일을 **읽는 순간 그 내용은 대화에 들어가 Anthropic 서버로 전송**됩니다(암호화되어 전송).
- 그래서 세 가지를 따로 생각해야 합니다.

| 구분 | 뜻 | 막을 수 있나 |
|---|---|---|
| **학습** | 내 대화로 AI 모델을 더 훈련 | ✅ 설정으로 막습니다. 팀 플랜은 기본적으로 학습에 쓰지 않습니다(👍👎 피드백을 보낸 대화는 예외 가능). 개인 Pro는 설정 → 개인정보(**Privacy**) → **Help improve Claude** 끄기 (화면 문구는 조금 다를 수 있습니다) |
| **저장** | 서버에 일정 기간 보관 | ⚠️ 줄일 수만 있습니다. 학습을 막아도 보통 30일 보관(개인 Pro에서 학습을 켜 두면 5년), 저장 위치는 미국. 내 PC에도 대화 기록이 남습니다 |
| **전송** | 내용이 서버로 감 | ❌ 읽히는 순간 일어납니다 → **보낼 것 자체를 줄이는 수밖에 없습니다** |

- 한 줄 정리: **"학습 안 함 ≠ 저장 안 함 ≠ 전송 안 함."**

**우리 단체 예시** — 미션펀드 담당자가 후원자 엑셀 원본을 "읽어 봐"라고 하면, 팀 플랜이라도 이름·연락처·금액은 이미 서버로 간 것입니다. 그래서 질문을 바꿉니다. "AI를 써도 될까?"가 아니라 **"무엇을 읽게 할까?"**

💭 **확인 질문**: 팀 플랜을 쓰면 신청서 원본을 넣어도 "서버로는 가지 않는다" — 맞을까요?

### 1.2 AI와 개인정보 5계명

🧩 **비유** — 선교지로 짐을 부칠 때, 싸기 전에 먼저 '그대로 보낼 것 / 포장해서 가릴 것 / 절대 부치지 않을 것'을 나눕니다. AI에게 자료를 줄 때도 똑같습니다.

| # | 계명 | 이렇게 합니다 | 우리 단체 예시 |
|---|---|---|---|
| ① | **목적에 필요한 것만** | 필요한 열·문장만 남긴 'AI용 사본' 만들기 | 후원 성공/실패 점검에 이름은 필요 없음 → 후원자ID·월·결과·금액만 |
| ② | **가명·익명 먼저** | 이름 → 번호(D0001). 이름↔번호 **대응표는 AI 작업 폴더 밖, 잠긴 곳에** | 학부모 문의 기록의 학생 이름 → 학생A, 학생B |
| ③ | **민감정보는 넣지 않기** | 주민등록번호·계좌·카드번호·비밀번호·건강 정보는 **지우고 시작** | 기부금영수증 발급명세(주민번호·주소)는 AI 작업 대상이 아님 |
| ④ | **보안국가 선교사 정보는 AI 입력 제외** | 실명·국가·얼굴 사진·교회명·종교 용어가 담긴 자료는 가명처리가 아니라 **아예 넣지 않고 사람이 직접** | 보안국가 사역자 신청서는 추출 대상에서 빼고 담당자가 직접 입력 |
| ⑤ | **결과물 공유·저장 위치 관리** | 결과 파일은 내 PC·단체 내부 저장소에. 공개 링크·공개 GitHub 금지, 공용 PC 기록 정리 | 4회차 `.gitignore`로 원본·결과 폴더가 GitHub에 올라가지 않게 |

- ④가 '가명'이 아니라 '제외'인 이유: 이름을 바꿔도 '국가 + 나이대 + 사역 분야'처럼 정보가 쌓이면 누구인지 짐작할 수 있고, 신원 노출은 생명·안전 문제로 이어질 수 있기 때문입니다.

**법은 이렇게 말합니다** (개인정보 보호법, 2026.9.11. 시행본 — 요지만)
- **제3조**: 목적에 필요한 **최소한**만 처리하고, 익명으로 목적을 이룰 수 있으면 익명, 안 되면 가명으로 → ①②계명과 같은 원칙입니다.
- **제23조**: 사상·신념, 건강 등 **민감정보**는 별도 동의나 법령 근거가 있어야 처리 → 기도제목 속 건강 이야기, 사역 내용·소속 교회는 신중히 다룹니다.
- **제24조의2**: **주민등록번호**는 법령이 허용한 경우에만 처리 → 영수증 발급에 허용된 것이지, AI 작업에 허용된 것이 아닙니다.
- **제28조의8**: 개인정보를 **국외로** 보내 처리·보관하려면 정해진 요건이 필요 → Claude의 데이터는 미국에 저장되므로 **원본을 보내지 않는 것**이 가장 쉬운 위험 감소책입니다.
- 우리 단체 업무가 구체적으로 어디에 해당하는지는 **단체 개인정보 보호책임자나 전문가 확인**이 필요합니다.

💭 **확인 질문**: 선생님 업무 파일 하나를 떠올려 보세요. 그 안에서 ③이나 ④에 해당하는 칸은 무엇인가요?

### 1.3 보안은 '부탁'이 아니라 '설정과 설계'

🧩 **비유** — 신입에게 금고 비밀번호를 알려 주면서 "절대 아무에게도 말하지 마"라고 부탁하는 것과, 비밀번호는 알려 주지 않고 "금고 여는 절차서를 만들어 줘"라고 하는 것. 어느 쪽이 안전할까요?

**설명**
- 프롬프트에 **"외부로 보내지 마", "기억하지 마"라고 쓰는 것은 보안 대책이 아닙니다.** 읽는 순간 이미 전송됐고, AI는 지시를 100% 따르는 기계가 아닙니다.
- 진짜 대책은 두 가지, **설정**과 **설계**입니다. 이것도 위험을 "없애는" 것이 아니라 **크게 줄이는** 방법입니다.

**설정 점검표** (한 번 해 두면 됩니다)
- [ ] 단체 **팀 플랜** 사용. 개인 Pro라면 **Help improve Claude** 끄기
- [ ] 개인정보가 오간 대화에는 👍👎 피드백을 누르지 않기
- [ ] 세션 환경은 **Local**(내 컴퓨터)
- [ ] 권한 모드는 **Manual** 권장(익숙해지면 Accept edits). **Bypass permissions**는 쓰지 않기
- [ ] 원본 파일 폴더는 Claude 작업 폴더 **밖**에 두기 (Manual 모드에서는 폴더 밖을 읽기 전에 Claude가 먼저 물어봅니다)
- [ ] 공용 PC라면 작업 후 기록 정리 (데스크탑 앱은 읽은 내용을 포함한 대화 기록을 내 PC에 남깁니다)

**설계 — 가장 좋은 패턴: "가짜로 도구 만들고, 진짜는 내 PC에서, AI엔 건수만"**

```
① 가짜 샘플 (양식·열 이름은 같고 내용은 가짜)
      ↓  Claude가 이걸 보고 '처리 스크립트(작은 자동 처리 프로그램)'를 만듦
② 실제 파일 → 그 스크립트가 내 PC에서 처리  (Claude는 원본을 읽지 않음)
      ↓
③ 화면에는 "처리 8건 / 빈칸 2건 / 형식 오류 1건"처럼 숫자만 출력
   (화면 출력도 Claude에게 전달되므로 이름·번호는 출력하지 않게)
```

- 발상의 전환: **AI에게 신청서를 읽히는 게 아니라, '신청서 읽는 기계'를 AI에게 만들게 합니다.**
- Part 2에서 직접 해 보고, 6회차(후원 엑셀)에서 본격적으로 씁니다.

> 🌳 **더 강한 방법 — 폴더 '읽기 금지' 규칙**: Claude에게 "이 프로젝트 설정 파일에 `원본_잠금` 폴더를 읽지 못하게 하는 Read 거부 규칙을 추가해줘"라고 요청할 수 있습니다. 단, 이 규칙은 **Claude가 파일을 여는 것**을 막을 뿐, **스크립트가 직접 여는 파일은 막지 않습니다.** 그래서 위 패턴과 함께 쓰면 꼭 맞습니다.

**우리 단체 예시** — 미션펀드 선교사 신청서, 다교연이 매달 받는 후원 엑셀, 다니엘칼리지 학부모 문의 기록은 모두 이 패턴으로 처리할 수 있습니다.

💭 **확인 질문**: "이 파일은 비밀이니 다른 데 보내지 마"라고 프롬프트에 적으면 안전해질까요? 그 대신 무엇을 해야 할까요?

## Part 2: 신청서 8장 → 엑셀 표 만들기 (25분)

🎯 **목표**: 가상 선교사 신청서 8장에서 7개 항목을 뽑아 엑셀 표(DB)로 만들고, 원문과 대조해 검증한 뒤, 실제 신청서에도 쓸 수 있는 **추출 도구(스크립트)**로 바꿔 둡니다. (미션펀드 M3 사전질문)

🛠 **준비**
- 새 세션(**Ctrl+N** / Mac **Cmd+N**), 세션 이름 "5회차 신청서 추출"
- 권한 모드 **Manual** 권장 — 무엇을 설치·실행하는지 보면서 승인합니다
- **실습 데이터 고르기** (튜터가 물어봅니다): ① 제공된 가상 샘플 `실습자료/05_신청서/` (기본) ② 우리 단체 **빈 양식**을 주고 가짜 내용으로 채운 샘플 ③ 실제 신청서 → Part 1의 분류(보낼 것/가릴 것/보내지 말 것)를 먼저 하고, **6단계(스크립트) 방식으로만**. 보안국가 신청서는 제외

👣 **단계**

**1. 실습 파일 복사하기**
```
실습자료/05_신청서 폴더를 실습공간/05회차/신청서/로 복사해줘. 원본은 건드리지 마.
```

**2. 항목 뽑아 엑셀 표 만들기** — 지금은 가상 데이터라 Claude가 직접 읽어도 괜찮습니다.
```
실습공간/05회차/신청서/ 폴더의 신청서 8개에서 이름·연락처·이메일·생년월일·소속·사역국가·사역내용을 뽑아 엑셀 표로 만들어줘.
- 신청서 1개 = 1행, 맨 앞 열은 파일 이름
- 신청서에 없는 값은 지어내지 말고 빈칸으로 두고, 마지막 '확인 필요' 열에 이유를 적어줘
- 전화번호·날짜 형식이 이상한 것도 '확인 필요'에 표시해줘
- 결과는 실습공간/05회차/신청서_DB.xlsx로 저장해줘
```
- Claude가 Word 파일을 읽는 도구(파이썬 패키지)를 설치하겠다고 물어보면, "무엇을 설치하는지 한 줄로 설명해줘"라고 한 뒤 승인하세요.
- 가상 샘플 중 `신청서_06`은 **보안국가 양식 예시**입니다. 처음부터 코드명(M-017)과 이니셜(C국)만 적도록 되어 있어 연습에 넣었습니다. 실제 보안국가 신청서에 실명·국가명·교회명이 적혀 있다면 ④계명대로 AI 처리에서 빼고 담당자가 직접 입력합니다.

**3. 결과 열어 보기** — 파일 탐색기(Mac은 Finder)에서 `신청서_DB.xlsx`를 더블클릭하거나 "신청서_DB.xlsx 열어줘"라고 합니다. 행이 8개인지, '확인 필요' 열에 무엇이 적혔는지 봅니다.

**4. 원문과 대조하기**
```
무작위로 신청서 3개를 골라, 표의 값과 원본 신청서 내용을 항목별로 대조해줘. 일치/불일치를 표로 보여주고, 불일치가 있으면 원문 문장을 그대로 보여줘. 표는 아직 고치지 마.
```

**5. 형식 점검하기**

## Part 3: 긴 PDF 분석과 인용 검증 (20분)

교진추의 청원서는 **교과서 원문을 정확히 인용할 때** 힘이 생깁니다. 인용 한 글자, 쪽 번호 하나가 틀리면 상대는 그 한 곳을 들어 청원 전체의 신뢰도를 문제 삼을 수 있습니다. 그래서 이 Part의 목적은 분명합니다. **진화론 관련 서술을 쪽수·원문 그대로 빠짐없이 뽑아 청원 논거를 탄탄하게** 만드는 것, 그리고 **인용 대조 검증이 곧 청원서의 신뢰도**라는 것을 몸으로 익히는 것입니다.

🎯 **목표**: 가상 교과서 PDF에서 진화론 관련 서술을 전수 추출하고, 인용문을 글자 그대로 대조 검증한 뒤, 교진추 관점의 청원 논거표 초안을 만듭니다. 서브에이전트와 스캔 글자 읽기(OCR)도 맛봅니다. (교진추 T1 사전질문, 다교연 G10 연결)

🛠 **준비**
- 새 세션, 이름 "5회차 교과서 분석" (신청서 세션과 섞지 않기 — 1업무 1세션)
- **실습 데이터 고르기**: ① 제공된 가상 샘플 `실습자료/05_교과서/` (기본) ② 실제 개정 교과서 PDF 1단원 — 개인정보는 없지만 **PDF 파일 자체는 외부에 공유하지 않습니다.** 처음엔 ①로 흐름을 익히고 실전 과제에서 ②를 권합니다

👣 **단계**

**1. 실습 파일 복사하기**
```
실습자료/05_교과서 폴더를 실습공간/05회차/교과서/로 복사해줘.
```

**2. 연습용 쟁점 코드북 만들기** — 코드북(분류 기준표)이 있어야 AI가 **교진추 기준 그대로** 분류합니다.
```
실습공간/05회차/교과서/쟁점코드북_연습.md 파일을 만들어줘. 교과서의 진화론 관련 서술을 교진추 관점에서 분류할 연습용 코드북이야. 코드마다 '쟁점 이름 / 정의 / 찾을 때 쓸 키워드'를 적어줘.
A 생명의 기원(무기물에서 생명이 저절로 생겨났다는 서술)
B 화석 증거(시조새·말 화석 계열처럼 중간 단계라고 제시하는 서술)
C 상동·흔적 기관, 발생 과정의 유사성을 공통 조상의 증거로 제시하는 서술
D 변이·자연선택을 새로운 종·큰 변화의 근거로 확장하는 서술
E 인류의 진화
F 가설을 확정된 사실처럼 단정하는 표현
Z 기타·확인 필요
```
- 실제 작업에서는 교진추가 1~16차 청원에서 다뤄 온 쟁점(예: 2차 청원의 시조새·말 화석 계열)으로 코드북을 만듭니다.

**3. 전수 추출하기**
```
교과서/가상_중학교과학_생명의진화_발췌.pdf를 처음부터 끝까지 읽고, 진화론 관련 서술을 빠짐없이 표로 뽑아 교과서/추출표.md로 저장해줘.
- 칸: 번호 | 인쇄 쪽 | PDF 쪽 | 위치(본문/그림 캡션/탐구활동/평가문항/읽기자료) | 원문(글자 그대로) | 쟁점 코드(쟁점코드북_연습.md 기준) | 확신도(높음/보통/낮음)
- 원문은 고쳐 쓰거나 요약하지 말고, 띄어쓰기·문장부호까지 그대로
- 키워드(진화, 자연선택, 돌연변이, 공통 조상, 화석, 시조새, 상동 기관, 적응, 생명의 기원 등)로 한 번, 키워드 없이 맥락으로 한 번 찾아서 합쳐줘
- 애매하면 빼지 말고 코드 Z로 넣어줘
마지막에 총 건수와 코드별 건수를 알려줘.
```
- 책에 인쇄된 쪽 번호와 PDF 파일의 쪽 순서는 다를 수 있습니다. 청원서에는 **인쇄 쪽**을 씁니다.

**4. 인용 대조 검증하기** ⭐ 청원서 신뢰도의 핵심
```

```
- Claude가 PDF에서 글자를 꺼내는 도구(파이썬 패키지)를 설치하겠다고 물어보면, 설명을 듣고 승인하세요.
- AI는 인용문을 **자연스럽게 '다듬는' 실수**를 자주 합니다. 그래서 "AI야, 맞게 인용했니?"라고 묻지 않고, **컴퓨터가 글자를 대조**하게 합니다.


**5. 청원 논거표 초안 만들기**
```
인용 검증을 통과한 행만 가지고, 쟁점 코드별로 묶어 교진추 관점의 청원 논거표 초안을 교과서/청원논거표_초안.md로 만들어줘.

- 쟁점마다 예상되는 반론 1개와 그에 대한 답변 방향도 한 줄씩 적어줘
```
- 근거 문헌 칸은 **사람이 실재와 내용을 확인한 문헌만** 채웁니다(10회차 문헌 조사 워크플로우에서 이어집니다).

**6. 서브에이전트 맛보기 — 여러 조수에게 나눠 맡기기**

```
같은 PDF를 소단원별로(소단원 구분이 없으면 쪽 범위로) 2~3묶음 나눠서, 서브에이전트 여러 개에게 동시에 맡겨 3단계와 같은 규칙으로 추출하게 해줘. 결과를 하나로 합친 뒤, 앞에서 만든 추출표.md와 건수·빠진 항목·다른 항목을 비교해줘.
```

**7. 스캔 이미지 글자 읽기 (OCR 맛보기)** — OCR(광학 문자 인식: 사진 속 글자를 텍스트로 바꾸기)
```

- 제목·본문·그림 설명(캡션)·표를 구분해서
- 흐리거나 읽기 어려운 글자는 추측하지 말고 [?]로 표시
```

## Part 4: 추출 결과 검증 체크리스트 (10분)

🧩 **비유** — 은행 창구는 마감 때 '시재'를 맞춥니다. 장부 금액과 금고 현금이 맞아야 퇴근합니다. 추출 결과도 **원본과 맞는지 확인해야 일이 끝납니다.**

**설명** — 어떤 추출이든 이 4가지를 순서대로 점검합니다.

| # | 점검 | 신청서(Part 2)에서는 | 교과서(Part 3)에서는 |
|---|---|---|---|
| 1 | **건수 대조** — 원본 수와 결과 행 수가 맞나 | 신청서 8장 = 표 8행 | 처음 추출과 서브에이전트 추출의 건수 비교 |
| 2 | **무작위 3건 원문 대조** | 3건 항목별 대조 | 인용문 전체는 스크립트로, 3건은 쪽 이미지를 직접 보고 쪽 번호까지 확인 |
| 3 | **빈칸·'확인 필요' 표시** — 모르는 건 모른다고 | '확인 필요' 열 | 코드 Z, 확신도 '낮음' |
| 4 | **추측 금지** — 원문에 없는 값은 채우지 않기 | 지어낸 생년월일·이메일 없음 | 다듬어진 인용, 지어낸 문헌 없음 |

- 2회차에서 배운 "끝나면 스스로 검토하고 **확실/불확실/추측**을 표시해줘"를 함께 쓰면 더 좋습니다.

**짧은 실습**

## 💬 이번 회차 딸깍 프롬프트 카드

**언제 쓰나: 실제 파일을 AI에 주기 전, 개인정보부터 분류할 때**
```
파일은 열지 말고, 내가 적는 항목 이름만 보고 '보낼 것 / 가릴 것(가명·삭제) / 보내지 말 것'으로 분류표를 만들어줘. 항목마다 이유를 한 줄씩 적어줘.
항목: 이름, 휴대폰, 이메일, 생년월일, 주민등록번호, 소속 교회, 사역 국가, 사역 내용, 기도제목
```

**언제 쓰나: 개인정보가 든 파일을 반복 처리해야 할 때 (가짜로 도구 만들기)**
```
실제 파일은 열지 마. 열 이름은 이름, 연락처, 이메일, 소속, 사역국가야. 이 열 이름으로 가짜 데이터 5줄짜리 샘플을 만들고, 그 샘플로 빈칸과 형식 오류를 점검하는 파이썬 스크립트를 짜줘. 실행하면 화면에는 처리 건수·빈칸 수·오류 수만 출력하고, 사람 이름이나 연락처는 절대 출력하지 않게 해.
```

**언제 쓰나: 여러 문서에서 같은 항목을 뽑아 표로 만들 때**
```
이 폴더의 문서마다 (뽑을 항목)을 뽑아 1문서 1행 엑셀 표로 만들어줘. 맨 앞 열은 파일 이름, 원문에 없는 값은 지어내지 말고 빈칸 + '확인 필요' 열에 이유를 적어줘.
```

**언제 쓰나: PDF에서 원문 그대로 인용을 뽑을 때**
```
이 PDF에서 (찾을 주제) 관련 서술을 빠짐없이 뽑아 표로 만들어줘. 칸: 인쇄 쪽 | PDF 쪽 | 위치(본문/캡션/활동/평가) | 원문(글자 그대로, 요약·수정 금지). 애매하면 빼지 말고 '확인 필요'로.
```

**언제 쓰나: 뽑은 인용문이 원문과 똑같은지 확인할 때**
```
표의 '원문' 칸을 하나하나 원본 글자와 스크립트로 대조해줘(공백·줄바꿈만 무시). 못 찾은 행과 쪽 번호가 다른 행만 보여주고, 표는 고치지 마.
```

**언제 쓰나: 스캔 이미지·사진 속 글자를 옮길 때**
```
이 이미지의 글자를 원문 그대로 마크다운으로 옮겨줘. 번역하지 말고, 제목·본문·캡션·표를 구분하고, 읽기 어려운 글자는 추측하지 말고 [?]로 표시해줘.
```

## 📌 오늘의 요약

- AI가 읽은 것은 서버로 간 것입니다. **학습 안 함 ≠ 저장 안 함 ≠ 전송 안 함.**
- 5계명: 필요한 것만 / 가명·익명 먼저 / 민감정보 0 / 보안국가 선교사 정보는 AI 제외 / 결과물 위치 관리.
- 보안은 부탁이 아니라 **설정과 설계** — 가짜로 도구를 만들고, 진짜는 내 PC에서, AI엔 건수만.
- 추출은 **원문 그대로**, 검증은 **컴퓨터가 글자 대조**. 인용 검증이 곧 청원서의 신뢰도입니다.
- 모든 추출은 건수 대조 → 무작위 3건 대조 → '확인 필요' 표시 → 추측 금지로 마무리합니다.

### 수준별 설명 가이드

- 🌱 **입문(폰 AI만 써 봄)**
  - 학습/저장/전송 = "공부 자료로 쓰기 / 서랍에 보관 / 택배로 보내기". 택배는 이미 보낸 뒤에는 못 돌린다는 점만 잡아 주세요.
  - 스크립트 = "Claude가 만들어 준 작은 자동 처리 기계". Part 2 6단계는 "나중에 실제 파일에는 이 기계만 돌린다"만 이해하면 충분합니다.
  - Read 거부 규칙, 두 겹 탐지(키워드+맥락)는 생략. 서브에이전트는 "조수 여러 명" 비유만.
- 🌿 **기초(PC로 AI·엑셀 업무 익숙)**
  - 코딩 없이 엑셀로 하는 가명처리 순서를 알려 주세요: ① 원본 복사해 'AI용' 파일 ② 주민번호·계좌·주소 열 삭제 ③ 맨 앞에 ID 열(`="D"&TEXT(ROW()-1,"0000")`) 만든 뒤 **값으로 붙여넣기** ④ 'ID+이름+연락처'만 따로 **대응표 파일**로 저장하고 암호 설정 ⑤ AI용 파일에서 이름·연락처 열 삭제.
  - 원본 폴더를 작업 폴더 밖에 두는 이유(폴더 밖을 읽기 전에 Claude가 묻는다)를 실제로 보여 줘도 좋습니다.
- 🌳 **중급(자동화·코딩 경험 있음)**
  - Read 거부 규칙과 그 한계(스크립트가 직접 여는 파일은 막지 않음 → OS 수준 차단은 별도 장치 필요).
  - `.hwpx`는 압축된 XML이라 스크립트로 읽기 비교적 쉽고, 구형 `.hwp`는 변환 후 처리가 무난하다는 점.
  - 인용 검증 스크립트 코드를 직접 읽어 보게 하고, 정규화 규칙(공백·줄바꿈·따옴표)을 어디까지 허용할지 스스로 정하게 하세요.
  - 대량(교과서 수십 권)은 전용 OCR·문서 변환 도구로 1차 변환 후 Claude가 정리·검수하는 편이 사용량 면에서 유리합니다. 서브에이전트 정의 파일(`.claude/agents/`)은 8회차 예고로만.

### 퀴즈 정답과 해설

1. **X** — 팀 플랜이 막는 것은 '학습'입니다. 읽는 순간 **전송**은 일어나고, 일정 기간(보통 30일) 서버에 **저장**됩니다.
2. **②** — 읽는 순간 이미 전송되고, AI는 지시를 100% 따르는 장치가 아닙니다. ①③④는 설정·설계로 보낼 것 자체를 줄이는 방법입니다.
3. **③** — 보안국가 선교사 정보는 '가명처리 대상'이 아니라 **'AI 제외 대상'**입니다. 이름을 바꿔도 국가·사역 분야·나이대가 쌓이면 식별될 수 있고, 신원 노출은 안전 문제와 직결됩니다.
4. **화면 출력도 대화에 들어가 AI(서버)로 전달**되기 때문입니다. 이름을 출력하면 원본을 읽히지 않으려던 설계가 무의미해집니다. (힌트: "Claude는 화면에 나온 결과를 어떻게 알게 될까요?")
5. **스크립트(컴퓨터)로 원문 글자와 하나하나 대조**하고, 쪽 번호는 쪽 이미지로 확인합니다. AI는 인용을 다듬는 실수를 자주 하고, 청원서의 인용이 한 곳이라도 틀리면 상대가 그 한 곳으로 청원 전체의 신뢰도를 공격할 수 있습니다. 정확한 인용이 곧 청원 논거의 힘입니다.
- 소크라테스식 진행: 정답 전에 힌트부터. 3번은 "이름만 바꿨는데 '중앙아시아 ○○국, 50대, 교사 출신'이 남아 있다면?"으로 유도.

- **공통**: 실제 파일 사용 시 개인정보 분류표가 **먼저** 있는가 / 검증 체크리스트 4가지를 거쳤는가 / 원문에 없는 값을 채우지 않았는가.

- **다교연**: 쪽 파일 머리말에 교과서명·학년·인쇄 쪽·PDF 쪽이 있는가, 원본 이미지와 대조 후 표시했는가, [?] 표시가 남아 있다면 사람이 확인했는가.
