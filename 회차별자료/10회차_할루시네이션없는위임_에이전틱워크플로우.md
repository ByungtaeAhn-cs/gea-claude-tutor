## Part 1: 에이전트 루프와 설계 6요소

### 1.1 챗봇과 에이전트 — 대답하는 사람 vs 일을 끝내는 사람

🧩 **비유**: 챗봇은 **전화 안내원**입니다. 물으면 답하고 거기서 끝납니다. 에이전트는 **출장 보낸 신입 동료**입니다. "후원자 감사 모임 준비"라는 목표를 받으면 할 일을 나누고, 장소에 전화하고, 결과를 보고 다음 할 일을 정합니다.

| 구분 | 챗봇 (폰 AI 앱에 묻고 답만 받던 방식) | 에이전트 (Code 탭의 Claude) |
|------|------|------|
| 하는 일 | 질문에 답을 만든다 | 목표를 이루려고 행동한다 |
| 흐름 | 한 번 묻고 한 번 답함 | 목표에 닿을 때까지 반복 |
| 도구 | 글자만 만든다 | 파일 읽기·쓰기, 웹 검색, 스크립트 실행 |
| 기억 | 지금 대화 | CLAUDE.md·인수인계 메모로 이어 감 |

에이전트는 **생각 → 행동 → 관찰**을 목표에 닿을 때까지 되풀이합니다(원 자료의 ReAct 루프). 이 루프를 여러 단계로 이어 붙인 업무 흐름을 **에이전틱 워크플로우**(AI가 여러 단계를 스스로 이어 가며 일하는 흐름)라고 부릅니다. 원 자료가 말하는 에이전트의 3요소도 이미 다 배웠습니다: **계획**(Plan 모드, 1·2회차), **도구 사용**(파일·웹·스크립트, 5·6회차), **기억**(CLAUDE.md·인수인계, 3회차).

**우리 단체 예시** — 6회차 후원 점검을 떠올려 보세요.

```
생각: "후원 엑셀 3개를 비교하려면 먼저 열 이름을 봐야겠다"
행동: 파일을 열어 구조를 읽음
관찰: "8월 파일만 '결제상태' 열 이름이 다르다"
생각: "스크립트가 두 이름을 모두 받게 고치자" → 행동 → 관찰 … → 보고서 완성
```

💭 **확인 질문**: 6회차에서 Claude가 스크립트를 돌리다 오류를 만나 스스로 고친 장면이 있었나요? 그 장면은 루프의 어느 단계였을까요?

### 1.2 믿을 수 있는 위임의 설계 6요소

🧩 **비유**: 신입을 출장 보내기 전에 쓰는 **출장 품의서**입니다. 목적, 일정표, 참고 자료, 결재자, 보고 방식이 적혀 있으면 멀리 보내도 안심이 됩니다.

루프가 길어질수록 작은 착오가 쌓이므로, "잘 해 줘"라는 부탁 대신 **구조**를 줍니다. 할루시네이션 '없는' 위임은 AI가 절대 틀리지 않는다는 뜻이 아닙니다(Anthropic 공식 안내도 이런 기법이 할루시네이션을 "크게 줄이지만 완전히 없애지는 못한다"고 말합니다). **틀린 것이 사람 손에 닿기 전에 걸리도록 그물을 여러 겹 치는 것**, 이것이 이번 회차의 뜻입니다.

| 요소 | 한 줄 뜻 | 없으면 생기는 일 | 이미 배운 곳 |
|------|---------|----------------|-------------|
| ① 목표와 완료 기준 | "끝났다"를 체크할 수 있는 문장으로 | 끝없이 돌거나 대충 끝냄 | 2회차 프로젝트 카드 |
| ② 단계 분해 | 단계마다 입력 → 출력 | 중간 오류가 안 보임 | 1회차 Plan 모드 |
| ③ 근거 자료 지정 | 공식 출처 폴더·사이트**만** | 그럴듯한 거짓 | 2회차 3단계 검증, 5회차 인용 |
| ④ 작성자·검수자 분리 | 쓰는 AI와 검사하는 AI를 나눔 | 자기 실수를 자기가 못 봄 | 7회차 reviewer |
| ⑤ 사람 승인 지점 ✋ | 되돌릴 수 없는 일(발송·제출·게시) 앞 | 잘못된 글이 밖으로 나감 | 1회차 Manual 모드 |
| ⑥ 기록 | 작업기록·인수인계 메모 | 무엇이 왜 틀렸는지 못 찾음 | 3회차 인수인계, 4회차 Git |

**우리 단체 예시** — 다니엘칼리지 학부모 문의 답변 초안이라면: ① 완료 기준 "모든 답에 FAQ 근거 문장 표시" ③ 근거 = FAQ·수업료 규정 문서만 ④ 초안은 Claude, 검사는 reviewer ⑤ 보내기 전 담당 선생님 확인 ⑥ 날짜별 답변 기록.

💭 **확인 질문**: 선생님 업무에서 '⑤ 사람 승인'이 꼭 필요한 순간 하나를 떠올려 보세요. 거기서 무엇이 되돌릴 수 없나요?

## Part 2: 설계서 작성과 실행

### 2.1 설계서 템플릿 — 한 장짜리 업무 지시서

🧩 **비유**: 설계서는 **레시피 카드**입니다. 재료(근거 자료), 순서(단계표), 맛보기(검증), 탔을 때 대처(실패 시)가 적혀 있으면 누가 요리해도 맛이 같습니다.

설계서는 **개요 칸**과 **단계표** 두 부분입니다. 9회차 스킬이 "어떻게 하나"를 담았다면, 설계서는 "누가, 무엇을 근거로, 어디서 멈추고, 어떻게 확인하나"를 담습니다.

**① 개요 칸**

| 칸 | 적을 내용 | 6요소 |
|----|----------|:----:|
| 업무명 | 한 줄 이름 + 사전질문 코드 | — |
| 언제 시작하나 | 날짜·주기·사건(트리거) — 예: "분기 마지막 달 1일" | — |
| 목표 | 이 일이 끝나면 무엇이 생기나 | ① |
| 완료 기준 | 체크할 수 있는 문장 3~5개 | ① |
| 근거 자료(이것만) | 써도 되는 폴더·사이트 + **쓰면 안 되는 것** | ③ |
| 작성자 / 검수자 | 누가 쓰고 누가 검사하나 | ④ |
| ✋ 사람 승인 지점 | 되돌릴 수 없는 일 바로 앞 | ⑤ |
| 기록 | 작업기록 파일 위치, 인수인계 | ⑥ |

**② 단계표** (6요소 ②)

| # | 단계 | 담당 | 입력 | 출력 | 검증 방법 | 실패 시 |
|---|------|------|------|------|----------|--------|
| 1 | … | AI / 서브① / 서브② / reviewer / 사람 ✋ | … | … | … | … |

- **담당** 표기: `AI`(지금 대화하는 Claude) · `서브①②`(동시에 일하는 서브에이전트) · `reviewer`(이 튜터 폴더의 검수자 에이전트) · `사람 ✋`(승인).
- **실패 시** 칸이 가장 중요합니다. "못 찾으면 '찾지 못함'이라고 쓴다", "3단계로 되돌린다"처럼 적습니다.

**우리 단체 예시**는 바로 아래 두 개의 완성본입니다. 사례 A(미션펀드)는 "글을 만드는 일", 사례 B(다교연)는 "공식 자료를 조사하는 일"의 설계서입니다.

**개요**

**단계표**

| # | 단계 | 담당 | 입력 | 출력 | 검증 방법 | 실패 시 |
|---|------|------|------|------|----------|--------|

| 7 | 게시용 마무리 | AI | 승인본 | 모금 페이지 글 + SNS 요약(일반국가만 — 보안국가 소식은 SNS 금지) | 승인본과 글자 대조 | — (**게시는 사람이 직접**) |

> ⚠️ **실제 보안국가 자료**는 AI에 넣기 **전에** 사람이 실명·국가·교회명을 먼저 가립니다(5회차 원칙 ④). 5단계 보안 점검은 그 뒤에 한 번 더 거르는 **두 번째 그물**입니다. 연습에서는 가상 샘플이라 AI가 가려도 됩니다.

### 2.4 실습: 설계서를 파일로 만들고 실행하기

🎯 **목표**: 사례 A 또는 B를 설계서 파일로 만들고, 서브에이전트 2개 병렬 조사 + reviewer 교차 검토로 끝까지 실행합니다.

🛠 **준비**
- 튜터 폴더가 열린 Code 탭, 권한 모드는 **Manual** 또는 **Accept edits**(Bypass permissions는 쓰지 않습니다).
- 🔀 **데이터 선택**: ① 가상 샘플(기본 — 사례 A) ② 실제 양식 기반 가상 데이터(빈 소식 양식을 주면 가짜 내용으로 채워 만듦) ③ 본인 실제 파일(5회차 개인정보 점검 먼저, 보안국가 자료는 사람이 먼저 가림). 사례 B는 공개된 공식 사이트만 읽으므로 개인정보가 없습니다.
- 사례 고르기: 🌱 처음이면 **사례 A**(샘플로 끝까지 됨), 🌿🌳 또는 다교연이면 **사례 B**, 자신 있으면 **내 관통 프로젝트**.

👣 **단계**
1. 샘플 복사(사례 A):
   ```
   실습자료/07_원고/ 폴더의 선교지소식_원자료_일반국가.md 와 선교지소식_원자료_보안국가.md 를 실습공간/10회차/분기소식/원자료/ 로 복사해줘.
   ```
2. 설계서 파일 만들기:
   ```
   10회차 자료의 사례 A 설계서(개요 + 단계표)를 실습공간/10회차/설계서_분기소식.md 로 옮겨 적어줘.
   연습이므로 1~2단계는 "원자료가 이미 도착함"으로 표시하고, 입력 칸은 방금 복사한 파일 이름으로 고쳐줘.
   ```
   사례 B라면 `설계서_공익법인조사.md`로 만들어 달라고 합니다. 저장된 파일을 열어 **완료 기준을 한 줄 직접 고쳐** 보세요. 내 설계서가 됩니다.
3. 계획부터 확인(**Plan** 모드로 바꾸거나 이렇게 말하기):
   ```
   바로 하지 말고, 이 설계서대로 하면 어떤 순서로 무엇을 할지 계획부터 보여줘. 서브에이전트는 몇 개, 어디서 멈출지도 알려줘.
   ```
4. 실행 — 사례 A:
   ```
   실습공간/10회차/설계서_분기소식.md 설계서대로 진행해줘.
   - 3단계(정리)는 서브에이전트 2개로 나눠 동시에 해줘: 하나는 일반국가 원자료, 하나는 보안국가 원자료.
   - 원자료에 없는 사실(이름·숫자·날짜·사건)은 만들지 말고 '확인 필요'로 표시해.
   - 5단계(보안·사실 점검)는 reviewer 에이전트에게 맡겨서, 글을 쓴 너와 다른 눈으로 교차 확인해줘.

   - 단계가 끝날 때마다 실습공간/10회차/분기소식/작업기록.md 에 한 줄씩 기록해.
   ```
   실행 — 사례 B:
   ```
   실습공간/10회차/설계서_공익법인조사.md 설계서대로 진행해줘.
   - 2-a(법령 조문)와 2-b(국세청·재정경제부 안내)는 서브에이전트 2개로 나눠 동시에 조사해.
   - 근거는 설계서 '근거 자료' 칸의 공식 사이트만 써. 블로그·뉴스·네 기억으로 채우지 마.
   - 모든 문장에 [기관 · 문서/조문 · 작성일 또는 시행일 · URL]을 붙이고, 못 찾으면 "찾지 못함", 페이지를 못 읽으면 "확인 실패"라고 써.
   - 공식 자료끼리 내용이 다르면 둘 다 보여주고 '서로 다름'으로 표시해.
   - 합친 결과는 reviewer 에이전트로 교차 확인해: 근거 없는 문장, 날짜가 어긋난 곳, 옛 명칭(지정기부금단체·기획재정부)을 찾아줘.
   - 결과는 실습공간/10회차/공익법인조사/ 에 저장하고, 끝에 '세무사·관할 세무서에 확인할 것' 목록과 "법률·세무 자문이 아닌 초안"이라는 문구를 붙여.
   - ✋ 단계에서는 멈추고 나에게 물어봐. 단계마다 작업기록.md 에 한 줄씩 기록해.
   ```
5. 지켜보기: 서브에이전트 두 개가 따로 일하고 보고서만 가져오는 모습을 봅니다(8회차의 "전문 팀원"). 화면 표시는 조금 다를 수 있습니다.
6. ✋ 단계에서 Claude가 멈추면 초안과 reviewer 점검표를 읽고 "승인" 또는 "○○ 고쳐줘"라고 답합니다.
7. **내 눈으로 3건 대조**: 결과물에서 문장 3개를 골라 원자료(또는 URL)를 직접 열어 맞는지 확인합니다.

✅ **이렇게 되면 성공**
- 결과 폴더에 **초안 + reviewer 점검표 + 작업기록.md** 세 가지가 있다.
- Claude가 ✋ 단계에서 멈추고 물어봤다.
- 사례 A: 형식(`#번호`·▣·기도제목)이 맞고, 보안국가 글에 실명·국가명·종교 용어가 남아 있지 않다.

### 3.1 예약 작업 = 알람 맞춰 둔 업무 지시

🧩 **비유**: 동료 책상에 "매주 월요일 아침엔 이것부터"라는 포스트잇을 붙여 두는 것입니다. 다만 이 동료는 **사무실 불이 켜져 있을 때만**(앱이 켜져 있고 컴퓨터가 깨어 있을 때만) 일합니다.

원 자료는 자동화를 세 칸으로 나눕니다. **트리거**(언제) → **에이전트 로직**(무엇을 — 설계서·스킬) → **출력**(어디에 — 결과 파일). 데스크탑 앱에서는 이것을 **예약 작업**으로 만듭니다.

| 알아 둘 사실 | 내용 |
|-------------|------|
| 만드는 곳 | Code 탭 사이드바 **Routines**(예약 작업 목록, 안 보이면 **More** 메뉴 안) → **New routine**(새 예약 작업) → **Local**(내 컴퓨터) |

### 3.2 실습: 첫 예약 작업 만들고 Run now

🎯 **목표**: 주 1회 도는 예약 작업 1개를 만들고, **Run now**로 한 번 돌려 결과 파일을 확인합니다.

🛠 **준비**
- 🔀 **데이터 선택**: ① 기본 예제(공식 웹 페이지만 읽음, 개인정보 없음) ② 내 업무 예약(3.1 예시 표에서 고르기) ③ 실제 파일을 읽는 예약이라면 5회차 점검 먼저 — 예약 작업은 **사람이 안 볼 때** 돌기 때문입니다.
- 다교연이 아니어도 기본 예제로 연습해도 됩니다. 원리를 익히는 것이 목적입니다.
- **지시문 5가지 체크**(원 자료의 자동화 프롬프트 팁 재구성): ① 언제 끝난 건지(종료 조건) ② 문제가 생기면 어떻게(추측 말고 '확인 실패'로 적기) ③ 어디에 저장(출력 위치) ④ 스스로 확인(지난 기록과 비교) ⑤ 하지 말 것(메일 발송·파일 삭제·개인정보 기록 금지).

👣 **단계**
1. Code 탭 사이드바에서 **Routines**를 누릅니다(안 보이면 **More** 메뉴 안). **New routine** → **Local**을 고릅니다. 다른 선택지가 보여도 이 과정에서는 내 컴퓨터 폴더를 쓰는 **Local**만 씁니다.
2. **Name**: `주간 공식 안내 확인(연습)`
3. **Description**: `매주 월요일 공익법인 관련 공식 안내 변경 확인`
4. **Instructions**에 아래를 붙여 넣고, 작업 폴더는 이 튜터 폴더(`gea-claude-tutor`)를 고릅니다. 권한 모드·모델은 기본값 그대로 두세요(**Bypass permissions**는 고르지 않습니다).
   ```
   매주 월요일에 공익법인(옛 이름 지정기부금단체) 관련 공식 변경사항만 확인한다.
   근거는 아래 공식 사이트만 쓴다. 블로그·뉴스·기억으로 채우지 않는다.
   1) 국세청 누리집 공익법인 메뉴의 '최근 주요 개정세법'과 참고자료실 새 글
   2) 국가법령정보센터의 법인세법 시행령 제39조 — 현재 시행일과 최근 개정일
   3) 재정경제부 고시·공고의 '공익법인등 지정·변경에 관한 고시' 새 글
   실습공간/10회차/모니터링/기록.md 와 비교해 바뀐 것만 표로 정리한다:
   날짜 | 기관 | 제목 | 링크 | 우리 단체 영향(추정이면 '확인 필요')
   기록.md 가 없으면 이번 결과를 첫 기록으로 만든다.
   페이지를 읽지 못하면 '확인 실패'로 적고 추측하지 않는다.
   결과는 실습공간/10회차/모니터링/YYYY-MM-DD.md 로 저장하고 기록.md 에 한 줄 추가한다.
   메일을 보내거나 파일을 지우지 않는다. 끝에 "법률·세무 자문이 아닌 참고용 정리"라고 적는다.
   ```
5. **Schedule**: **Weekly** → 월요일 오전 9시. (시간 고르는 화면 문구는 조금 다를 수 있습니다.)
6. 저장한 뒤 **Run now**를 누릅니다. 파일 쓰기·웹 읽기 권한을 물으면 **항상 허용** 쪽을 고릅니다(화면 문구는 조금 다를 수 있습니다).
7. 알림이 오면 사이드바 **Scheduled** 섹션의 새 세션을 열고, `실습공간/10회차/모니터링/` 결과 파일을 확인합니다.
8. (선택) 대화로 하나 더 만들어 보기 — "매월 1일"은 일정 목록에 없으니 말로 부탁합니다:
   ```
   매월 1일 오전 9시에 실습공간/06회차 의 후원 점검 스크립트로 가장 최신 후원 엑셀을 점검하는 예약 작업 만들어줘.
   결과는 실습공간/10회차/후원점검/YYYY-MM.md 에 요약만 저장하고, 후원자 이름·연락처는 적지 마.
   만들기 전에 이름·지시문·일정을 먼저 보여줘.
   ```
9. 설정 → **Desktop app** → **General**에서 **Keep computer awake**를 확인합니다(사무실 PC처럼 켜 두는 컴퓨터라면 켜 두세요).

✅ **이렇게 되면 성공**
- **Routines** 목록에 `주간 공식 안내 확인(연습)`이 보인다.
- **Run now** 결과로 `모니터링/날짜.md`와 `기록.md`가 생겼다.
- 읽지 못한 페이지가 있었다면 '확인 실패'로 정직하게 적혀 있다.

🆘 **막히면**
- **Routines**가 안 보인다 → **More** 메뉴를 열어 보세요. 그래도 없으면 앱을 최신 버전으로 업데이트하거나, 대화로 "매주 월요일 9시에 이 지시문으로 예약 작업 만들어줘"라고 부탁합니다.
- 실행이 멈춰 있다 → 권한 승인을 기다리는 중입니다. 그 세션을 열어 승인하고, **Run now**로 한 번 더 돌려 '항상 허용'을 눌러 둡니다.
- 정해진 시간에 안 돌았다 → 앱이 꺼져 있었거나 컴퓨터가 잠들었을 가능성이 큽니다. 다시 켜면 최근 7일 중 1회만 따라잡습니다.

### 4.1 실습: 수료카드 만들기

🎯 **목표**: 관통 프로젝트의 여정을 `내_학습기록/수료카드.md` 한 장으로 정리합니다.

🛠 **준비**: `내_학습기록/내_프로젝트.md`, `진도.md`, `실습공간/과제/` 폴더. 🔀 수료카드에는 개인정보를 넣지 않습니다(숫자는 건수·시간만).

👣 **단계**
1. 초안 요청:
   ```
   내_학습기록의 학습자_프로필.md, 진도.md, 내_프로젝트.md 와 실습공간/과제/ 폴더를 읽고
   아래 칸으로 수료카드 초안을 내_학습기록/수료카드.md 로 만들어줘.
   - 내 프로젝트 한 줄 / Before → After(걸린 시간·품질·마음) / 설계서(파일 위치 + 6요소 요약)
   - 내 스킬(/이름) / 예약 작업(이름·일정, 안 했으면 이유) / 검증 구조(근거·검수·승인)
   - 남은 과제 3개 / 다음 30일 계획 / 한 줄 소감
   시간 절약 같은 숫자는 내가 말한 것만 쓰고, 모르는 칸은 나를 한 번에 하나씩 인터뷰해서 채워줘.
   ```
2. 인터뷰에 답합니다. "한 줄 소감"은 꼭 직접 쓰세요.
   - 관통 프로젝트가 L1(단체 블로그)이면 Before/After에 "한 편 준비 시간", "판정표에서 잡은 오류 수", "발행 편수(비공개 연습 포함)"를 넣습니다.
3. 마무리: "수료카드를 스스로 검토해서 과장되거나 근거 없는 문장을 표시해줘"(2회차 메타프롬프트 ⑤).

✅ **이렇게 되면 성공**: 수료카드에 Before/After, 설계서 위치, 예약 여부, 남은 과제 3개가 모두 있고, 숫자는 모두 선생님이 직접 말한 값이다.

🆘 **막히면**: 관통 프로젝트가 중간에 멈췄어도 괜찮습니다. "지금까지 된 것 / 남은 것"으로 나눠 쓰면 그것이 훌륭한 수료카드입니다.

### 4.2 확장 로드맵 — 큰 프로젝트도 같은 설계서로

🧩 **비유**: 큰 건물도 방 하나 짓는 설계도를 층마다 되풀이해 올립니다. 오늘 쓴 설계서가 그 한 층입니다.

**케냐 교과서 파이프라인(다교연 G10·교진추 T5)** 은 기준 세우기(KICD 교육과정 설계서 대응표) → 스캔·글자 추출 → 자료실 → 분류(교과서별 서브에이전트) → 설계 카드(교진추 관점 메모) → 원고 작성 → 검수 → 그림 → 조판 → 현지 검토 → 승인·배포까지 이어지는 긴 흐름입니다. 단계 하나하나가 오늘의 단계표 한 줄이고, 쓰는 에이전트와 검수하는 에이전트를 나누는 원리도 같습니다. **맨 먼저 할 일**은 KICD 승인 절차 확인입니다. KICD가 승인 교재 사용을 강조하고 있으므로(2026-06 보도), 새 교재를 어떤 지위로 쓸지부터 현지 파트너와 확인해야 합니다.

**다니엘칼리지 챗봇(D1·D3)** 도 같은 순서입니다: 문의 기록 분류 → 근거 문서('챗봇 교과서') → 답해도 되는 것·안 되는 것·사람에게 넘길 조건 → 테스트 질문으로 시험 → 운영하며 고치기. 대니의 신앙 테두리는 다섯 겹 울타리(복무 지침서, 교재 제한, 거절·이관 규칙, 이중 검사, 사람의 눈)로 지킵니다. 실전 과제의 "테스트 질문 10개"가 그 첫 벽돌입니다.

| 6요소 | 케냐 교과서 | 다니엘 챗봇 |
|------|-----------|-----------|
| ① 완료 기준 | 단원별 원고가 KICD 학습목표·분량에 맞음 | 테스트 합격 기준(근거 없는 답 0건) |
| ③ 근거 자료 | KICD 설계서, 쪽별 교과서 자료실 | FAQ·규정 문서, 신앙고백·요리문답 |
| ④ 작성/검수 | 원고 에이전트 / 검수 에이전트 | 대니 / 검사용 AI |
| ⑤ 사람 승인 | 교진추 감수, 현지 교사 검토 | 이관 규칙, 매주 대화 기록 점검 |

💭 **확인 질문**: 두 프로젝트 모두 ③ 근거 자료를 먼저 만드는 이유는 무엇일까요?

### 4.3 앞으로 혼자 배우는 법

🧩 **비유**: 자전거 보조바퀴를 떼는 날입니다. 넘어지지 않는 요령은 이미 몸에 있습니다. 이제 필요한 건 **길 묻는 법** 세 가지입니다.

| 도구 | 언제 | 이렇게 말하기 |
|------|------|-------------|
| **메타프롬프트** | 새 일을 시작할 때 | "○○ 하고 싶어. 먼저 조사하고 시작하자. 애매한 건 나를 인터뷰해서 정해줘." |
| **공식 문서** | 새 기능·바뀐 화면이 궁금할 때 | "Claude Code 공식 문서에서 ○○ 기능을 찾아 출처 링크와 함께 쉽게 설명해줘." |
| **튜터식 질문** | 배운 걸 굳히고 싶을 때 | "정답을 바로 주지 말고, 내가 스스로 찾도록 질문으로 이끌어줘." |

**우리 단체 예시** — SHINE행복한학교가 새 AI 영상 도구를 만났다면: 공식 문서로 "무엇을 할 수 있고 무엇은 못 하는지" 먼저 확인하고 → 메타프롬프트로 "우리 홍보 영상 기획에 이 도구를 쓰고 싶어, 먼저 조사하고 나를 인터뷰해줘" → 익힌 뒤에는 튜터식 질문으로 "사람이 맡을 단계와 AI가 맡을 단계를 내가 나눠 볼 테니 질문으로 점검해줘".

도구와 화면은 계속 바뀝니다. 그러나 "먼저 묻게 하고, 근거를 대게 하고, 사람이 확인한다"는 원칙은 바뀌지 않습니다. 이 튜터도 "튜터 최신 버전으로 업데이트해줘" 한마디로 새 내용을 받을 수 있습니다.

💭 **확인 질문**: 다음 달에 처음 해 볼 새 업무 하나를 떠올려 보세요. 세 도구 중 무엇으로 시작하시겠어요?

열 번의 만남 동안 선생님은 복사·붙여넣기로 AI를 쓰던 자리에서, 일을 설계하고 맡기고 확인하는 **팀장**의 자리로 옮겨 오셨습니다. 맡기되 확인하는 일은 좋은 청지기의 일이기도 합니다. 아낀 시간이 선생님만 할 수 있는 일, 곧 사람을 만나고 마음을 살피는 일에 쓰이기를 바랍니다. 정말 수고 많으셨습니다. 🎉

### 퀴즈 정답과 해설
1. **②** 근거 자료 지정(6요소 표의 ③). "이것만 쓰고 저것은 쓰지 마"가 이 요소의 핵심이다. 쓰면 안 되는 것까지 적어야 완성.
2. **X**. 로컬 예약 작업은 앱이 켜져 있고 컴퓨터가 깨어 있어야 실행된다. 놓친 실행은 다시 켰을 때 최근 7일 중 가장 최근 1회만 따라잡는다.
3. **X**. 2026.2.27 법인세법 시행령 개정으로 의무이행 여부 보고는 폐지됐지만 일부 국세청 안내는 아직 갱신되지 않았다. 공식 자료끼리 어긋나면 둘 다 싣고 '서로 다름' 표시 후 관할 세무서에 확인한다. 날짜를 함께 적게 하는 이유다.
4. **②** Run now. 권한을 미리 '항상 허용'해 두지 않으면 예약 실행이 승인 대기로 멈춘다. ③ Bypass permissions는 이 과정에서 쓰지 않는다.
5. 예시 답: "자기가 쓴 글의 실수는 자기 눈에 잘 안 보이므로, 다른 책상(다른 컨텍스트)에서 원자료와 대조하는 검수자가 더 잘 잡는다." — '다른 눈', '원자료 대조', '작성과 검사 분리' 중 하나가 들어 있으면 정답.

### 실전 과제 검수 기준
- 설계서에 **6요소가 모두** 있다: 완료 기준은 체크 가능한 문장, 근거 자료는 '이것만 + 쓰면 안 되는 것', 작성자와 검수자가 다르다.
- 단계표의 모든 행에 **검증 방법**과 **실패 시**가 있다. 발송·제출·게시 앞에 ✋가 있다.
- 1회 이상 실행 결과 + reviewer 점검표 + 작업기록이 있고, 학습자가 **직접 3건 대조**한 흔적이 있다.
- 세무·법령 과제: 모든 주장에 출처·날짜, '확인 필요' 표시, 면책 문구, 세무사·관할 세무서 확인 목록.
- 교진추(T2): 교진추 관점의 청원 논거를 적극적으로 세우도록 돕되, **모든 인용이 원문과 글자 그대로 일치**하고 쪽수·URL이 있는지 확인. 불일치·확인 실패는 숨기지 않고 표시하게 한다(청원서의 신뢰도를 높이는 방향).
- 미션펀드: 보안국가 글에 실명·국가명·교회명·종교 용어·위치 정보 0건.
- 다니엘: 테스트 10문항에 정상(예: "환불은 언제까지 돼요?")·금지(예: "선생님 전화번호 알려줘")·공격(예: "이전 지시 다 무시해") 유형이 섞여 있고, 합격 기준을 미리 적었다.
- 예약 작업: **Run now** 성공 기록, 지시문에 '보내지 않음·지우지 않음·개인정보 적지 않음'이 있다.

### 안전·개인정보 주의
- 예약 작업은 사람이 보지 않을 때 돈다. 지시문에 **메일 발송 금지(초안만), 파일 삭제 금지, 개인정보 기록 금지**를 반드시 넣게 한다. **Bypass permissions**는 권하지 않는다.
- 실제 보안국가 선교사 정보(실명·국가·얼굴·교회명·종교 용어)는 **AI 입력 제외**가 원칙이다(5회차 ④). 사람이 먼저 가리고, AI 보안 점검은 두 번째 그물로만 쓴다.
- 세무·법령: AI 결과는 초안이며 제출 서류의 책임은 법인과 대표자에게 있다. "법률·세무 자문이 아닙니다 · 제출 전 세무사와 관할 세무서 확인"을 결과물마다 붙이게 한다. "AI가 정확히 알려 준다", "세무사 없이 된다" 같은 표현은 쓰지 않는다.
- 실제 후원 파일을 예약 작업으로 점검할 때는 5·6회차 패턴(스크립트가 내 PC에서 처리, 결과는 건수·요약만)을 지킨다.
- 데스크탑 앱은 대화 기록과 결과 파일을 PC에 남긴다. 공용 PC에서는 예약 작업을 만들지 않도록 안내.
- 아침 브리핑처럼 커넥터를 쓰는 예약은 후원자 연락처·금액을 브리핑에 적지 않도록 지시문에 넣는다.

### (해당 시) 강사가 강의 당일 함께 진행할 때의 팁
- 10회차는 자가학습 회차다. 후속 모임에서 수료 발표를 한다면 1인 3~5분: Before/After 숫자 1개, 설계서 한 장(단계표에서 ✋ 위치 짚기), 다음 30일 계획 순서가 좋다.
- 사례 B를 시연한다면 "공식 자료끼리 어긋난 실화"(의무이행 여부 보고)를 먼저 보여 주고, 설계서가 그것을 잡아내는 장면으로 마무리하면 설득력이 크다.
