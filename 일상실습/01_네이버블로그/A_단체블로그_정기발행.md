# 유형 A: 단체 블로그 정기 발행 — 조사부터 임시저장까지, 우리 블로그 편집국 꾸리기

> 블로그 한 편은 조사하는 사람, 쓰는 사람, 확인하는 사람, 올리는 사람이 함께 만듭니다.
> 이 실습에서 신입 동료 Claude는 앞의 세 사람 몫을 배우고, 마지막 '발행' 버튼은 늘 선생님이 누릅니다.

## 🗺️ 전체 그림

### 한 편이 만들어지는 길

🧩 **비유**: 작은 **편집국**을 꾸린다고 생각해 보세요. 취재 기자가 자료를 모으고, 작가가 쓰고, 교열 데스크가 사실을 확인하고, 윤문 담당이 문장을 고르고, 사진부가 사진을 붙입니다. 마지막으로 배달원이 원고를 **편집장 책상(임시저장함)** 에 올려 두면, 편집장(선생님)이 보고 '발행'합니다.

```
[주제판 · 카테고리 설정]  어떤 카테고리에, 누구를 위해, 어느 깊이로 쓸지  → ✋ 주제 확정
        ↓
① blog-research   자료조사 → 출처 카드
② blog-writer     원고 + 배치표(네이버 에디터에 넣을 블록 순서)
③ blog-factcheck  사실 판정표 + 내부용 '예상 반론 메모'  (+ reviewer 독립 검수)
        ↓ ✋ 담당자 확인: ❌·확인 못 함·단체 입장 문장
④ blog-polish     문장 다듬기 (뜻이 바뀐 문장은 원래대로)
⑤ blog-image      단체 사진·무료 이미지·(선택) AI 삽화 + 출처대장
⑥ 미리보기         네이버처럼 보이는 화면(PC/모바일)  → ✋ 이 글 승인
⑦ naver-draft     블로그 도우미 확장이 에디터를 채우고 '저장'(임시저장)
⑧ 발행             ✋ 선생님이 직접 '발행' → 발행기록
정기화: 예약 작업이 매주 ①~⑥까지 초안을 만들어 두고 알려 줌 (임시저장·발행은 하지 않음)
```

✋ 표시가 **사람 승인 지점**입니다. 주제 확정, 판정표 확인, 미리보기 승인, 발행 — 네 곳에서 사람이 멈춰 확인합니다. 네이버는 공식 글쓰기 API가 없고 약관이 허락 없는 자동 게시를 금지하므로, **로그인과 '발행'은 사람**이 하고 확장은 임시저장까지만 합니다(00 문서 ④).

## 🃏 회차별 단계 카드

각 카드는 **그 회차 본 학습을 마친 뒤** 씁니다. 회차 본문 끝의 '🚀 관통 프로젝트' 절과 같은 자리(`내_학습기록/내_프로젝트.md`의 회차별 성장 기록 표)에 결과를 남기므로, 카드가 그 절의 **블로그판**이라고 보시면 됩니다. 2~8회차 카드는 튜터 폴더 세션에서, 9~10회차 카드는 프로젝트 폴더를 연 세션에서 합니다.

**지금 몇 회차세요?**

| 지금 위치 | 이렇게 시작합니다 |
|---|---|
| 2~3회차 | 2회차 카드부터 차례로 |
| 4~9회차 진행 중 | 아래 '따라잡기' 문장으로 지난 카드를 한 번에 → 이후 회차는 카드대로 |
| 10회차 수료 | 아래 '🏃 몰아서 경로' |
| 다른 관통 프로젝트를 이미 진행 중 | 그 프로젝트는 그대로 두고, 수료 뒤 몰아서 경로로(두 개를 동시에 하면 둘 다 느려집니다) |

```
관통 프로젝트를 'L1 단체 블로그 정기 발행'으로 하고 싶어. 일상실습/01_네이버블로그/A_단체블로그_정기발행.md의 2회차 카드부터 지난 회차 카드까지를 차례로 따라잡자. 카드마다 완료 기준을 확인하고 나서 다음 카드로 넘어가줘.
```

### 🃏 3회차 카드 — 블로그 운영 규칙(CLAUDE.md)과 카테고리 설정

🧩 CLAUDE.md는 새 동료 책상에 붙여 두는 **'우리 블로그 편집 지침'** 이고, 주제판은 **편집 회의 칠판**입니다. 한 번 적어 두면 매 글마다 다시 설명하지 않아도 됩니다.

| CLAUDE.md에 넣을 규칙 | 예(교진추 블로그를 가정한 예시) |
|---|---|
| 블로그 정보 | 주소, 독자(교사·학부모), 주기, 담당(쓰기·확인·발행) |
| 톤 | 정중한 설명체, 문단 3~5문장, 설교조·조롱 금지 |
| 금지 표현 | 출처 없는 '사기극·조작', 확인 안 된 '모든 교과서', 확인 못 한 '동료심사를 거친' |
| 신학 테두리 | 정통 개혁주의, 단체 관점은 적극적으로 + 인용은 1차 출처와 대조 |
| 출처 표기 | 글 끝 '참고한 자료'(논문·책·단체 자료 형식), 그다음 '사진 출처' |
| AI 사용 표기 | 글 끝 고정 문구 — 예: "이 글은 AI(Claude)의 도움을 받아 자료를 조사하고 초안을 작성한 뒤, 담당자가 사실을 확인하고 다듬었습니다." |
| 사진·인물 | 모든 이미지는 출처대장에, NC(비영리 한정) 라이선스 제외, 얼굴은 동의 대장 확인, 만 14세 미만은 보호자 동의 |
| 단체 입장 문장 | 근거 자료가 없으면 `[담당자 확인: 단체 입장]` 표시 → 담당자 승인 뒤 지움 |
| 부분 수정 | 지적된 문장만 고침, 글 전체 다시 쓰기 금지 |
| 발행 | 로그인·발행은 사람, 한 번에 한 편, 예상 반론 메모는 내부용(발행 금지) |

주제판의 **검증 수준**은 카테고리마다 정합니다. 모르면 '엄격'으로 둡니다.

| 검증 수준 | 어떤 글 | 확인하는 깊이 |
|---|---|---|
| 엄격 | 과학·인용·논쟁이 들어간 글(교진추 자료실·칼럼) | 모든 사실 문장을 1차 출처와 대조, 예상 반론 메모, reviewer 필수 |
| 보통 | 공식 자료 소개, 뉴스레터 블로그판 | 숫자·날짜·인용·고유명사를 공식 출처와 대조 |
| 가벼움 | 행사 후기, 단체 소식, 영상 소개 | 날짜·장소·이름·숫자를 단체 기록과 대조, 얼굴 사진 동의 |

### 🃏 10회차 카드 — 설계서, 작업 이력·재시도, 첫 임시저장 → 사람 발행, 예약 작업

| 항목 | 내용 |
|---|---|
| 익히는 기능 | 설계 6요소, 사람 승인 지점, 기록, 예약 작업(Routines) |
| 블로그에서 할 일 | `설계서.md`, 작업 이력·재시도·로그, 첫 임시저장(비공개) → 사람 발행, 주간 초안 예약 작업, (선택) 자동 예약 발행 |
| 어디서 · 시간 | 프로젝트 폴더 세션 · 2~3시간 |

**1. 설계서**
```
설계서.md를 10회차 설계서 템플릿(개요 칸 + 단계표: # | 단계 | 담당 | 입력 | 출력 | 검증 방법 | 실패 시)으로 만들어줘. 업무명: 단체 블로그 정기 발행(L1). 단계: 주제 고르기(사람 ✋) → blog-research → blog-writer → blog-factcheck + reviewer → 담당자 확인(사람 ✋: ❌·확인 못 함·단체 입장 문장) → blog-polish → blog-image → 미리보기 승인(사람 ✋) → naver-draft 임시저장 → 발행(사람 ✋) → 발행기록. 애매한 칸은 나에게 물어봐줘.
```

**2. 작업 이력·재시도·로그** — 🧩 택배 **배송 조회**처럼 "어느 단계까지 왔고 어디서 멈췄는지"를 남깁니다. 실패하면 처음부터가 아니라 **멈춘 단계부터** 다시 하므로 시간과 사용량을 아낍니다.
```
한 편을 만드는 단계마다 글 폴더의 작업이력.json과 로그/YYYY-MM-DD.log에 기록하는 도구/작업이력.py를 만들어줘. 형식은 튜터 폴더의 일상실습/01_네이버블로그/여행스튜디오_규약.md 2.6절. 오류가 나면 멈추고 그 단계를 '실패'로, 다시 할 때는 실패한 단계부터(앞 단계 산출물 재사용). 스킬 5개가 이 도구로 기록하게 고치고, 막혔을 때 쓸 수리프롬프트_카드.md도 만들어줘. 마지막으로 일부러 한 단계를 실패시켜 이어하기가 되는지 보여줘.
```

**3. 첫 임시저장 → 사람 발행** — 처음 몇 편은 **비공개**로 연습합니다.
```
승인된 글 1편의 발행 패키지를 naver-draft로 임시저장해줘. 공개는 비공개로. 시작 전에 제목·카테고리·블록 수·사진 수·승인 상태를 보여주고 내 확인을 받아줘.
```
그다음은 **선생님이 직접** 합니다: 네이버 글쓰기 화면 오른쪽 위 **'저장'** 옆 숫자 → 임시저장 목록에서 이 글 열기 → 오른쪽 아래 **기기 아이콘**으로 모바일 화면 확인 → 빠진 것 채우기 → **'발행'** 설정에서 카테고리·태그·공개(비공개) 확인 → '발행'. 끝나면 "발행 끝났어. 주소는 ○○야. 발행기록에 남겨줘."

**4. 주간 초안 예약 작업** — Code 탭 사이드바 **Routines** → **New routine** → **Local**(10회차 Part 3).

| 칸 | 넣을 것 |
|---|---|
| Name | `블로그 주간 초안` |
| Description | `매주 월요일 주제판 '대기' 주제 1개로 미리보기까지 초안 만들기` |
| Instructions | 아래 지시문을 붙여 넣고, 작업 폴더는 `실습공간/과제/내프로젝트`(권한 모드·모델은 기본값, Bypass permissions는 고르지 않음) |
| Schedule | **Weekly** → 월요일 오전 9시 |

```
CLAUDE.md와 주제판.md를 읽는다. 주제 목록에서 상태가 '대기'이고 예정일이 가장 빠른 주제 1개만 고른다.
blog-research → blog-writer → blog-factcheck → blog-polish → blog-image 순서로 미리보기까지 만든다. 단계마다 작업이력에 기록한다.
팩트체크에서 ❌나 확인 못 함이 나오면 고치지 말고 목록만 적고 멈춘다. 단체 입장 문장은 [담당자 확인]을 그대로 둔다.
naver-draft(임시저장)와 발행은 하지 않는다. 외부 AI 삽화도 만들지 않는다. 메일을 보내거나 파일을 지우지 않는다.
주제판의 그 주제 상태를 '초안(검토 대기)'로 바꾸고, 결과 요약을 글 폴더의 주간보고.md에 쓴다.
```
저장한 뒤 **Run now**로 한 번 돌려 권한을 '항상 허용'해 둡니다. 예약 작업은 **앱이 켜져 있고 컴퓨터가 깨어 있을 때만** 돕니다.

**5. (선택) 자동 예약 발행** — 기본은 꺼져 있습니다.

> ⚠️ 네이버 이용약관은 허락 없는 자동화 수단의 게시를 금지하고, 아이디 보호조치·검색 누락 위험이 있습니다. 켜려면 세 가지가 **모두** 필요합니다: ① `블로그설정.json`의 `자동예약발행: true` ② 담당자가 미리보기를 보고 "이 글 승인"한 글 ③ 이번에 사람이 예약 시각을 말하고 "예약 발행해"라고 지시. AI 삽화가 든 글(`AI활용표시: true`)은 예약 발행되지 않습니다(사진마다 'AI 활용 설정'을 사람이 켠 뒤 직접 발행). 한 계정에 하루 여러 편을 몰지 않고, 정확히 같은 간격도 고집하지 않습니다. 확신이 없으면 켜지 마세요.

✅ **완료 기준**: 설계서에 승인 지점 4곳과 '실패 시' 칸 · 작업이력에 단계 기록 + 실패 → 이어하기 1회 · 비공개 임시저장 → 사람 발행 → 발행기록 1줄 · 예약 작업 Run now 결과(주간보고.md) · `내_프로젝트.md` 10회차 세 칸과 수료카드에 블로그 Before/After

📁 **결과물**: `설계서.md`, `도구/작업이력.py`, `로그/`, `수리프롬프트_카드.md`, 예약 작업, 발행 1편

🆘 **막히면**: 임시저장이 멈추면 `확장이 보낸 결과를 읽고 몇 번째 단계에서 왜 멈췄는지 알려줘. 내가 화면을 확인한 뒤 그 단계부터 다시 하자.` · '로그인 필요'면 사람이 로그인 · 카테고리 단계가 '주의'(블로그에 없어 기본 카테고리로 임시저장됨)면 발행 전에 '발행' 설정 창에서 직접 고르고, 다음 글부터 주제판 카테고리 이름을 블로그와 글자 대조 · 예약 작업이 승인 대기로 멈추면 Run now로 '항상 허용'.

## 💬 딸깍 프롬프트 카드

프로젝트 폴더 세션에서 씁니다. `<글 폴더>` 자리는 Claude가 물어보면 답하면 됩니다.

```
주제판에서 '대기' 주제 중 예정일이 가장 빠른 것으로 이번 주 초안을 만들어줘. 미리보기까지 하고 임시저장 전에 멈춰줘.
```
**팩트체크만 다시 할 때**
```
<글 폴더>의 원고에서 지난 검증 뒤 바뀐 문장과 새 문장만 blog-factcheck로 다시 검증해줘. 바뀌지 않은 문장은 건드리지 마.
```
**지적된 문장만 고칠 때**
```
팩트체크 판정표의 ❌·⚠️ 문장만 고쳐줘. 다른 문장은 한 글자도 바꾸지 말고, 고친 목록을 표로 보여줘. 그다음 바뀐 문장만 다시 검증해줘.
```
**멈춘 단계부터 다시 할 때 (수리 프롬프트)**

### 교진추 관련 신학 방침
- 교진추의 관점(반진화론·창조과학)은 개혁주의 신학 안에 있으며, 튜터는 이를 **적극 수용**해 블로그 연재를 더 효율적·효과적으로 돕습니다. 팩트체크는 반대편이 꼬투리 잡을 **인용·서지의 빈틈을 미리 막는 일**이라고 설명합니다.
- 리허설에서 1차 출처로 확인한 문장(예: 연구자 본인이 1998년 서한에서 1874년 그림이 상당 부분 지어낸 것이라고 쓴 점)이 오히려 글을 강하게 만들었습니다. 흔한 오해를 글이 먼저 바로잡으면 신뢰가 올라갑니다.
- 자주 틀리는 서지: 1차 청원 "시조새는 중간종이 아니다"는 **2011-12-05**, 2차 "말의 화석계열"은 2012-03-26(교진추 게시물 기준) — "2012년 청원"으로 뭉뚱그리지 않습니다.
- 해석 쟁점(양식화를 의도적 조작으로 볼지 등)은 판정하지 않고, 예상 반론 메모에 주류 학계의 근거와 답변 준비 포인트로 정리합니다. 단체의 관점을 바꾸라고 권하지 않습니다.
