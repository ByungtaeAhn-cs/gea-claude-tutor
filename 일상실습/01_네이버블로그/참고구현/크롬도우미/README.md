# 블로그 도우미 (Chrome·Edge 확장) — 네이버 글 채우기

내 PC에서 만든 글(발행 패키지)을 **네이버 블로그 글쓰기 화면에 채우고 '저장'(임시저장)까지** 해 주는 확장입니다. 네이버 연동의 **기본 경로**입니다.

- 로그인은 **사람이 자기 브라우저에서** 합니다. 확장은 비밀번호를 만지지 않습니다.
- '발행'은 기본적으로 **사람이** 누릅니다. (선택: 사람이 승인한 글만 예약 발행 — 아래 '예약 발행')
- Claude in Chrome 은 네이버를 막는다는 보고가 있어 기본에서 뺐습니다. 쓸 수 있는 환경이면, 확장이 멈춘 화면을 살펴보는 **보조**로만 씁니다.

## 이렇게 동작합니다

```
내 PC 안                                                  브라우저(Chrome 또는 Edge, 사람이 로그인해 둠)
발행 패키지 → 서버(127.0.0.1:8765) ⇄ 블로그 도우미 확장 → 네이버 글쓰기 화면: 제목·본문·사진·동영상·장소·태그… → '저장'
              (여행 스튜디오 또는 발행서버)   (연결 코드로 짝지음)
```

글·사진·동영상은 내 PC 안에서만 오가다가 네이버 글쓰기 화면에 들어갑니다. 확장은 **127.0.0.1:8765 말고는 아무 데도 보내지 않습니다.**

## 준비물

- Chrome 또는 Microsoft Edge (버전 111 이상) — **네이버에 로그인해 둔 그 브라우저**에 설치
- 발행 패키지(`발행/패키지_….json`)와 업로드 사본(사진·동영상) — 여행 스튜디오·단체 블로그 스킬이 만들어 줍니다
- 서버 하나: 여행 블로그는 **여행 스튜디오**, 단체 블로그는 **발행서버**(학습자 프로젝트의 `도구/발행서버.py` — 공용 도구를 `도구\`에 복사해 둔 것. 참고구현 안에서는 `참고구현/공용/발행서버.py`)

> 아래 단체 블로그 명령은 모두 **학습자 프로젝트 폴더**(예: `실습공간/과제/내프로젝트/`)에서 실행하는 모양입니다.

## 1. 설치 (한 번만)

화면 글자는 브라우저 버전에 따라 **조금 다를 수 있습니다.**

| 순서 | Chrome | Microsoft Edge |
|---|---|---|
| 1 | 주소창에 `chrome://extensions` (또는 점 세 개 메뉴 → 확장 프로그램 → 확장 프로그램 관리) | 주소창에 `edge://extensions` (또는 점 세 개 메뉴 → 확장 → 확장 관리) |
| 2 | 오른쪽 위 **개발자 모드** 켜기 | 왼쪽(또는 아래)의 **개발자 모드** 켜기 |
| 3 | **압축해제된 확장 프로그램을 로드** → 이 폴더(`크롬도우미`) 고르기 | **압축 풀린 확장 로드**(Load unpacked) → 이 폴더 고르기 |
| 4 | 목록에 **블로그 도우미 (네이버 글 채우기)** | 같음 |
| 5 | (권장) 주소창 옆 퍼즐 아이콘 → 블로그 도우미 **고정** | (권장) 확장 아이콘 → 블로그 도우미 **도구 모음에 표시** |

- 설치할 때 "blog.naver.com 데이터 읽기·변경" 권한이 보입니다. 글쓰기 화면을 채우는 데 필요합니다. 그 밖에는 내 PC 의 `127.0.0.1:8765` 와 연결 정보 저장(storage)만 씁니다.
- Edge 공식 안내: learn.microsoft.com/microsoft-edge/extensions/getting-started/extension-sideloading
- 폴더를 옮기거나 지우면 확장도 사라집니다. 파일을 고쳤다면 확장 카드의 **새로고침(⟳)** 후 네이버 화면도 새로고침.

## 2. 연결하기 (브라우저마다 한 번)

1. 연결 코드(숫자 6자리, 5분 동안 한 번만)를 받습니다.
   - 여행 블로그: 여행 스튜디오의 **[확장 연결]**
   - 단체 블로그(**8회차 — 아직 글이 없을 때**): Claude 에게 "확장 연결하게 서버 켜 줘" →
     ```
     python 도구/발행서버.py --연결만
     ```
     글(패키지) 없이 서버를 켜고 연결 코드를 보여 줍니다. 확장이 연결되면 서버 창에 **연결 목록**이 나오고, Ctrl+C 로 끕니다(`--연결되면종료`를 붙이면 연결되자마자 저절로 꺼짐). 코드가 5분 안에 안 쓰이면 새 코드를 다시 보여 줍니다.
   - 서버가 이미 켜져 있을 때(9회차부터, 다른 브라우저를 더 연결할 때): 다른 창에서 `python 도구/발행서버.py --연결코드`
2. 브라우저 오른쪽 위 **블로그 도우미 아이콘**을 누르고 코드를 넣고 **[연결]**.
3. "연결됨 · 발행서버(또는 여행스튜디오)"가 보이면 끝. 연결 정보는 내 PC(`~/.gea-blog-helper`)에 남아서 **9회차에 글이 생긴 뒤 켠 서버에서도 그대로 통합니다**. 여행 스튜디오와 발행서버 둘 다 됩니다(같은 PC).

같은 확장 폴더를 Chrome 과 Edge 에 둘 다 설치하면 확장 ID 가 같아 **나중에 연결한 쪽만 통합니다**(평소 쓰는 브라우저 하나로 정하기). 연결을 끊으려면 팝업의 **[연결 끊기]**.

## 3. 글 채우기

### 여행 블로그
여행 스튜디오의 **[네이버 임시저장]** 을 누르면 스튜디오가 작업을 만들고 브라우저로 글쓰기 화면을 엽니다.

### 단체 블로그(GUI 없음) — Claude 가 대신 합니다
Claude 에게 "이 글 네이버에 임시저장해 줘"라고 하면, Claude 는:
1. 서버를 켜고 작업을 만든 뒤 글쓰기 화면을 엽니다. 블로그 아이디·브라우저·편 사이 간격은 프로젝트의 `블로그설정.json` 에서 읽습니다.
   ```
   python 도구/발행서버.py --설정 블로그설정.json --패키지 발행/패키지_칼럼.json --작업 임시저장 --열기
   ```
   `블로그설정.json` 예: `{"블로그ID": "내블로그아이디", "브라우저": "chrome", "자동예약발행": false, "편사이간격분": 30}` (브라우저는 확장을 설치한 것 — `chrome`·`edge`·`default`). 명령줄에 `--열기 아이디`·`--브라우저 edge` 를 주면 그 값이 이깁니다. 서버는 켜 둔 채로 둡니다.
2. 확장이 채우는 동안 기다렸다가 결과를 읽어 알려 줍니다.
   ```
   python 도구/발행서버.py --패키지 발행/ --작업보기 n20261007-101233-a3f9
   ```
   또는 `발행/작업_<작업ID>.json` 의 `상태`(임시저장완료 / 실패)와 `단계`를 읽습니다.

### 화면에서 일어나는 일
1. 글쓰기 화면 오른쪽 아래에 **블로그 도우미** 패널이 뜨고 작업을 받습니다.
2. **5초** 뒤 채우기 시작(그 사이 **[멈춤]** 가능). 채우는 동안 화면을 만지지 마세요.
3. 단계 목록이 하나씩 '완료'로 바뀝니다: 준비 → 제목 → 블록들 → 태그 → 카테고리 → 공개설정 → AI활용 → 저장.
4. 끝나면 "임시저장까지 끝났습니다". 사람이 네이버 화면에서 **모바일 보기로 확인한 뒤 '발행'** 을 누릅니다.

## 4. 패널 사용법

| 화면 | 뜻 |
|---|---|
| 단계 목록 | 대기 / 진행 중 / 완료 / **완료(주의)** / 사람이 함 / 건너뜀 / **실패**. 단계에 마우스를 올리면 내용 |
| **[멈춤]** | 지금 단계가 끝나면 멈춤(시작 전이면 바로) |
| **['…' 단계부터 다시]** | 실패한 단계부터 다시. 앞 단계 내용은 그대로 둠(화면을 새로고침했다면 처음부터 새 글쓰기 화면에서) |
| **[이 단계는 내가 했음 → 다음]** | 사람이 그 단계를 손으로 끝냈을 때. 다음 단계부터 이어서 |
| **[작업 확인]** | 서버에 작업이 있는지 지금 확인. 빈 글쓰기 화면은 10초마다 저절로 확인하고, **이미 글이 있는 화면(끝났거나 실패)은 새 글을 받지 않습니다** — 스튜디오·Claude 가 이 작업을 다시 하라고 했을 때만 이 버튼으로 **같은 작업 ID 의 작업만** 받습니다(다시 하기 버튼도 같음 — 다른 글이 기다리고 있어도 섞이지 않음). 다음 글은 새 글쓰기 화면에서 |
| 사진 묶음만 넣기(보조) | 글 채우기와 따로, 사진 묶음 하나만 넣을 때(배치 선택은 사람이). **기본으로 숨김** — 확장 아이콘(팝업)의 "'사진 묶음만 넣기'(보조 도구) 보이기"를 켜야 보임(다른 글의 사진 목록이 보이므로 필요할 때만) |
| 고급(실측용) | 사진 넣는 방법 고르기, 자세한 기록, **[진단 보내기]**(막혔을 때 — 화면 구조만 내 PC 서버로, 아래 11절) |

**결과가 '주의'** 인 단계(예: 업로드 사본이 없는 영상, 사진 설명을 못 넣음)는 패널 문장대로 사람이 마무리합니다. **'실패'** 이면 그 단계에서 멈춰 있으니, 이유를 읽고 사람이 처리한 뒤 다시 하세요. 확장은 모르는 화면에서 아무 버튼이나 누르지 않습니다.

## 5. 글을 넣는 방법 (방법 표)

처음에는 공개 자료로 정했고, **2026-10-08 강사 실측**(Edge 154, Windows, 실습용 비공개 블로그)으로 고쳤습니다. '실측' 열이 그 결과입니다. 네이버 화면이 바뀌면 다시 깨질 수 있고, 바꿀 곳은 `selectors.js` 입니다(실측한 값에는 `2026-10-08 실측` 표시).

| 단계 | 방법 | 확인 | 실측(2026-10-08) |
|---|---|---|---|
| 제목 | 제목 칸 클릭 → `execCommand('insertText')`, 안 되면 paste 이벤트 | 제목 칸 글자 = 패키지 제목 | ✅ `execCommand`(숨은 입력 프레임) |
| 본문·소제목·인용구 | 마지막 문단 끝 클릭 → 빈 문단 만들기 → 글 유형 메뉴(본문/소제목/인용구) → **숨은 입력 프레임(input_buffer)에 paste 이벤트**(text/html·text/plain), 안 되면 `execCommand` | 글이 보이고 **문서 끝**에 있음 | ✅ paste. 새 문단은 **Enter 키 이벤트**로 만듦(`insertParagraph`는 입력 프레임만 바뀌고 에디터 문단은 안 생김). 두 줄 글은 한 덩어리 안의 문단 둘 |
| 꿀팁 / 참고자료 | 꿀팁 → 인용구("꿀팁: …"), 참고자료 → 본문("참고자료" + "- 항목") | 위와 같음 | ✅ |
| 구분선 | 구분선 버튼 | 구분선 모듈이 문서 끝에 생김 | ✅ |
| 사진 | (a) 사진 버튼 → 네이버가 여는 파일 칸을 가로채 사진을 넣음(파일 선택 창 안 열림) → 안 되면 (b) 끌어다 놓기 | 사진 모듈이 문서 끝에 생김 | ✅ (a) 가로채기 |
| 그룹 사진 방식 | 배치 선택 창에서 **개별 사진 / 콜라주 / 슬라이드** 를 묶음 '방식'에 맞게 고름 | 사진이 보임 | ✅ 콜라주 3장 |
| 사진 설명·대표 | 사진 클릭 → 설명 칸 클릭 → 글 넣기 / 대표 버튼 | 설명 글자 확인(못 하면 '주의') | ⚠️ **설명은 안 들어감**(원인 조사 중 — 패널 기록에 방법별 결과를 남김, 사람이 넣기). 대표: 첫 사진이 이미 대표 |
| 장소 | 장소 버튼 → 검색(검색 버튼·Enter 를 번갈아 최대 4번) → **이름이 정확히 같은** 결과의 '추가' → 5곳까지 → 확인 | 장소 모듈이 문서 끝에 생김 | ✅ 2곳(협재해수욕장·성산일출봉). 검색칸은 React 라 `execCommand` 로 입력, 검색 버튼 클릭이 가끔 무시되어 재시도 |
| 동영상 | 확장의 숨은 '동영상 다리' 창(`video-bridge.html`)이 내 PC 서버에서 동영상을 받아 파일로 넘김 → '동영상' 버튼 → 네이버 **동영상 업로더**(`#video-uploader-wrap`)의 '동영상 추가'가 여는 파일 칸을 가로채 넣음(1회 최대 10개) → 파일마다 '업로드 완료'가 될 때까지 기다림(최대 30분, 1분마다 '처리중') → 목록에서 파일을 하나씩 골라 **제목(필수, 40자)**·정보를 넣고 '완료' | 동영상 모듈이 문서 끝에 생김. '주의' 아이콘·시간 초과면 멈춤 | ✅ 2개(5초·126MB) 한 번에 → 본문에 **동영상 덩어리 2개**. 동영상 다리는 네이버 화면 정책에 막히지 않음. 제목은 블록 `제목` + 번호(" 1", " 2"), 없으면 글 제목 |
| 태그 | 발행 설정 창을 엶(이것만으로는 발행 안 됨) → 태그 칸에 하나씩 + Enter | 태그 칩 확인 | ✅ 2개(`span.tag__`) |
| 카테고리 | 카테고리 목록에서 **이름이 정확히 같은** 것의 **라디오**를 누름(없으면 '있는 것' 목록과 함께 실패) | 버튼 글자 | ✅ (줄 `li`를 누르면 안 바뀜 → 안의 라디오) |
| 공개 설정 | `#open_public` / `#open_neighbor` / `#open_both_neighbor` / `#open_private` | 선택됨 | ✅ 비공개 |
| AI 활용 | **확장은 누르지 않음.** 글의 `AI활용표시`가 true 면 '주의'로 "AI로 만든 사진·영상마다 'AI 활용 설정'을 켜세요"라고 안내, false 면 건너뜀 | — | 발행 설정 창에는 없고 **사진·콜라주·동영상 덩어리마다 스위치**(사진을 누르면 사진 위에 'AI 활용 설정', 켜짐 = `.se-is-selected`). 어떤 사진이 AI 인지는 사람이 알므로 사람이 켬(강사 결정) |
| 저장 | 발행 설정 창 닫기 → '저장' | 저장 개수 증가 또는 알림 | ✅ 저장 개수(0→1). 임시저장 글을 다시 열어도 **태그·카테고리·공개가 남음**, 모바일 보기 정상 |
| 예약 발행(선택) | 발행 시간 '예약' → 날짜·시·분(10분 단위, 한국 시간) → 발행 확인 | 창이 닫히고 '예약 발행' 표시 | 미실측(라디오 `#radio_time2` '예약' 은 있음) |

'AI 활용 설정' 기준: **AI로 만든(또는 바꾼) 이미지·영상마다 사람이 켬(네이버 기준), 글을 AI 도움으로 쓴 사실은 글 끝 문구로** 적습니다.

동영상을 큰 파일 통로로 옮기는 까닭: 확장 안 메시지는 JSON 이라 수백 MB 동영상을 글자(base64)로 바꾸면 메모리를 3~4배 쓰고 메시지 크기 한계에 걸립니다. 확장 출처의 숨은 창은 토큰으로 내 PC 서버에서 직접 받아(스트리밍, 브라우저가 큰 파일은 디스크에 둠) 파일 그대로 넘기므로 복사가 없습니다. 받을 파일 목록은 서비스 워커가 일회용 표(2분, 같은 탭)로 묶어 두어 네이버 페이지가 받기를 시키거나 파일을 엿볼 수 없고, 토큰은 그 창 밖으로 나가지 않습니다.

출처 번호([C1]~[C7], [N1])는 `selectors.js` 맨 위에 있습니다. 공개 카테고리 목록은 서버에서 `--카테고리확인 블로그아이디`(또는 `--설정` 의 `블로그ID`)로 미리 대조할 수 있습니다(네이버 공개 목록을 읽음, 비공개 카테고리는 안 나올 수 있음 — 확장은 에디터의 카테고리 목록으로 다시 확인).

## 6. (선택) 예약 발행

아래가 **모두** 맞을 때만 확장이 발행 확인 버튼을 누릅니다. 하나라도 아니면 임시저장까지만 합니다. 1~3은 **사람이 직접 누르는 것**이고, Claude 는 대신할 수 없습니다(보안 검수 M3).
1. 예약 발행 작업을 **사람 경로**로 만듦: 여행 스튜디오 화면, 또는 발행서버 `--작업 예약발행` 이 띄우는 **데스크탑 확인 창**에서 사람이 [예약 작업 만들기]. 예약 시각은 10분 단위, 지금부터 15분 이상 뒤.
2. 글이 **서명된 승인**을 가짐: 여행 스튜디오는 미리보기 [이 글 승인], 단체 블로그는 `python 도구/발행서버.py --승인 <패키지>` 의 확인 창에서 [이 글 승인]. 서버가 **글 지문과 업로드 파일(사진·동영상·지도 그림)의 바이트 해시**에 서명하므로, JSON 에 `승인됨`만 써서는 안 되고 **승인 뒤 글이나 사진·지도 그림이 하나라도 바뀌면 승인도 무효**(다시 승인). 예약 작업 중에는 서버가 사진을 내줄 때와 확인 버튼을 누르기 직전에 파일을 다시 확인합니다(재검수 N1).
3. 자동 예약이 **켜져 있음**: 설정 `"자동예약발행": true` + 사람이 켠 허락 기록. 단체 블로그는 `python 도구/발행서버.py --설정 블로그설정.json --자동예약켜기`(확인 창에서 위험 안내를 읽고 [자동 예약 켜기]) — 설정 파일 값만 바꿔서는 켜지지 않고, `--자동예약발행` 옵션은 없앴습니다. 끌 때 `--자동예약끄기`. 기본은 꺼짐.
4. 글의 `AI활용표시`가 **false**: AI로 만들거나 바꾼 사진·영상이 있는 글(true)이나 값이 없는 글은 예약 발행하지 않습니다 — 'AI 활용 설정'은 임시저장 뒤 사람이 사진·영상마다 켜야 해서입니다(2026-10-08 실측, 서버·확장 둘 다 확인).

누르기 직전 마지막 확인은 **서버가 '지금' 조건으로** 합니다: 확장이 확인 버튼을 누르기 직전에 보내는 표시(`확인누름`)를, 서버는 허락 기록·서명된 승인·글 지문(승인 뒤 안 바뀌었는지)과 예약 여유(15분)를 다시 따져 맞을 때만 받습니다. 채우는 도중에 설정을 끄거나 승인을 거두면 확장은 누르지 않고 '예약불가'로 멈춥니다(단계 목록은 받을 때 고정 — 도중에 바뀌지 않음).

두 번 예약하지 않게: 확장은 확인 버튼을 누르기 **직전에** 서버에 표시를 남기고, 누르기 직전에 예약 시각이 아직 15분 이상 남았는지 다시 봅니다. 누른 뒤 보고가 끊기면 그 작업은 '예약확인필요'로 멈추고 다시 시도할 수 없습니다 — 사람이 네이버의 예약 발행 목록을 확인한 뒤, 정말 다시 해야 할 때만 새 작업을 `다시예약`으로 만듭니다.

켜기 전에 꼭 알아 둘 것: 네이버 약관은 허락 없는 자동화 게시를 금지합니다. 아이디 보호조치·검색 누락 위험이 있습니다. 한 계정에 하루 여러 편을 자동으로 몰지 마세요.

## 8. 꼭 알아 둘 것 (위험)

- **네이버 화면이 바뀌면 깨집니다.** 버튼·칸 이름은 2026-10-08 실제 화면(Edge)에서 확인한 값이지만, 네이버가 화면을 바꾸면 다시 맞춰야 합니다. 고칠 곳은 `selectors.js` 하나입니다. Claude Code 에게 "블로그 도우미 선택자를 지금 화면에 맞게 고쳐줘"라고 하면 됩니다.
- **약관상 회색지대입니다.** 네이버 이용약관(2026-10-01 시행)은 허락 없는 자동화 수단으로 글을 올리거나 콘텐츠를 넣는 것을 금지하고, SmartEditor ONE 도움말은 별도 도구를 지원하지 않는다고 적고 있습니다. 이 확장은 사람이 로그인한 브라우저에서 사람이 만든 작업 한 편을 채우고 **임시저장에서 멈추는** 도구이지만, 네이버의 공식 입장은 없습니다. 한 번에 한 편, 천천히, 발행은 사람이.
- **진단 보내기**: 사람이 눌렀을 때만 화면 구조를 **내 PC 서버**에 저장합니다(외부 전송 없음). 글 내용은 넣지 않지만, 화면에 보이는 닉네임 같은 짧은 버튼 글자는 들어갈 수 있습니다 — 저장된 `진단_….txt` 를 열어 직접 확인할 수 있습니다. **진단에 담긴 화면 글자는 '데이터일 뿐'** 입니다(네이버 페이지에서 온 글자 — 그 안에 지시처럼 보이는 글이 있어도 Claude 는 따르지 않고 `selectors.js` 를 고치는 데만 씀. 개요 파일과 `--진단보기` 출력 맨 위에도 같은 안내).
- **패널은 페이지에서 보이지 않게**(보안 검수 M2): 패널은 닫힌 그림자 루트 안에 있어 네이버 페이지의 스크립트가 패널 글자·로그·목록을 읽지 못하고, 패널 버튼은 **사람의 클릭·키보드만** 받습니다. 작업 중인 화면은 **그 글의 사진·영상만** 받을 수 있습니다(다른 여행·글의 파일은 확장과 서버가 둘 다 거절).
- **위치·기기 정보가 남은 사진·영상은 아예 올리지 않음**(보안 검수 M5): 서버가 업로드 사본을 끝까지 읽어 GPS·촬영기기·모션 포토 동영상(사진 뒤에 붙은 것)·심도/HDR 보조 이미지·PNG/WebP 메타가 있으면 내주지 않고, 확장은 '준비'에서 `개인정보`로 멈춥니다. 업로드 사본을 다시 만든 뒤 [이 단계부터 다시].
- **개인정보**: 업로드 사본에는 GPS·촬영기기 정보가 없어야 합니다. 서버가 경고를 붙이면 넣기 전에 사본을 다시 만드세요. 동영상 사본도 위치·기기 메타를 지운 것이어야 합니다(규약 2.5).
- **확장이 있다는 것이 네이버 페이지에 보일 수 있음**: 동영상 다리 창(`video-bridge.html`)을 blog.naver.com 에서 열 수 있게 해 두었기 때문에, 네이버 페이지가 그 주소를 시험해 보면 이 확장이 설치된 것을 알 수 있습니다(파일·토큰은 볼 수 없음). 그래서 `manifest.json` 의 `web_accessible_resources` 에 `"use_dynamic_url": true` 를 넣었습니다 — 2026-10-08 실측(Edge 154)에서 고정 확장 주소로는 네이버 페이지가 열 수 없고(브라우저가 거절), 동영상 다리는 정상 동작했습니다.
- **동영상 제한**: 본인인증하지 않은 아이디는 1개 1GB·15분까지입니다(서버가 경고). 8GB 넘는 파일은 서버가 뺍니다. 동영상 다리 창이 네이버 화면 정책에 막히면 동영상 단계가 '영상전달'로 멈춥니다(그때는 사람이 올리고 [이 단계는 내가 했음]).

## 10. 문제가 생기면

| 증상 | 확인할 것 |
|---|---|
| '준비'에서 "작성 중인 글이 있습니다" 안내 | 새로고침·로그인 뒤 네이버가 예전 글을 이어 쓸지 묻는 창. 패널이 1분 기다리니 **[취소]**(새 글)를 누르면 그대로 이어서 채움. [확인]은 예전 글을 불러오므로 '에디터에 이미 내용이 있음'으로 멈춤 |
| '준비'에서 `개인정보` | 업로드 사본에 위치·기기 정보·모션 포토 등이 남아 서버가 내주지 않은 파일이 있음(패널 문장에 파일 이름). 업로드 사본을 다시 만든 뒤 [이 단계부터 다시] |
| 예약이 안 켜짐 `예약불가 … 허락` / `… 서명` / `… 바뀌었습니다` | 순서대로: 사람이 `--자동예약켜기`(확인 창) / 사람이 `--승인 <패키지>`(확인 창) / 승인 뒤 글이 바뀜 → 다시 승인 |
| 패널이 안 보임 | 글쓰기 화면인지, 확장이 켜져 있는지, 화면 새로고침. 개발자 도구의 `<html data-blog-helper="…">` 가 `shell-no-panel`/`no-editor` 면 주소나 에디터 모양이 바뀐 것 → `manifest.json` 의 `matches`, `selectors.js` 의 `writeUrl`·`editorRoot` |
| 연결 필요 | 확장 아이콘 → 연결 코드 넣기(코드는 5분·한 번만) |
