# 블로그 도우미 회귀 시험 — 모의 에디터

`모의에디터.html`은 네이버 SmartEditor ONE을 흉내 낸 시험 페이지입니다(진짜 네이버가 아닙니다). **2026-10-08 강사 실측**(Edge, 실제 네이버 에디터)에서 확인한 구조에 맞춰 두었습니다. 확장을 설치하거나 네이버에 접속하지 않고, 브라우저 하나로 `content.js`·`selectors.js`를 고친 뒤 깨진 곳이 없는지 확인합니다.

> 실측 기록: 크롬도우미 [README.md](../README.md) 5절(방법 표)·11절(결과 요약). 실제 화면에서 막히면 그때는 패널의 **[진단 보내기]** 로 고치고, 고친 구조를 이 모의 에디터에도 반영해 두세요.

## 1. 여는 법

1. 터미널에서 **크롬도우미 폴더**를 웹으로 엽니다(하네스가 `../content.js` 등을 불러오므로 파일로 직접 열면 안 됨).
   ```
   python -m http.server 8790 --bind 127.0.0.1
   ```
2. 브라우저 주소창에 `http://127.0.0.1:8790/테스트/모의에디터.html?harness=1`
3. 왼쪽 파란 상자(테스트 하네스)가 "준비됨 (블로그 도우미 0.5.1)"이면 됩니다. 하네스는 확장 파일을 **캐시 없이 늘 새로** 불러옵니다.

## 2. 시나리오

**[글 채우기(가짜 작업)]** 를 누르면 패널이 가짜 작업(본문 2줄·소제목·사진 1·콜라주 3·인용구·구분선·장소 2·**동영상 2개**·참고자료, 태그 2·카테고리 '여행'·비공개·AI 표시 true)을 받아 5초 뒤 채웁니다. 끝나면 콘솔에서 `__harness.summary()`를 봅니다.

## 3. 설정(주소 뒤에)

| 설정 | 뜻 |
|---|---|
| `input=detached\|attached\|existing\|dispatch\|none\|ignored` | 사진 버튼이 파일 칸을 다루는 방식(기본 detached) |
| `drop=on\|trusted\|off`, `delay=300`, `only=1` | 끌어다 놓기, 사진이 보일 때까지(ms), 첫 장만 |
| `paste=on\|trusted` | 숨은 입력칸이 paste 이벤트를 받는지(trusted = 진짜 붙여넣기만) |
| `barrier=protect\|captcha\|login` | 보호조치 문구 / 캡차 / 로그인 프레임 |
| `popup=draft`, `restore=800` | '작성 중인 글이 있습니다.' 창, [확인] 뒤 예전 글이 불러와지기까지(ms) |
| `help=1`, `prefill=1` | 도움말 패널, 제목이 이미 있음 |
| `placeflaky=1` | 장소 검색 버튼의 첫 클릭 무시 |
| `placespace=1\|branch\|dup\|same` | 장소 검색이 띄어쓰기를 무시하고 비슷한 이름을 여럿 돌려줌(2026-10-09 실측 흉내). 가짜 작업의 블록 7 장소도 바뀜: `1` = '성산 일출봉'(결과는 '성산일출봉'·'성산일출봉 주차장'·'성산일출봉 매표소')·'오설록 티뮤지엄', `branch` = '바다 카페'(가상 — 결과는 '바다카페 애월점'·'바다카페 협재점'·'바다커피' 등 지점 여럿), `dup` = '성산 일출봉'(띄어쓰기만 다른 '성산일출봉'이 2곳), `same` = '성산일출봉'·'오설록 티뮤지엄'(이름이 정확히 같은 '성산일출봉'이 2곳) |
| `cat=missing` | 카테고리 목록에 '여행'이 없음(낙서장·포토로그·스크랩·일상, 기본 낙서장 — 2026-10-09 실측 블로그 모양) |
| `mode=reserve` | 가짜 작업의 모드를 '예약발행'으로(예약 조건은 안 맞으므로 단계는 '저장'까지 — 서버와 같음) |
| `caption=dead\|none` | 사진 설명 칸이 글을 받지 않음 / 설명 칸이 아예 없음(실제 화면에서 설명이 안 들어가는 현상의 '못 넣음' 경로만 흉내) |
| `vup=600`, `venc=900`, `vlate=300`, `vfail=1` | 동영상 업로드·대표 이미지 추출 시간(ms), 업로더 내용이 늦게 그려지는 시간, 첫 동영상 업로드 실패 |
| `shell=1` | 바깥 화면 + `iframe#mainFrame`(실제 확장을 설치해 패널·주소 판별을 볼 때) |

## 4. 실측 구조를 흉내 낸 것 / 못 낸 것

흉내 낸 것(2026-10-08 실측):
- 숨은 입력 프레임: **Enter 키로 새 문단**, `execCommand('insertParagraph')`는 무시
- 동영상: `div.se-popup.se-popup-video-upload > #video-uploader-wrap`(nvu_) — 창 틀 먼저·내용 늦게, '동영상 추가' → 파일마다 `nvu_step_upload/extract`(로딩 아이콘) → "업로드 완료"(진행 막대는 남음), 정보 칸이 같은 창 안(제목 필수·40자), 파일을 고를 때마다 목록을 새로 그림, 제목이 비었거나 처리 중이면 완료 거절, 본문에 파일마다 동영상 덩어리
- 사진·콜라주·동영상마다 'AI 활용 설정' 스위치(`button.se-set-ai-mark-button-toggle`, 켜짐 `.se-is-selected`) — 발행 설정 창에는 없음
- 카테고리: `li.item__ > span.option__ > input[type=radio] + label` — 줄 클릭으로는 안 바뀜
- 장소 검색칸: 브라우저 입력(InputEvent)만 검색어로 받음(값 setter만으로는 검색 안 됨, React 흉내), 검색 전 안내 `…-before-search`
- '작성 중인 글이 있습니다.' 창: `se-popup-alert-confirm`, `strong.se-popup-title`, [취소]/[확인]

흉내 낸 것(2026-10-09 실측 — 설정을 켤 때만): 장소 검색이 띄어쓰기를 무시하고 비슷한 이름·여러 지점을 돌려줌(`placespace`), 블로그에 작업의 카테고리가 없음(`cat=missing`)

못 낸 것(실제 화면에서만 확인):
- [취소]·새로고침 때 에디터 프레임이 새로 그려지는 일(패널이 새로 뜸 → 확장의 '재개' 경로)
- 사진 설명이 실제로는 안 들어가는 현상(모의에서는 들어감 — 원인 미확정. `caption=dead|none`은 못 넣었을 때의 보고 문장만 시험)
- 동영상 다리 iframe·네이버 화면 정책(CSP)·대용량 업로드, 로그인·보호조치의 실제 화면
- 예약 발행 레이어의 날짜·시·분 칸 모양(미실측)
