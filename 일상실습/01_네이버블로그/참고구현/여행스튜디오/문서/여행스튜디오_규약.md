## 0. 원칙

1. **원본 사진·영상은 절대 고치거나 옮기지 않는다.** 원본 폴더는 읽기만, 작업 사본은 `여행/<여행ID>/작업/`.
2. **추측하지 않는다.** 촬영 시각·장소 이름·사람·컨셉이 애매하면 **질문 카드**로 묻는다.
3. **지우지 않는다.** 흐린 사진 등은 '제외 후보' 표시만, 결정은 사람이 GUI에서.
4. **네이버**: 로그인은 사람이 **자기가 평소 쓰는 Chrome 또는 Edge**에서. 글 채우기·임시저장은 **블로그 도우미 확장**. '발행'은 기본적으로 사람. (선택: 사람이 승인한 글만 확장이 **예약 발행** — 9절)
5. 추가 설치 최소: 서버는 **Python 표준 라이브러리만**. 사진 처리에만 `python -m pip install pillow pillow-heif av imagehash mediapipe py-staticmaps tzdata`(Python 3.12 이상, 가상환경 권장, OpenCV는 mediapipe가 함께 설치 — `opencv-python`을 따로 깔지 않음). 영상은 FFmpeg(Mac은 `ffmpeg-full`). AI 삽화는 **Codex CLI(ChatGPT 로그인)**.
6. 모든 텍스트 파일 UTF-8, 스크립트 시작 시 `sys.stdout.reconfigure(encoding="utf-8")`.
7. **스킬 이름은 영문 소문자-하이픈**(예: `studio-connect`), 설명(description)은 한국어로 언제 쓰는지 구체적으로.
8. **같은 파일을 여러 프로그램이 고칠 때**: 잠금 파일(`.목록` `.여행정보` `.장소` `.작업이력` `.원고` `작업함/.상태` `로그/.로그`) + 임시 파일→교체(원자적 쓰기). Windows에서 잠금·교체 중 `PermissionError`는 '사용 중'으로 보고 짧게 재시도. 잠깐 못 읽은 파일을 빈 값으로 덮어쓰지 않는다. 도구 스크립트는 쓰기 직전에 다시 읽어 **`사용자결정`은 절대 덮어쓰지 않는다.**
9. **설정 파일은 바꾼 키만 합쳐 저장**(모르는 키 보존). 도구 전용 설정은 `도구/도구설정.json`.
10. **명령은 Bash 도구로, 권한 규칙과 같은 글자 형태로**(`python 도구/대기.py`처럼 상대 경로·슬래시·따옴표 없이). 처음 승인 창에서 '항상 허용'을 고르면 다음부터 묻지 않는다.

## 2. 데이터 파일

### 2.1 `여행정보.json`
```json
{"여행ID":"2026-09_제주","이름":"제주 2박3일","원본폴더":["D:/사진/제주여행"],
 "기간":{"시작":"2026-09-26","끝":"2026-09-28"},"시간대":"+09:00","하루경계":"04:00",
 "기기보정초":{"카메라":4020},"컨셉":"","선택한구성안":null,"숨길장소":["숙소"]}
```
- `기기`는 원본 하위 폴더 이름(없으면 EXIF 제조사·모델). `기기보정초`는 **목록에서만** 더함(원본 불변). `하루경계` 기본 04:00(사용자 확인).
- 숨김: 도구는 `장소.json`의 `숨김`과 `숨길장소`(이름) **둘 다** 본다. 숙소로 보이는 장소(저녁·아침에 같은 곳)는 **확인 전까지 지도에서 빼고 이름 조회(역지오코딩)도 하지 않는다**(위치를 밖으로 보내지 않음).

### 2.2 `목록.json` 항목
```json
{"id":"p0001","원본":"D:/…/IMG_1234.HEIC","종류":"사진","기기":"아이폰","모델":"Apple iPhone 15",
 "기록시각":"2026-09-26T10:12:03","시각출처":"EXIF+Offset","보정초":0,"촬영시각":"2026-09-26T10:12:03+09:00",
 "일차":1,"GPS":{"위도":33.394,"경도":126.239},"장소ID":"L02","영상길이초":null,
 "미리보기":"작업/미리보기/p0001.jpg","썸네일":"작업/썸네일/p0001.jpg",
 "점수":{"선명도":182.4,"선명도_묶음비":0.93,"눈감음":null,"연사묶음":"B02"},
 "판정":{"제외후보":false,"사유":[],"대표후보":true},"사용자결정":"미정","장면설명":""}
```
- `시각출처`: `EXIF+Offset` / `EXIF`(시간대 없음→여행 시간대 가정) / `영상UTC`(→현지 변환) / `영상현지` / `파일명` / `파일수정시각` / `사용자`. 약한 출처는 GUI에 ⚠.
- `사용자결정`: `미정` / `사용` / `대표`(낱장 크게) / `제외`. **서버(화면)만 바꾼다.**
- 추가 필드(v2.1): `장소근거`(GPS/시간추정), `원본없음`, `판정.묶음베스트`, `점수.얼굴수·색감·밝기·대표점수`. Claude의 시트 판단은 `작업/판정_<번호>.json` → `작업함.py 판정`으로 합쳐 `장면설명`·`판정`에만 반영.
- `장소.json`: `{"L02":{"이름":"협재해변","확인됨":true,"중심":{…},"사진수":14,"숨김":false}}`. 역지오코딩 결과는 `확인됨:false` → 질문 카드로 확인.

### 2.3 `구성안.json`, `편목록.json`
```json
{"컨셉":"아이와 처음 간 제주, 느리게 걷기","안":[
 {"번호":1,"이름":"하루에 한 편씩","설명":"…","편":[{"편ID":"1일차","제목안":"…","범위":{"일차":[1]}},…],"좋은점":"…","아쉬운점":"…","추천":true}]}
```
- 사용자가 고르면 `편목록.json` = 선택한 안의 `편` 배열. 편ID는 파일 이름에 쓰므로 공백·특수문자 없이(`1일차`, `하이라이트`, `바다`).

### 2.4 `배치_<편ID>.json` (글 한 편 — 단체 블로그도 같은 형식)
```json
{"편ID":"1일차","제목":"제주 첫날, 협재 바다에 발 담그기","카테고리":"여행","태그":["제주여행"],"공개":"비공개",
 "블록":[
  {"종류":"본문","글":"…"},{"종류":"소제목","글":"협재해변"},
  {"종류":"사진","사진":["p0001"],"설명":"…","대표":true},
  {"종류":"그룹사진","방식":"콜라주","사진":["p0002","p0003"],"설명":""},
  {"종류":"영상","영상":"p0100","설명":""},{"종류":"지도","이미지":"작업/지도/1일차.png"},
  {"종류":"장소","장소":["협재해변","오설록 티뮤지엄"]},{"종류":"인용구","글":"…","출처":""},
  {"종류":"꿀팁","글":"…"},{"종류":"구분선"},{"종류":"참고자료","목록":["…"]}],
 "AI활용표시":false,"승인":{"상태":"미승인","승인자":"","시각":""}}
```
- **배치 규칙**: `대표`는 `사진` 블록 1장씩. 나머지는 `그룹사진`(콜라주·슬라이드, **한 묶음 10장 이하** — 넘으면 멈춤, `--나누기`로만 자동 분할). `장소` 블록 5곳 이하.
- `AI활용표시`: 네이버 'AI 활용 설정'은 **AI로 만들거나 바꾼 이미지·영상이 있을 때만** true. 네이버 스위치는 사진·영상마다 있어서(2026-10-08 실측) 확장은 누르지 않고, true 면 임시저장 뒤 "AI 사진·영상마다 직접 켜기"를 '주의'로 알림. 글을 AI 도움으로 쓴 사실은 별도로 **글 끝 AI 사용 문구**(기본 포함). 여행 블로그(실제 사진)는 기본 false, 단체 블로그에 AI 삽화가 있으면 true. 글 끝 `참고자료` 블록 권장.
- `승인`: 사람이 미리보기에서 [이 글 승인]을 누르면 `승인됨`. 패키지는 만들 때 승인 상태를 복사하고, 패키지가 최신이면 이후 승인·취소도 패키지에 반영. 자동 예약 발행(9절)은 `승인됨`인 글만, 그리고 누르기 직전에 서버가 다시 확인.

### 2.5 `발행/패키지_<편ID>.json`
- 배치 + 업로드 사본 경로. 업로드 사본: EXIF 회전 반영 → 장변 2048px JPG(품질 85) → **GPS·기기 정보 제거** → 영문 파일명(`d1_03_p0001.jpg`) → 그룹 폴더 → 10MB 넘으면 `업로드묶음` 번호로 나눔. **동영상 사본**(`작업/업로드사본/<id>.mp4`, 위치·기기 메타 제거 후 다시 읽어 확인)도 패키지 블록으로 들어가 확장이 '동영상'으로 올림(v2.1, 2026-10-08 실측 — 2개를 한 번에 올리면 본문에 동영상 2개, 네이버 업로더에서 제목 필수).
- 형식·묶음 계산은 **`공용/발행묶음_API.md` v1**과 `공용/발행서버.py`의 `build_bundles()`가 기준(직접 구현 금지, import해서 사용).
- 패키지를 만들기 전에 **누수 점검**: 원고에 `[S숫자]`, "내부용", "발행 금지", "예상 반론" 같은 내부 표시가 남아 있으면 멈춘다.

### 2.6 `작업이력.json` (재시도·이어하기)
```json
[{"작업ID":"t20261007_1012_글쓰기_1일차","종류":"글쓰기","편ID":"1일차","상태":"실패",
  "단계":[{"이름":"초안","상태":"완료","산출물":"원고/1일차.md"},
          {"이름":"검수","상태":"완료","산출물":"원고/1일차_검수.md"},
          {"이름":"미리보기","상태":"실패","오류":"…","로그":"로그/2026-10-07.log#L120"}],
  "재시도":"가능","시작":"…","끝":"…"}]
```
- 작업 상태 `진행중`/`성공`/`실패`/`멈춤`(+`재시도횟수`), 단계 상태 `진행중`/`완료`/`실패`/`건너뜀`. 작업ID 모양: 도구·Claude 작업 `t…`, 발행 작업 `n…`(필드 `출처: 발행`, `발행상태`). 도구는 `--작업ID <id>`로 실패한 단계부터 이어서.
- 각 단계가 끝날 때마다 산출물을 저장하고 기록한다. **재시도는 실패한 단계부터**(앞 단계 산출물 재사용 → 토큰 절약). `재시도`: `가능` / `불가(이유)`. [처음부터 다시]는 기존 산출물을 `처리완료/보관/`으로 옮긴 뒤 시작.
- 오류가 나면 그 작업을 **자동으로 멈추고** 상태를 `실패`로, GUI에 [다시 시도]·[처음부터]·[로그 보기]를 보여 준다. 수리 프롬프트 카드: "로그/오늘.log의 마지막 오류를 분석해서 원인을 찾고 고친 다음 그 단계부터 다시 실행해줘".

## 3. GUI ↔ Claude 다리 (작업함)

| 방향 | 위치 | 내용 |
|---|---|---|
| GUI → Claude | `작업함/요청/<시각>_<종류>.json` | `{"id","종류","여행ID","내용":{…},"보낸시각"}` 종류: `목록만들기` `시계확인` `고르기` `구성안` `지도` `꿀팁인터뷰` `글쓰기` `수정요청` `임시저장` `재시도` `영상` `자유요청` |
| Claude → GUI | `작업함/질문/<id>.json` | `{"id","여행ID","제목","설명","사진":[ids],"선택지":[…],"여러개선택":false,"입력칸":true,"관련요청","보낸시각"}` |
| GUI → Claude | `작업함/답변/<질문id>.json` | `{"질문id","선택":[…],"입력":"…","보낸시각"}` |
| Claude → GUI | `작업함/상태.json` | `{"연결":{"마지막신호"},"진행":[{"요청id","작업ID","단계","메시지","퍼센트","상태","갱신"}],"알림":[…]}` 진행 `상태`: `진행중`/`완료`/`멈춤`/`실패` |

- 요청 `내용` 모양: `글쓰기 {편ID}`, `수정요청 {편ID, 블록번호?, 글}`, `임시저장 {편ID, 패키지만:true}`(**패키지까지만** — 발행 작업 만들기·브라우저 열기는 사람이 ⑦[네이버 임시저장]), `재시도 {작업ID, 처음부터:false}`, `영상 {목표초, 음악파일?}`(소재가 모자라면 제안 길이로 자동, 직접 주면 그대로; 결과 `작업/영상/`), `구성안 {글?}`, `지도 {장소수정?}`, `자유요청 {글}`, 나머지 `{}`.
- **`도구/대기.py`**: 3초마다 연결 신호 갱신, `요청/`·`답변/`에 새 파일이 오면 내용 출력 후 **종료**, 50분 무소식이면 `시간초과` 출력 후 종료. 새로 켠 대기.py가 이전 것을 물러나게 함(교대).
- **Claude 루프**(`studio-connect` 스킬): 대기.py를 **백그라운드로 실행** → 종료 알림으로 깨어나 처리 → 진행 갱신 → **처리 후 반드시 다시 대기**. (데스크탑 앱에서 실측 성공: 2026-10-07)
- **명령 백업**: 감시가 꺼져 있을 때 사용자가 Code 탭에 "스튜디오 요청 처리해줘" → Claude가 `python 도구/대기.py --한번`(쌓인 요청만 확인, 연결 신호는 갱신하지 않음)으로 처리.
- 연결 표시: 신호 10초 안 = 🟢 연결됨(점+글자) / `진행`에 `진행중` 항목이 10분 안 갱신 = 🟡 작업 중 / 그 밖 = 🔴 연결 안 됨 + [Claude 연결하기] → `claude://code/new?q=여행 스튜디오 연결해줘&folder=<절대경로>`(URL 인코딩, 앱이 폴더 확인 창을 띄움). 안 되면 "Code 탭에서 이 폴더를 열고 '여행 스튜디오 연결해줘'" 안내.

## 7. 이 폴더 `CLAUDE.md` 규칙 (요약)

- 원본은 읽기만. 사진은 콘택트 시트로 본다.
- 애매하면 질문 카드(썸네일 포함, 선택지 우선, 한 번에 3개 이하).
- 사진 속 사람의 이름·관계를 추측하지 않는다. 장소 이름은 확인 전 '추정'.
- 꿀팁은 사용자가 말한 것만 `꿀팁노트.md`에(날짜·여행), 새 글을 쓸 때 관련 꿀팁을 먼저 제안.
- 숙소·집 위치는 지도·글에서 뺀다. 타인·아이 얼굴이 크게 나온 사진은 대표로 고르기 전에 묻는다.
- 검수에서 지적된 **문장만** 고친다(전체 재작성 금지). 근거가 부족하면 그 부분만 보강 조사.
- 모든 단계는 `작업이력.json`과 `로그/`에 남긴다. 오류는 멈추고 보고.
- 네이버 로그인·발행은 사람. 자동 예약 발행은 설정이 켜져 있고 `승인됨`인 글만.

## 8. 네이버 연동 — 블로그 도우미 확장 (기본 경로)

- **준비(1회)**: 사람이 자기 **Chrome 또는 Edge**에서 네이버에 로그인(로그인 상태 유지). 확장을 개발자 모드로 설치. 여행 스튜디오 ⑦[확장 연결] 또는 단체 블로그 `python 도구/발행서버.py --연결만`(패키지 없이 연결만 하는 모드)이 보여 주는 **연결 코드**(6자리·5분·한 번)를 확장 팝업에 입력 → 확장이 토큰을 받아 저장. 이후 모든 `/api/발행/*`는 헤더 `X-Blog-Helper-Token` 필수(없으면 401).
- **발행 작업(job) 흐름**:
  1. `POST /api/발행/작업 {여행ID|패키지경로, 편ID, 모드:"임시저장"|"예약발행", 예약시각?}` → 작업 생성(`대기`).
  2. 서버(또는 Claude)가 사람의 Chrome으로 블로그 글쓰기 주소를 연다(OS 기본 방식으로 Chrome 실행).
  3. 확장이 `GET /api/발행/대기작업`으로 작업을 받아 **채우기**: 제목 → 블록 순서대로(소제목·본문·인용구는 에디터 글 유형, 사진 묶음 업로드 후 그룹 사진 방식 선택, 장소 멀티 첨부 5곳씩, 구분선) → 태그 → 카테고리(**블로그 카테고리 이름과 정확히 일치** — 공개 카테고리 목록과 대조) → 공개 설정 → 'AI활용'(스위치는 누르지 않음 — `AI활용표시` true 면 사람이 사진·영상마다 켜도록 '주의') → **'저장'(임시저장)**.
  4. 단계마다 `POST /api/발행/결과 {작업ID, 단계, 상태, 메시지}` 보고 → GUI·Claude가 표시. 실패한 단계에서 **멈춤**(추측 클릭 금지), 재시도는 그 단계부터.
- **[다시 시도](실패한 단계부터)는 채우던 같은 화면에서**: 서버는 새 글쓰기 화면을 열지 않고 "패널의 [작업 확인]"을 안내. 새 화면은 [처음부터]·시작 전 작업만.
- 확장은 작업을 받을 때 **단계 계획을 고정**(채우는 도중 패키지를 바꾸면 반영 안 됨 → [처음부터]). Chrome과 Edge에 같은 확장 폴더를 넣으면 연결 목록에는 한 줄로 보인다.
- **공통 설정 키**(여행 스튜디오 `설정.json` = 단체 블로그 `블로그설정.json`): `블로그ID`, `브라우저`(chrome/edge/default), `자동예약발행`(false), `편사이간격분`(10), `예약최소여유분`(15), `중단판정분`(10).
- **하지 않는 것**: 로그인·비밀번호 입력, 캡차 우회, 여러 편 연달아 빠르게 올리기(한 번에 한 편, 다음 편까지 간격), 기본 모드에서 '발행' 클릭.
- 선택자는 `selectors.js` 한 곳에 모은다(네이버 화면이 바뀌면 여기만 고침 — Claude Code에게 "확장 선택자를 지금 화면에 맞게 고쳐줘").
- 보조(선택): Claude in Chrome이 네이버를 열 수 있는 환경이면, 확장이 막힌 단계를 화면을 보며 진단하는 데 쓸 수 있다(네이버 차단 보고가 있어 기본 경로 아님).

## 9. (선택) 자동 예약 발행

- 설정 `자동예약발행: true`(기본 false)이고, 글이 `승인됨`일 때만. 확장이 발행 설정 창에서 '예약'을 고르고 시각을 넣은 뒤, 누르기 직전 서버에 `확인누름`을 보고 → 서버가 **지금 조건**(설정·승인·여유 시간)으로 다시 확인해 허락할 때만 발행을 누른다. 누른 뒤 멈추면 '네이버 예약 목록을 확인'하라고 알린다.
- 켜기 전에 반드시 안내: 네이버 약관은 허락 없는 자동화 게시를 금지하며 아이디 보호조치·검색 누락 위험이 있다. 한 계정에 하루 여러 편을 자동으로 몰지 않는다.
