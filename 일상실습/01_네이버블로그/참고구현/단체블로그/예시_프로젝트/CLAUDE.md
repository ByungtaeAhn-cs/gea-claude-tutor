# 교진추 블로그 운영 규칙 (예시)

> 이 파일은 **예시**입니다. 3회차에 학습자가 자기 단체 블로그에 맞게 직접 만듭니다. 교과서진화론개정추진회(교진추) 블로그를 가정해 썼으며, 실제 운영 규칙은 단체 담당자가 정합니다.
> Claude는 이 폴더에서 블로그 일을 할 때 이 규칙을 먼저 읽고 따릅니다.

## 1. 블로그 정보
- 블로그: (사)교과서진화론개정추진회 공식 네이버 블로그 `blog.naver.com/str_bg`
- 독자: 중·고등학교 교사, 학부모, 교회 교육 담당자, 과학에 관심 있는 고등학생·대학생
- 발행: 주 1편 안팎(자료실 위주), 칼럼은 필자 일정대로. **정확히 같은 간격을 고집하지 않습니다**(네이버는 기계적인 일정한 간격을 오히려 의심할 수 있다고 밝힘).
- 카테고리: 교진추 소개 / 자료실(우주 진화·화학적 진화·생물학적 진화·지질학적 진화·인류의 진화·일반자료) / 교과서 청원 자료 / 추천 동영상 / 칼럼(필자별) / 도서 소개 / 뉴스레터 / 교사 참고자료
- 담당: 원고 확인·발행 = 사무국 담당자(사람). Claude = 자료조사·초안·팩트체크·이미지·미리보기·임시저장

## 2. 톤
- 정중한 설명체(~습니다). 문단은 3~5문장, 소제목 3~5개.
- 주장은 분명하게, 근거는 구체적으로(누가·언제·어디서). 감정적 표현보다 사실을 앞세웁니다.
- **설교조 금지**: 훈계, "~해야 합니다"의 반복, 성경 구절로 과학 논증을 대신하기를 하지 않습니다. 신앙적 결론이 필요하면 마무리에서 한두 문장으로 담백하게.
- 어려운 말은 처음 나올 때 괄호로 풀이합니다. 예: 상동기관(겉모양은 달라도 구조와 기원이 같다고 보는 기관).
- 비꼬기·조롱·인신공격을 하지 않습니다. 상대 학자·교사·출판사를 깎아내리지 않고 **주장과 근거**를 다룹니다.

## 3. 신학 테두리
- 정통 개혁주의 신앙고백 안에서 씁니다. 창조주 하나님과 성경의 권위를 전제합니다.
- 교진추의 관점(교과서 속 진화론 오류 지적, 반진화론·창조과학)을 **적극적으로** 살립니다.
- 다만 과학적 사실·인용·숫자는 **1차 출처와 대조해 정확히** 씁니다. 정확성이 단체의 신뢰입니다.
- 다른 교단·신학 입장(유신진화론 등)을 다룰 때는 그 입장의 원문을 정확히 인용한 뒤 비판합니다.

## 4. 금지 표현
| 쓰지 않는 표현 | 이유 · 대신 |
|---|---|
| "사기극", "조작", "날조"를 출처 없이 | 1차 출처가 그 말을 썼을 때만, **누가 어디서 쓴 말인지** 밝혀서. 예: Science 1997년 뉴스 기사 제목은 "fraud"라고 표현했다 |
| "과학계가 공식적으로 인정했다", "학계 정설이 뒤집혔다" | 근거 문서(성명·논문)가 있을 때만, 그 문서를 인용 |
| "모든 교과서", "아직도 실려 있다" | 교과서 실물(출판사·연도·쪽)을 확인한 범위에서만 |
| 확인 안 된 '동료심사를 거친' | 창조과학 학술지는 이름·저자·연도를 정확히. 심사 방식 수식어는 확인한 경우에만 |
| "진화론자들은 ~" 같은 뭉뚱그리기 | 특정 저자·문헌을 지목 |
| 낚시성 제목, 같은 키워드 반복 | 네이버 검색 가이드가 스팸 유형으로 봄 |

## 5. 출처 표기
- 글 끝에 **"참고한 자료"** 소제목을 두고 번호 없이 나열합니다.
  - 논문: 저자 (연도). 제목. *학술지* 권(호): 쪽. https://doi.org/…
  - 뉴스 기사·독자 서한: 위 형식 + [뉴스 기사] / [독자 서한]처럼 글 종류 표시
  - 책: 저자 (연도). 『제목』. 출판사. 인용한 쪽
  - 옛 문헌: 저자 (연도). 『제목』(판차). 도판 번호. 디지털 원본 주소
  - 교과서: 출판사 (연도). 『과목』. 쪽
  - 단체 자료: 교과서진화론개정추진회 (연도). 「문서명」.
  - 창조과학 학술지: 학술지 이름 그대로(DOI가 없으면 학술지 누리집 주소)
- 본문 인용은 원문 그대로 짧게 + 우리말 뜻 + (저자, 연도, 쪽). 길게 옮기지 않습니다(저작권법 제28조 인용 범위).
- 사진 출처는 "참고한 자료" 다음에 **"사진 출처"** 로(출처대장의 표기문구).

## 6. AI 사용 표기 (모든 글 끝에 그대로)
> 이 글은 AI(Claude)의 도움을 받아 자료를 조사하고 초안을 작성한 뒤, 담당자가 사실을 확인하고 다듬었습니다.

- AI로 변환한 이미지가 있으면 캡션에 "AI로 삽화풍 변환한 이미지"를 붙이고, 발행할 때 네이버 'AI 활용' 설정을 켭니다.

## 7. 사진·인물 규칙
- 모든 이미지는 `출처대장.csv`에 기록합니다. 라이선스: CC0·퍼블릭 도메인·CC BY·Pexels·Pixabay·공공누리 1유형. **NC(비영리 한정)는 쓰지 않습니다**(후원 링크가 있으므로 상업 이용으로 봄).
- 교과서 지면 사진은 인용에 필요한 부분만, 출판사·연도·쪽을 밝혀서.
- 행사 사진 속 사람: `사진동의대장.xlsx`에서 게시 동의를 확인합니다. **만 14세 미만은 보호자 동의**. 동의 확인 전에는 외부 AI(삽화 변환)에 올리지 않습니다.
- 동의가 없으면 뒷모습·손·원경처럼 알아볼 수 없는 사진만 씁니다.
- AI가 넣은 출처 정보(C2PA·워터마크)를 지우지 않습니다.

## 8. 글 쓰는 규칙 (모든 스킬 공통)
- **단체 입장 문장**("교진추는 ~라고 봅니다", "앞으로 ~하겠습니다")은 이 파일이나 `자료/`의 단체 자료에 근거가 있을 때만 씁니다. 없으면 `[담당자 확인: 단체 입장]`을 붙여 두고, 담당자가 승인한 뒤 표시를 지웁니다(표시가 남으면 발행 패키지가 만들어지지 않음).
- **부분 수정**: 팩트체크·검수·담당자 지적은 **해당 문장만** 고칩니다. 글 전체를 다시 쓰지 않습니다. 근거가 부족한 주장은 그 주장만 보강 조사합니다.
- **인용**: 따옴표 안은 원문 그대로, 번역은 따옴표 없이. 줄였으면 "…".

## 9. 작업 순서·이력·재시도
- 한 편은 이 순서로 만듭니다: **자료조사(blog-research) → 초안(blog-writer) → 팩트체크(blog-factcheck) → 다듬기(blog-polish) → 이미지(blog-image) → 미리보기 → 패키지 → 임시저장(naver-draft)**.
- 단계마다 산출물을 글 폴더에 저장하고 `도구/작업이력.py`로 `작업이력.json`에 기록합니다. 모든 기록은 `로그/YYYY-MM-DD.log`에도 남습니다.
- 오류가 나면 **멈추고** 그 단계를 '실패'로 기록한 뒤 보고합니다. 다시 할 때는 `작업이력.py 이어하기`가 알려 주는 단계부터(앞 단계 산출물을 다시 만들지 않음). 단, 고치느라 앞 단계 산출물(예: 원고)을 바꿨다면 그 다음 단계(예: 미리보기)부터 다시 합니다. 막히면 `수리프롬프트_카드.md`의 문장을 씁니다.
- 검증 깊이는 `주제판.md`의 **카테고리 설정**(검증 수준 엄격/보통/가벼움)을 따릅니다.

## 10. 발행 규칙
- 네이버 연동은 **블로그 도우미 확장**(Chrome 또는 Edge에 설치)이 합니다. 로그인·확장 연결 코드 입력·'발행'은 담당자가 합니다. Claude는 발행서버를 켜고 작업을 만들고 결과를 보고합니다(naver-draft).
- 기본은 **임시저장**. 자동 예약 발행은 `블로그설정.json`의 `자동예약발행: true` + 글 `승인됨` + 담당자의 이번 지시가 모두 있을 때만.
- 한 번에 한 편. 발행 전 팩트체크 판정표의 ❌·확인 못 함이 0인지(또는 담당자가 처리 방법을 정했는지) 확인합니다.
- `예상반론메모_*.md`는 **내부용**입니다. 블로그·소식지·SNS에 싣지 않습니다.
- 발행 후 `발행기록.md`에 날짜·제목·주소·카테고리를 한 줄 남깁니다.

## 11. 폴더 규칙
```
교진추블로그/
├── CLAUDE.md               # 이 파일
├── 블로그설정.json          # 블로그ID, 브라우저(chrome/edge/default), 자동예약발행(기본 false)
├── 주제판.md                # 카테고리 설정 + 주제 목록
├── 발행기록.md · 수리프롬프트_카드.md
├── 자료/                    # 단체 자료(소식지·청원서·강의안). 외부 검색어에 내용을 넣지 않음
├── 기준예시/                # 우리 블로그의 잘 쓴 글 1~2편(작가·다듬기 스킬이 말투를 맞춤)
├── 도구/                    # 미리보기.py, 템플릿.html, 작업이력.py, 발행서버.py, AI삽화.py(선택)
├── 로그/                    # YYYY-MM-DD.log (git 제외 권장)
├── .claude/skills/          # blog-research · blog-writer · blog-factcheck · blog-polish · blog-image · naver-draft
└── 글/YYYY-MM-DD_주제/      # 한 편마다 한 폴더
    ├── 작업이력.json
    ├── 자료조사_주제.md · 원고_주제.md · 배치_주제.json · 고친목록_주제.md
    ├── 팩트체크_주제.md · 예상반론메모_주제.md (내부용) · 다듬기대조_주제.md
    ├── 이미지/ · 출처대장.csv · 배치_주제_미리보기.html
    └── 발행/ 패키지_주제.json, 사진묶음_주제/
```

## 12. 도구 위치·설정
- 도구: `도구/미리보기.py`, `도구/작업이력.py`, `도구/발행서버.py`(블로그 도우미 확장용 로컬 서버), `도구/AI삽화.py`(선택, ChatGPT Plus + Codex CLI 로그인 필요)
- `블로그설정.json`: `{"블로그ID": "str_bg", "브라우저": "chrome", "자동예약발행": false, "편사이간격분": 30}` — `브라우저`는 **확장을 설치한 브라우저**(chrome/edge), 또는 default(PC 기본 브라우저)
- 연락처 이메일(Crossref·위키미디어 요청 예절): 환경변수 `BLOG_CONTACT_EMAIL`(단체 공용 주소). 파일에 적지 않습니다.
- 무료 사진 API 키: 환경변수 `PEXELS_API_KEY`, `PIXABAY_API_KEY`(있을 때만). **이 폴더에 키를 저장하지 않습니다.**
- PDF·HWP 읽기용 패키지(`pypdf`, `olefile`)는 프로젝트 가상환경 `.venv`에 설치합니다(전역 설치 안 함).
