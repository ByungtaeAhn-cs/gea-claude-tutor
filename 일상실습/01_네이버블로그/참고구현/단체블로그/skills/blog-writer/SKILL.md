# blog-writer — 원고 + 배치 JSON

대상: $ARGUMENTS

출처 카드를 바탕으로 **우리 단체 목소리**로 글을 씁니다. 결과물은 두 개입니다.
- `원고_<주제>.md` — 사람이 읽고 고치는 **원본**. 사실 문장마다 출처 카드 번호([S1])가 붙어 있어 팩트체크가 추적합니다.
- `배치_<주제>.json` — 네이버 에디터에 넣을 **블록 순서표**. 미리보기·발행 패키지·블로그 도우미 확장이 이 파일을 씁니다(여행 블로그와 같은 형식, 아래 '배치 JSON 형식').

**원고가 원본입니다.** 고칠 때는 원고를 고치고 배치 JSON을 다시 만듭니다. 배치 JSON 글에는 카드 번호를 넣지 않습니다.

## 먼저 읽을 것
1. 프로젝트 `CLAUDE.md` — 톤, 금지 표현, 신학 테두리, AI 사용 표기 문구, 출처 표기 형식, 사진·인물 규칙, 폴더·도구 위치
2. `주제판.md`의 **카테고리 설정** — 이 글 카테고리의 정확한 블로그 카테고리 이름, 발행 목적, 검색 키워드, 검증 수준
3. `기준예시/`의 글 1~2편 — 길이, 문단 길이, 소제목 수, 말투, 마무리 방식
4. `자료조사_<주제>.md` — 없으면 멈추고 "blog-research부터 할까요?"라고 묻습니다

## 입력
- 처음 쓸 때: 주제, 자료조사 파일, (있으면) 담당자의 분량·강조점
- 고칠 때: **지적 목록**(팩트체크 판정표의 ❌·⚠️, reviewer 검수표, 담당자 메모) — 번호와 위치가 있어야 합니다

## 작업 이력
글 폴더의 `작업이력.json`에 남깁니다(도구 위치는 CLAUDE.md):
```
python "<도구>/작업이력.py" 단계 --폴더 "<글 폴더>" --이름 초안 --상태 진행중
python "<도구>/작업이력.py" 단계 --폴더 "<글 폴더>" --이름 초안 --상태 완료 --산출물 원고_<주제>.md 배치_<주제>.json
```
오류가 나면 `--상태 실패 --오류 "…"`로 남기고 멈춥니다. 다시 할 때는 `이어하기`가 알려 주는 단계부터(자료조사 결과는 다시 만들지 않음).

## 단계 — 처음 쓸 때

### 1. 글 설계 보여 주기
- 독자의 질문 → 글의 **한 줄 요지** → 소제목 3~5개 → 소제목마다 쓸 출처 카드 번호 → 사진 자리.
- **단체 자료를 거쳐 온 인용·숫자**(칼럼·청원서가 다른 문헌을 인용한 것)는 설계표에 "팩트체크 우선 확인"으로 표시합니다(1차 리허설에서 가장 많이 틀린 곳).
- 표 하나로 보여 주고 "이 순서로 쓸까요?"라고 묻습니다. "알아서"라고 했으면 바로 씁니다.

### 2. 원고 쓰기
- **사실 문장에는 카드 번호**: "1997년 Richardson 연구팀은 … [S2]". 카드에 없는 사실은 쓰지 않습니다. 필요하면 자료조사로 돌아갑니다.
- 한 문장의 근거가 둘이면 둘 다 붙입니다(예: 그림 실물에서 본 것 [S1] + 논문 결론 [S2]).
- **단체 입장 문장**("교진추는 ~라고 봅니다", "앞으로 ~하겠습니다")은 CLAUDE.md나 단체 자료 카드에 근거가 있을 때만 씁니다. 근거가 없으면 쓰지 않거나, 원고에 `[담당자 확인: 단체 입장]`을 붙여 두고 담당자가 승인한 뒤에만 남깁니다(이 표시는 누수 점검에 걸려 승인 전에는 발행 패키지가 만들어지지 않습니다).
- **인용과 번역**: 따옴표 안에는 **원문 그대로**(영어면 영어)를 씁니다. 우리말 뜻은 따옴표 없이 풀어 씁니다. 예: 리처드슨은 1874년 그림이 상당 부분 지어낸 것("substantially fabricated")이라고 썼습니다. 번역문에 따옴표를 붙이면 원문처럼 보입니다.
- **인용구 블록**은 원문 문장 전체를 쓰거나, 줄였으면 "…"로 표시합니다. 출처(저자, 연도, 학술지 권: 쪽)를 붙입니다.
- **확인한 범위만큼만 단정**: 초록만 봤다면 "초록에는 없다", 본문을 봤다면 "논문에 없다". 연구팀의 자체 평가는 "연구팀은 ~라고 결론지었다"로 쓰고, 학계 전체의 평가처럼 쓰지 않습니다.
- **시간 순서 점검**: 연도가 둘 이상 나오는 문장은 앞뒤가 맞는지 봅니다(예: 1874년 책의 그림이 1868년부터 의심받았다 → 시간이 맞지 않음. '초기 그림'인지 밝힘).
- **단체 관점은 분명하게, 단정 어휘는 근거만큼만**: '사기·조작·폐기·공식 선언'은 1차 출처가 그 말을 썼을 때만, 누가 어디서 쓴 말인지 밝혀서.
- **설교조 금지**: 훈계, "~해야 합니다"의 반복, 성경 구절로 논증을 대신하기를 피합니다.
- **쉬운 말**: 전문 용어는 처음 나올 때 괄호로 풀이합니다. 예: 양막류(파충류·조류·포유류처럼 양막에 싸여 발생하는 동물), 양식화(실제 모습이 아니라 정해진 틀에 맞춰 단순하게 그림).
- **사진 자리**: "무엇을 보여 줄지"를 구체적으로 + 캡션 초안.
- **제목 후보 3개**: 정보형 / 질문형 / 핵심 사실형. 낚시성 금지.
- **마무리**: 요지 2~3문장. 단체 활동 안내·다짐은 위의 '단체 입장 문장' 규칙을 따릅니다.
- **참고 자료**: 글 끝 `참고자료` 블록(CLAUDE.md 형식: 저자 (연도). 제목. 학술지 권(호): 쪽. DOI 링크 + 뉴스·서한은 [뉴스 기사]·[독자 서한]).
- **AI 사용 표기**: CLAUDE.md 문구를 그대로 글 끝에.
- **태그**: 30개 이하(보통 8~15개). 카테고리 설정의 검색 키워드를 참고하되 같은 말 반복 금지.

### 3. 배치 JSON 만들기 — 형식 (이 스킬 안에서 완결)

**맨 위 키**
| 키 | 값 | 비고 |
|---|---|---|
| `편ID` | 글 폴더·파일 이름에 쓰는 짧은 이름(공백·특수문자 없이) | 예: `헤켈배아` |
| `제목` | 고른 제목 | |
| `제목후보` | 문자열 3개 | 미리보기 점검판에만 보임 |
| `카테고리` | **블로그의 실제 카테고리 이름과 글자까지 같게**(주제판의 카테고리 설정) | 확장이 이 이름으로 고름 |
| `태그` | 문자열 목록(30개 이하) | |
| `공개` | `전체공개` / `이웃공개` / `서로이웃공개` / `비공개` | 처음 몇 편은 `비공개` 권장 |
| `블록` | 아래 블록 목록(순서 = 글 순서) | |
| `AI활용표시` | `true` / `false` | AI로 만들거나 변환한 **이미지·영상**이 있으면 `true` → 확장이 임시저장 뒤 "그 사진·영상마다 'AI 활용 설정'을 켜세요"라고 알림(네이버 설정은 사진·영상마다 있어 사람이 켬, `true` 인 글은 예약 발행 안 됨). 글만 AI 도움을 받았으면 본문 AI 사용 표기로 충분(네이버 도움말 기준). 단체가 다르게 정했으면 CLAUDE.md를 따름 |
| `승인` | `{"상태":"미승인","승인자":"","시각":""}` | 처음엔 늘 `미승인`. 담당자가 미리보기를 보고 승인하면 `승인됨`·승인자(직책)·시각을 채움. 자동 예약 발행은 `승인됨`만 |

**블록 종류**
| 종류 | 키 | 비고 |
|---|---|---|
| `본문` | `글`, (선택) `역할`: `출처`·`AI표기` | 문단 사이는 `\n\n`, 굵게는 `**…**` |
| `소제목` | `글` | |
| `인용구` | `글`, `출처` | 원문 전체 문장 또는 "…" |
| `사진` | `사진`: [상대경로], `설명`, `대표` | 아직 파일이 없으면 `사진` 대신 `"자리": "무엇을 보여 줄지"` |
| `그룹사진` | `방식`: `콜라주`/`슬라이드`/`개별 사진`, `사진`: [..], `설명` | 한 묶음 10장 이하 |
| `영상` | `영상`, `제목`, `설명` | **`제목` 필수**: 40자 이하, 그 영상 내용(네이버 업로더가 제목을 꼭 받음 — 없으면 글 제목이 들어감, 2026-10-09 실측). 업로드 사본이 있으면 확장이 올리고, 없으면 사람이 '동영상' 버튼 |
| `지도` | `이미지` | |
| `장소` | `장소`: [이름..] | 한 블록 5곳 이하 |
| `꿀팁` | `글` | |
| `구분선` | — | |
| `참고자료` | `목록`: [문자열..] | 글 끝에 **하나만**. 참고 문헌 줄 다음에 `사진 출처: …` 줄을 이어 붙임. 별도 '참고한 자료' 소제목은 넣지 않음(확장이 '참고자료' 머리글을 붙임) |

### 4. 스스로 점검
- [ ] 소제목 3~5개, 제목 후보 3개, 태그 30개 이하, 카테고리 이름이 카테고리 설정과 같다
- [ ] 모든 사실 문장에 카드 번호가 있고, 카드에 없는 사실·단체 입장이 없다(있으면 `[담당자 확인: 단체 입장]`)
- [ ] 따옴표 안은 원문 그대로, 번역은 따옴표 없이. 인용구는 완결 문장이나 "…"
- [ ] 연도 순서가 맞다. 단정은 확인한 범위만큼
- [ ] 금지 표현·설교조가 없다
- [ ] 사진 자리마다 '무엇을 보여 줄지'와 캡션 초안이 있다
- [ ] 참고자료 블록·AI 사용 표기가 글 끝에 있다. `AI활용표시`·`승인` 키가 있다
- [ ] 원고와 배치 JSON의 문장이 같다(카드 번호만 빼고)

## 단계 — 고칠 때 (부분 수정 원칙)
1. **지적된 문장만 고칩니다.** 글 전체를 다시 쓰지 않습니다. 지적이 없는 문장은 글자 하나도 바꾸지 않습니다(흐름을 위해 앞뒤 접속어 하나 정도만 예외, 바꿨으면 보고).
2. 지적마다 [번호 · 위치 · 고치기 전 · 고친 뒤 · 근거 카드]를 표로 남깁니다(`고친목록_<주제>.md`).
3. **근거가 부족해서** 걸린 문장은 그 주장 하나만 blog-research로 보강 조사합니다(새 카드 번호 추가). 보강이 안 되면 그 문장을 빼거나 수위를 낮춥니다.
4. 원고 파일은 판을 남깁니다(예: `원고_<주제>_v2.md` → 확정본 `원고_<주제>.md`).
5. 배치 JSON을 다시 만들고, **바뀐 문장 목록**을 blog-factcheck에 넘겨 그 문장들만 다시 검증받습니다.

## 출력과 다음 단계
- `원고_<주제>.md`, `배치_<주제>.json`(+ 고칠 때 `고친목록_<주제>.md`)을 글 폴더에 저장하고, 설계표·점검 결과를 짧게 보고합니다.
- 다음: **blog-factcheck** → **blog-polish**(문장 다듬기) → **blog-image** → 미리보기 → 패키지 → **naver-draft**.

## 하지 않는 것
- 출처 카드에 없는 사실·숫자·인용·단체 입장을 새로 넣기
- 번역문에 따옴표를 붙여 원문처럼 보이게 하기, 인용을 줄이면서 "…" 없이 마침표로 닫기
- 지적받지 않은 문장까지 다시 쓰기
- 사람(특히 아이) 얼굴이 보이는 사진을 자리로 지정하면서 동의 확인을 빼먹기
- 네이버에 직접 올리기(임시저장은 naver-draft, 발행은 사람)

## 예시 — 고친 목록 한 줄
