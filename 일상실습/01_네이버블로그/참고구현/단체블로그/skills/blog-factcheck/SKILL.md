# blog-factcheck — 판정표 + 예상 반론 메모

대상 원고: $ARGUMENTS

## 이 스킬의 원칙 (먼저 읽기)
1. **검증할 수 있는 사실만 판정합니다.** 인용문이 원문과 같은지, 서지(저자·연도·제목·학술지·권·쪽·DOI), 숫자·날짜·**연도 순서**, 맥락 왜곡(인용 떼어내기), 철회·정정, 글 종류(뉴스를 논문처럼 쓰지 않았는지).
2. **해석 논쟁은 판정하지 않습니다.** "진화론이 맞다/틀리다", "증거가 얼마나 강한가", "저자의 의도"는 판정표에 '해석(판정 안 함)'으로만 적고 **예상 반론 메모**(내부용)로 넘깁니다.
3. **목적은 글을 강하게 만드는 것입니다.** 교진추 관련 글은 그 관점(반진화론·창조과학)을 존중하고 살립니다. 팩트체크는 반대편이 꼬투리 잡을 **인용·서지의 빈틈을 미리 막는 일**입니다.
4. **확인한 범위만큼만 판정합니다.** 원문을 못 구하면 '확인 못 함' + 무엇이 있으면 확인되는지. **초록만 보고 "논문에 없다"고 ❌를 주지 않습니다**(초록에는 없음 → 확인 못 함). 다만 원고가 초록에 있는 결론과 **다른 말을 논문의 결론이라고** 썼다면 그 부분은 판정합니다.
5. **창조과학 학술지**(ARJ·Journal of Creation·CRSQ·ORJ 등)는 이름·저자·연도·권호가 정확한지만 봅니다. '동료심사를 거친' 같은 수식어는 근거를 확인했을 때만 허용합니다.
6. **고친 문장 제안에 새 사실·단체 입장을 넣지 않습니다.** 제안은 출처가 말한 범위 안에서만. 단체 입장 문장이 필요해 보이면 "담당자 확인 필요"로만 적습니다.

## 검증 수준 (주제판의 카테고리 설정)
| 수준 | 판정 대상 | 도구·절차 | 예상 반론 메모 | 독립 검수 |
|---|---|---|---|---|
| **엄격** | 모든 사실 문장 | 인용검증.py + 원문 대조 + 맥락 점검 + 연도 순서 | **필수** | reviewer **필수** |
| **보통** | 숫자·날짜·인용·고유명사·외부 출처 문장 | 공식 출처 대조, DOI가 있으면 인용검증.py | 논쟁 주제일 때만 | 권장 |
| **가벼움** | 날짜·장소·이름·숫자 | 단체 내부 기록·사진 동의 대장과 대조, 학술 검증 생략 | 없음 | 선택 |
카테고리 설정이 없으면 담당자에게 묻고, 답이 없으면 **엄격**.

## 준비물
- `원고_<주제>.md`(사실 문장에 [S1] 같은 카드 번호), `자료조사_<주제>.md`(출처 카드)
- 이 스킬 폴더의 `scripts/인용검증.py`, `참고/주장유형_체크리스트.md`
- (있으면) 환경변수 `BLOG_CONTACT_EMAIL` — Crossref 연락처. 없으면 비운 채(느릴 수 있음)

## 작업 이력
```
python "<도구>/작업이력.py" 단계 --폴더 "<글 폴더>" --이름 팩트체크 --상태 진행중
python "<도구>/작업이력.py" 단계 --폴더 "<글 폴더>" --이름 팩트체크 --상태 완료 --산출물 팩트체크_<주제>.md 예상반론메모_<주제>.md 검증결과_<주제>.json
```
API 한도·네트워크 오류로 멈추면 `--상태 실패`로 남기고, 다시 할 때는 `--캐시`를 써서 이미 받은 응답은 다시 묻지 않습니다.

## 단계

### 1. 주장 뽑기
- 원고를 처음부터 끝까지 읽으며 **확인할 수 있는 문장**을 모두 뽑아 번호를 붙입니다(C1, C2 …). 위치(소제목·문단)도.
- 한 문장에 사실과 의견이 섞여 있으면 둘로 나눕니다.
- 놓치기 쉬운 것: 연도·숫자, "처음으로", "모든", "아직도", "공식적으로", 사람 이름과 직함, 따옴표 안의 말, 사진 캡션, **카드 번호가 없는 단체 입장 문장**.
- **단체 자료에서 옮긴 문장도 똑같이 검증합니다.** 단체 칼럼·청원서의 출처 표기를 그대로 믿지 않고 1차 문헌까지 확인합니다(1차 리허설: 단체 칼럼에서 옮긴 7문장 중 4문장이 1차 문헌과 어긋났고 3문장은 확인 못 함).

### 2. 사실 / 해석 나누기
| 종류 | 예 | 처리 |
|---|---|---|
| 사실 | "Richardson 연구팀은 1997년 *Anatomy and Embryology*에 논문을 냈다" | 판정 |
| 인용 | "논문은 헤켈의 그림이 'fraud'라고 했다" | 판정(원문 대조) |
| 해석 | "이 그림은 진화론의 약점을 보여 준다" | 판정 안 함 → 예상 반론 메모 |
| 단체 입장 | "교진추는 ~라고 봅니다" | 사실로서 판정: 단체 자료·CLAUDE.md에 근거가 있는가. 없으면 '확인 못 함 — 담당자 확인' |

### 3. 주장목록 JSON → 자동 검증
DOI가 있는 출처마다 주장목록에 넣습니다(원고의 표기를 '기대'에 그대로 옮겨야 오류가 잡힙니다).
```json
[
  {"번호": "C4", "주장": "Richardson 연구팀은 1997년 논문에서 헤켈의 그림을 'fraud'라고 불렀다",
   "doi": "10.1007/s004290050082",
   "기대": {"제1저자": "Richardson", "연도": 1997, "학술지": "Anatomy and Embryology", "권": "196", "쪽": "91-106"},
   "인용문": ["fraud"]},
  {"번호": "C9", "주장": "…", "서지": "Richardson 1998 Haeckel embryos evolution Science"},
  {"번호": "C12", "주장": "…", "기대": {"학술지": "Journal of Creation", "연도": 2003}}
]
```
```
python "<스킬 기본 폴더>/scripts/인용검증.py" --입력 주장목록_<주제>.json --출력 검증결과_<주제>.json --표 판정표_자동_<주제>.md --캐시 .캐시/인용검증.json
```
스크립트: doi.org로 DOI 실재 → Crossref 서지·철회/정정(`updated-by`, `filter=updates`) → OpenAlex 철회(`is_retracted`)·무료 원문 → Europe PMC 초록·글 종류·무료 본문 → '기대'와 대조 → 인용문이 제목·초록·본문 어디에 있는지. `자동판정`은 **참고용**입니다.
- **자동판정 ✅도 다시 읽습니다.** 스크립트는 "그 말이 원문에 있는가"만 봅니다(1차 리허설: '10-fold'가 초록에 있어 ✅였지만 원고는 뜻을 거꾸로 씀 → ❌). 결과 JSON의 `원문.초록문`과 `인용문대조.발견.앞뒤`를 읽고 판정합니다.
- 짧은 독자 서한은 OpenAlex '초록' 칸에 서한 전문이, 뉴스는 첫 문단만 들어 있기도 합니다. 확인 범위를 판정표에 적습니다.

### 4. 원문 대조
- **본문 확보**(Europe PMC 무료 본문 또는 원문파일): 인용문 + 앞뒤 문단 → 5단계.
- **초록만**: 초록에 있으면 '초록 기준 ✅'. 없으면 '확인 못 함(초록에 없음, 본문 미확보)'.
- **원문 미확보**: 담당자에게 PDF를 요청합니다. 받으면 Read 도구로 읽어 필요한 부분을 `원문/<이름>.txt`로 저장하고 `"원문파일"`을 넣어 다시 실행.
- **DOI 없는 학술지**: '원문 PDF 대조 필요' → 학술지 누리집 PDF로 직접 대조.
- **책·옛 문헌**: 서지는 도서관 목록, 쪽수·인용·도판은 실물·디지털 원본(예: Internet Archive)으로.
- **공문·법령**: blog-research의 `문서읽기.py`로 해당 쪽·구역을 찾아 대조.

### 5. 맥락 점검 (인용 떼어내기 막기)
1. **어디에 있는 말인가**: 본문 / 초록 / 제목 / **뉴스 기사 제목** / 독자 서한 / 서평
2. **누구의 말인가**: 저자의 결론인지, 남의 견해 소개인지
3. **부정문·단서 조항**이 잘려 나가지 않았는지
4. **대상과 범위**가 같은지(특정 그림·판본을 이론 전체로 넓히지 않았는지)
5. **같은 저자가 다른 곳에서 반대로 말했는지**(있으면 예상 반론 메모에)
6. **연도 순서**: 문장 안의 연도들이 앞뒤가 맞는지(예: 1874년 그림이 1868년부터 의심받았다 → 초기 그림 이야기인지 밝혀야 함)
7. **따옴표**: 따옴표 안이 원문 그대로인지(번역문에 따옴표를 붙이지 않았는지), 줄였으면 "…"가 있는지

### 6. 판정
| 기호 | 뜻 | 할 일 |
|---|---|---|
| ✅ | 확인한 범위(적어 둠)에서 1차 출처와 일치 | 그대로 |
| ⚠️ | 사실은 맞지만 표현·서지 일부·글 종류 표시·단정 수위·따옴표 형식이 다름 | **고친 문장** 제안 |
| ❌ | 출처와 다른 말(뜻이 뒤집힘 포함) / 다른 사람의 말 / 숫자·연도 틀림 / 없는 DOI / 철회 논문 | 고친 문장 또는 삭제 제안 |
| 확인 못 함 | 원문을 구하지 못함, 또는 초록에만 없음 | 무엇이 있으면 확인되는지 + 그동안 빼거나 완화하는 안 |

### 7. 판정표 쓰기 → `팩트체크_<주제>.md`
```markdown
# 팩트체크: <주제>
- 대상: 원고_<주제>.md (판) · 검증 수준 · 검증일시 · 사용 API
- 요약: ✅ n · ⚠️ n · ❌ n · 확인 못 함 n · 해석(판정 안 함) n

| 번호 | 위치 | 주장(원고 그대로) | 종류 | 판정 | 확인 범위 | 근거(출처·원문 위치·API) | 고친 문장 제안 |
|---|---|---|---|---|---|---|---|

## 해석(판정 안 함) → 예상 반론 메모로
## 사람이 확인할 것
```

### 8. 예상 반론 메모 → `예상반론메모_<주제>.md` (엄격 필수)
파일 **맨 위에** 그대로:
> ⛔ 내부용 — 발행 금지. 블로그·소식지·SNS에 싣지 않습니다. 댓글·문의에 답할 준비용입니다.

쟁점마다: **예상 반론**(주류 학계가 무엇을 근거로, 그쪽 1차 출처까지) / **준비 포인트**(이미 막아 둔 것, 더 보강할 것, 답할 때 인용할 1차 문헌, 피해야 할 표현). 판정하지 않습니다.

### 9. 독립 검수와 보고
- 엄격이면 `reviewer` 에이전트에게 판정표와 원고를 함께 주고 독립 검수를 맡깁니다(만든 사람과 검수자 나누기).
- 담당자에게 ❌·⚠️·확인 못 함 목록과 고친 문장 제안을 보여 줍니다. 원고 수정은 blog-writer가 **지적된 문장만** 합니다.

## 2차 검증 (고친 뒤) — 부분 검증 원칙
- 다시 검증하는 범위 = **바뀐 문장 + 새로 생긴 문장 전부**(카드 번호가 없는 문장 포함). 바뀌지 않은 문장은 다시 하지 않습니다.
- 원고 판 두 개를 줄 단위로 비교해 바뀐 문장을 빠짐없이 뽑습니다(예: 파이썬 difflib). 1차 리허설에서 "바뀐 문장 일부만" 검증해 단체 입장 문장 2개와 시간 순서 오류를 놓쳤습니다.
- 결과를 판정표에 '2차 검증' 절로 덧붙이고, 1차 판정 중 고칠 것이 있으면 정정 기록을 남깁니다.
- **근거 부족**으로 걸린 주장은 그 주장 하나만 blog-research에 보강 조사를 요청합니다.
- 숫자 계산(몇 년 전, 몇 배)은 코드로 계산해 적습니다.

## 참고 자료
- `참고/주장유형_체크리스트.md`: 헤켈 배아·말 계열·시조새·회색가지나방(후추나방)·밀러-유리 실험별 **검증 절차**(판정이 아님). DOI 31개는 2026-10-07에 다시 확인(모두 실재, 철회·정정 없음).

## 하지 않는 것
- 해석 논쟁을 판정하거나, 단체의 관점을 바꾸라고 권하기
- 원문·초록을 보지 않고 ✅ 주기, 초록만 보고 "논문에 없다"고 단정하기
- 고친 문장 제안에 출처에 없는 사실·단체 입장 넣기
- 예상 반론 메모를 블로그 원고·배치 JSON에 넣기
- 창조과학 학술지에 확인 안 된 수식어 붙이기 또는 근거 없이 깎아내리기
- 구글 스칼라 자동 조회, 유료 논문 우회 다운로드
- 사람 대신 '발행해도 됨'을 최종 승인하기

## 예시 — 판정표 한 줄
| 번호 | 위치 | 주장 | 종류 | 판정 | 확인 범위 | 근거 | 고친 문장 제안 |
|---|---|---|---|---|---|---|---|
| C9 | 2절 3문단 | 헤켈은 크기를 실제보다 10배 차이 나게 그렸다 | 숫자·맥락 | ❌ | 초록 + 도판 실물 | 초록: 실제 배아의 길이가 "greater than 10-fold" 차이. 헤켈 도판은 비슷한 크기 → 뜻이 뒤집힘 | 실제 배아는 이 시기 길이가 10배 넘게 차이 나는데, 헤켈의 그림에서는 비슷한 크기로 나란히 그려져 있습니다 |
