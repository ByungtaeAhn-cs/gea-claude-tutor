# 발행 API — 버전 2 (블로그 도우미 확장 ↔ 내 PC 서버)

> 블로그 도우미 확장이 **네이버 연동의 기본 경로**가 되면서 정한 약속입니다(규약 v2 8·9절).
> v1(`발행묶음_API.md`, 사진 묶음만)의 내용은 이 문서 4절에 흡수했습니다.
>
> | 서버 | 누가 씀 | 이 문서를 따르는 방법 |
> |---|---|---|
> | 여행 스튜디오 서버 | 여행 블로그(GUI) | `공용/발행서버.py` 의 `PublishAPI` 를 **import 해서 그대로** 씀(10절) |
> | 발행서버 | 단체 블로그(GUI 없음) | 학습자 프로젝트에서는 `python 도구/발행서버.py …` (11절. 참고구현 안에서는 `공용/발행서버.py`) |
>
> 기준 구현은 `공용/발행서버.py` 입니다. 이 문서와 구현이 다르면 이 문서를 고치고 구현을 맞춥니다. 작성: 2026-10-07.
> v2.1(2026-10-07, 규약 v2.1): **공통 설정 키**(2.3) · **동영상 업로드**(4.2·4.3) · **연결만 모드**(3.1) · 'AI 활용' 기준(6절) · **진단 보내기**(5.3, 실측용).
> v2.2(2026-10-08, 보안 검수 반영): **승인 서명·사람 경로 예약**(5.4, 검수 M3) · **작업 중 파일 범위**(5.5, M2) · **메타가 남은 파일 거절**(4.4, M5) · 연결 해제(L1)·Content-Length(L2).
> v2.3(2026-10-08, 재검수 N1·N2): 승인이 **업로드 파일 바이트(사진·동영상·지도 그림)** 도 묶음(`파일지문`), 예약 작업 중 파일을 내줄 때·누르기 직전에 다시 계산(5.4). 승인·예약 작업 만들기 확인 창 함수(`confirm_approval`·`confirm_reserve_job`).

## 0. v1 → v2 바뀐 점

| | v1 | v2 |
|---|---|---|
| 확장의 일 | 사진 묶음만 넣음(최후 수단) | **글 전체 채우기 → 임시저장**(기본 경로). 선택: 승인된 글의 예약 발행 |
| 확장 구별 | 못 함(아무 확장이나 읽을 수 있었음) | **연결 코드 → 토큰**. `/api/발행/*` 의 확장 요청은 `X-Blog-Helper-Token` 필수 |
| 파일 주소 | `/파일/<패키지>/<경로>` | `/api/발행/파일?패키지=…&경로=…` (토큰 필요) |
| 작업 | 없음 | `POST /api/발행/작업` → 확장이 `GET /api/발행/대기작업` 으로 받아 채우고 `POST /api/발행/결과` 로 단계마다 보고 |
| 응답 필드 | `여행` | `여행ID`, `편ID` 추가. `블록`(블록 위치), `합계크기` |
| 동영상 | 건너뜀(사람이 올림) | (v2.1) 업로드 사본이 있으면 **묶음**(종류 `영상`)이 되고 확장이 '동영상'으로 올림. 파일은 Range·스트리밍 |
| 설정 | 서버마다 이름이 다름 | (v2.1) **공통 설정 키**(2.3) — 스튜디오 `설정.json` = 단체 블로그 `블로그설정.json` |

## 1. 한눈에

```
Claude·스튜디오 화면(로컬)                 서버 127.0.0.1:8765                  블로그 도우미 확장(Chrome·Edge)
 ① POST /api/확장연결  ─────────────▶  연결 코드 482913 (5분)
                                                         ◀── ② POST /api/확장연결/토큰 {코드}  (팝업에 코드 입력)
                                       토큰 발급 ──────────▶   토큰 저장
 ③ POST /api/발행/작업 {패키지,모드} ─▶  작업 n2026…(대기) → 발행/작업_<id>.json
 ④ 글쓰기 화면을 브라우저로 엶
                                                         ◀── ⑤ GET  /api/발행/대기작업   (채우는중)
                                                         ◀── ⑥ GET  /api/발행/파일?…    (사진·동영상)
                                                         ◀── ⑦ POST /api/발행/결과 {단계,상태} × 단계마다
 ⑧ GET /api/발행/작업/<id> ─────────▶  임시저장완료 / 예약발행완료 / 실패(단계·메시지)
```

## 2. 공통 규칙

| 항목 | 규칙 |
|---|---|
| 주소 | `http://127.0.0.1:8765` (또는 `localhost:8765`). 한 PC 에서 여행 스튜디오와 발행서버를 동시에 켜지 않음 |
| 메서드 | `GET`, `POST`(본문은 JSON, `Content-Type: application/json` 필수 — 아니면 415), `OPTIONS`(확장의 사전 요청). 그 밖 405 |
| 응답 | UTF-8 JSON, `Cache-Control: no-store`, 모든 JSON 에 `"버전": 2` |
| Host | `127.0.0.1:8765` · `localhost:8765` · `[::1]:8765` 가 아니면 403(DNS 리바인딩 방지) |
| 한글 경로 | 퍼센트 인코딩으로 옴. 응답 안의 `묶음주소`·`주소` 는 **인코딩된 ASCII 상대 주소** — 받는 쪽은 조립하지 말고 그대로 요청 |

### 2.1 부르는 쪽 세 가지

| 이름 | 판별 | 쓸 수 있는 주소 |
|---|---|---|
| **로컬** | 토큰 헤더가 없고, `Origin` 이 없으면서 `Sec-Fetch-Site` 가 **없거나 `same-origin`**, 또는 `Origin` 이 서버 자신(`http://127.0.0.1:8765`, `http://localhost:8765`). = Claude 의 curl·Python(브라우저가 아님), 스튜디오 화면. `Sec-Fetch-Site: none`(주소창, 다른 확장의 서비스 워커 등 브라우저 안의 것)은 로컬이 아니므로 토큰이 필요(없으면 401) | 연결 코드 만들기, 작업 만들기, 작업 보기·재시도·취소, 묶음·파일 보기 |
| **확장** | `Origin: chrome-extension://<32자 a~p>` (Edge 도 같은 값. `extension://…` 도 받음) **+ 올바른 토큰**(그 확장 출처에 묶인 것). **확장 서비스 워커의 GET 요청에는 `Origin` 이 붙지 않으므로**, `Origin` 이 없고 `X-Blog-Helper-Token` 헤더가 있는 요청도 확장으로 보고 토큰만으로 확인(2026-10-07 시험에서 확인) | 대기작업·결과, 작업 보기·재시도·취소, 묶음·파일, 연결 확인·해제 |
| **연결용** | 확장 출처, 토큰 없음 | `POST /api/확장연결/토큰` 하나뿐 |

- 다른 웹사이트(`Origin: https://…`, `null`)나 `Sec-Fetch-Site: cross-site/same-site` 인 요청은 403.
- 확장 출처인데 토큰이 없거나 틀리면 **401 `연결필요`** → 확장은 "확장 아이콘을 눌러 연결 코드를 넣으세요"를 보여 줌.
- CORS: `Access-Control-Allow-Origin` 은 **확장 출처에만** 그 값 그대로(+`Vary: Origin`). `*`·네이버 출처 허용 금지(네이버 페이지 스크립트가 내 사진을 읽게 됨). 사전 요청은 `Allow-Methods: GET, POST, OPTIONS`, `Allow-Headers: Content-Type, X-Blog-Helper-Token`, 요청에 `Access-Control-Request-Private-Network` 가 있으면 `Allow-Private-Network: true`.

### 2.2 오류

```json
{"버전": 2, "오류": "사람이 읽을 한국어 문장", "코드": "연결필요"}
```

| HTTP | 코드 | 언제 |
|---|---|---|
| 400 | `잘못된_요청` · `코드틀림`(+`남은시도`) · `코드만료` · `예약불가` · `여러_패키지` | 값이 틀림(계획에 없는 단계, 마지막이 아닌 단계의 `최종`, 음수·숫자 아닌 `Content-Length` 포함) |
| 401 | `연결필요` | 확장 토큰 없음·틀림 |
| 403 | `거부` · `경로_탈출` · `작업밖파일` · `사람확인필요` | 출처·Host·권한, 이상한 파일 경로, 작업 중인 확장이 다른 글의 파일·묶음을 요청(5.5), 사람 경로가 아닌 예약발행 작업 만들기(5.4) |
| 404 | `없음` · `패키지_없음` · `작업_없음` · `목록에_없음` | |
| 405 · 413 · 415 | `메서드` · `너무큼` · `형식` | |
| 409 | `진행중작업`(+`작업ID`) · `담당아님` · `상태아님` · `예약확인필요`(+`작업ID`) · `처리시간초과` · `승인과다른파일` | 한 글에 작업 둘, 남의 작업 보고, 상태가 맞지 않음, 예약 확인 버튼을 이미 눌렀을 수 있는 글, `처리중` 신호가 90분을 넘음, 예약 작업 중 승인 뒤 바뀐 파일(5.4) |
| 429 | `시도초과` | 연결 코드를 5번 틀림 → 그 코드 무효 |
| 500 | `서버_오류` | 예상 못 한 오류(연결을 끊지 않고 JSON) |
| 503 | `잠시후` | 작업 파일이 잠깐 잠겨 읽지 못함(조용히 빼먹지 않고 알림) — 잠시 뒤 다시 |
| 416 | (본문 없음) | 파일 밖을 가리키는 `Range`(4.2) |

### 2.3 공통 설정 키 (v2.1)

여행 스튜디오 `설정.json` 과 단체 블로그 `블로그설정.json` 이 **같은 키**를 씁니다. 발행서버는 `--설정 <블로그설정.json>` 으로 직접 읽고, 스튜디오는 `설정.json` 을 `settings` 콜백으로 그대로 넘깁니다(모르는 키는 무시).

| 키 | 기본 | 뜻 |
|---|---|---|
| `블로그ID` | `""` | 글쓰기 화면을 열 블로그(`https://blog.naver.com/<블로그ID>?Redirect=Write`). `--열기`·`--카테고리확인` 에서 아이디를 빼면 이 값 |
| `브라우저` | `"chrome"` | `chrome` · `edge` · `default`(PC 기본 브라우저) — **블로그 도우미 확장을 설치한 브라우저**. 모르는 값은 chrome |
| `자동예약발행` | `false` | 승인된 글의 예약 발행을 확장에 허락(9절 위험 안내 뒤). JSON `true` 일 때만, 그리고 **사람이 확인 창에서 켠 허락 기록**이 있어야 켜짐(5.4 — 파일 값만 바꿔서는 안 켜짐) |
| `편사이간격분` | `10` | 한 편이 끝난 뒤 다음 편을 내주기까지(분) |
| `예약최소여유분` | `15` | 예약 시각은 지금부터 최소 이만큼 뒤(분) |
| `중단판정분` | `10` | `채우는중`인데 이만큼 보고가 없으면 `실패(중단됨)`(분, 최소 7 — 사진 단계 최대 6분보다 길게) |

- 숫자가 아니거나 빈 값·무한대·NaN 이면 기본값, 분 단위 값은 0~10000 으로 자름. 우선순위: **명령줄 옵션 > 설정 파일 > 기본값**.
- 모듈 함수: `normalize_settings(dict) -> dict`(위 6개 키로 맞춤), `load_settings_file(경로)`, `DEFAULT_SETTINGS`.

## 3. 확장 연결(페어링)

| 요청 | 부르는 쪽 | 본문 → 응답 |
|---|---|---|
| `POST /api/확장연결` | 로컬 | `{"이름"?}` → `{"코드":"482913","유효초":300,"만료":"2026-10-07T10:15:00+09:00"}` |
| `POST /api/확장연결/토큰` | 연결용 | `{"코드":"482913","이름":"Chrome (Windows)"}` → `{"토큰":"…","확장ID":"chrome-extension://…","서버":"발행서버"}` |
| `GET /api/확장연결/확인` | 확장 | → `{"연결됨":true,"서버":"…","확장ID":"…"}` (팝업의 연결 표시) |
| `GET /api/확장연결` | 로컬 | → `{"연결":[{"확장ID","이름","연결시각","마지막접속"}],"대기코드":1}` (스튜디오 [확장 연결] 화면) |
| `POST /api/확장연결/해제` | 로컬·확장 | 로컬: `{"확장ID":"chrome-extension://…"}` 또는 **`{"모두": true}`** 일 때만 전부(빈 값은 400 — 검수 L1) / 확장: 자기 것만 → `{"해제":1}` |

- 코드: 6자리 숫자, **5분**, **한 번만**. 틀리면 살아 있는 코드마다 실패 수 +1, 5번이면 무효(429).
- 토큰: 32바이트 무작위(URL 안전). **그 확장 출처(확장ID)에 묶임** — 다른 확장이 같은 토큰을 내면 401. 같은 확장이 다시 연결하면 예전 토큰은 버림.
- 저장: `<상태폴더>/연결.json`, 기본 `~/.gea-blog-helper/` (환경변수 `BLOG_HELPER_STATE` 로 바꿈). **코드·토큰 원문은 저장하지 않고 SHA-256 값만.** 여행 스튜디오와 발행서버가 같은 폴더를 쓰므로 **한 번 연결하면 둘 다 됨**.
- 확장은 토큰을 `chrome.storage.local` 에 둡니다(그 브라우저 프로필 안).

### 3.1 글 없이 미리 연결 — 연결만 모드 (단체 블로그 8회차)

단체 블로그 교재는 **8회차에 확장을 연결**하고, 첫 발행 패키지는 9회차에 생깁니다. 보통 서버는 패키지가 있어야 켜지므로 8회차에는 이 모드를 씁니다.

```bash
python 도구/발행서버.py --연결만                 # 패키지 없이 서버를 켜고 연결 코드(6자리·5분)를 보여 줌
python 도구/발행서버.py --연결만 --연결되면종료    # 확장이 연결되면 연결 목록을 출력하고 스스로 꺼짐
```

1. 서버가 `연결 코드: 482913` 을 출력 → 2. 학습자가 브라우저 오른쪽 위 확장 아이콘(블로그 도우미) → 코드 입력 → [연결] → 3. 서버가 `연결됨: Chrome 블로그 도우미 (chrome-extension://…)` 과 **연결 목록**을 출력 → 4. Ctrl+C 로 끔(또는 `--연결되면종료`).
- 아무도 연결하지 않은 채 코드가 만료되거나, 누가 5번 틀려 코드가 무효가 되면 새 코드를 바로 다시 보여 줌. 켜져 있는 동안 확장 팝업의 '연결 확인'·글쓰기 화면 패널도 '연결됨'으로 보임(작업은 없음).
- 토큰은 상태폴더(기본 `~/.gea-blog-helper`)에 남으므로 **9회차에 패키지를 넣고 켠 보통 서버에서 그대로 통함**(다시 연결할 필요 없음). 여행 스튜디오도 같은 폴더를 씀.
- 이미 다른 서버(스튜디오·발행서버)가 8765 를 쓰고 있으면 이 모드는 켜지지 않음 → 그 서버로 연결: 다른 창에서 `python 도구/발행서버.py --연결코드`.
- 같은 확장 폴더를 Chrome·Edge 에 함께 설치하면 확장ID 가 같아 연결 목록에는 한 줄이고, **나중에 연결한 브라우저의 토큰만 통함**(먼저 연결한 쪽은 다시 연결해야 함).

## 4. 글·묶음·파일 (v1 흡수)

| 요청 | 부르는 쪽 | 응답 |
|---|---|---|
| `GET /api/발행/패키지` | 확장·로컬 | `{"서버","목록":[{"패키지","여행ID","편ID","일차","제목","묶음수","사진수","영상수","합계크기","승인","묶음주소"}],"경고":[]}` |
| `GET /api/발행/묶음?패키지=…` (또는 `여행=&편=`, `여행=&일차=`) | 확장·로컬 | 4.1 |
| `GET /api/발행/파일?패키지=…&경로=…` | 확장·로컬 | 사진·동영상 바이트(`Content-Type`·`Content-Length`·`Accept-Ranges: bytes`). `Range` 받음(4.2) |

### 4.1 묶음 응답

```json
{"버전":2,"서버":"발행서버","패키지":"패키지_1일차","여행ID":"2026-09_제주","편ID":"1일차","일차":1,
 "제목":"…","묶음수":2,"사진수":4,"영상수":0,"합계크기":2104311,
 "묶음":[{"번호":1,"블록":3,"종류":"사진","방식":"한 장","장수":1,"합계크기":523411,"업로드묶음수":1,
          "설명":"물빛이 이렇게 맑을 줄이야","대표":true,"앞소제목":"협재해변","폴더":"사진묶음_1일차/02_사진",
          "파일":[{"순서":1,"id":"p0001","이름":"d1_02_p0001.jpg","크기":523411,"형식":"image/jpeg",
                  "주소":"/api/%EB%B0%9C%ED%96%89/%ED%8C%8C%EC%9D%BC?…","경로":"사진묶음_1일차/02_사진/d1_02_p0001.jpg",
                  "업로드묶음":1}],
          "경고":[]}],
 "건너뜀":[{"블록":6,"종류":"영상","사유":"업로드 사본 경로가 없음 — 사람이 에디터의 '동영상' 버튼으로 올림"}],
 "경고":[]}
```

| 필드 | 뜻 |
|---|---|
| 묶음 `번호` | 1부터. 패널의 [묶음 N 넣기], 작업의 `글.블록[].묶음` 이 가리키는 값 |
| `블록` | 패키지 `블록` 배열 위치(1부터) |
| `방식` | **`한 장` / `개별 사진` / `콜라주` / `슬라이드`** (네이버 '그룹 사진' 이름). 그룹사진의 `개별사진`·`개별`도 `개별 사진`으로, 모르는 값은 `콜라주`+경고. 파일이 1장이면 `한 장`. 동영상 묶음은 `동영상` |
| `장수`·`합계크기` | 실제로 내줄 수 있는 파일 기준(없는 파일은 빠지고 경고) |
| `앞소제목` · `폴더` | 넣을 자리 찾기 · 실패 때 "이 폴더 사진을 직접 올리세요" 안내 |
| 파일 `주소` | 그대로 요청. 서버마다 형식이 달라도 됨(발행서버: 위처럼, 허용 폴더 기준 경로) |
| 파일 `경로` | 패키지 JSON 폴더 기준 상대 경로(정보용). **절대 경로는 내보내지 않음** |
| `업로드묶음` | 사진: 합계 10MB 미만으로 나눈 번호(정보용 — 확장은 한 묶음을 **한 번에** 넣음). 동영상: 10개씩 나눈 번호(네이버 1회 최대 10개 — 확장이 이 단위로 나눠 올림) |
| 파일 `길이초` | (동영상만) MP4·MOV·3GP 의 길이(초, `moov/mvhd` 에서 읽음). 못 읽으면 `null` |

- **블록 하나 = 묶음 하나**(`업로드묶음` 으로 쪼개지 않음 — 한 번에 넣어야 콜라주·슬라이드 하나가 됨).
- 묶음이 되는 블록: `사진`·`그룹사진`·`지도`·**`영상`**(업로드 사본이 있을 때). 업로드 사본이 없는 블록은 `건너뜀`(동영상은 "사람이 '동영상' 버튼으로").
- `사진수`는 사진 묶음만, `영상수`는 동영상 묶음만 셈.
- 경고: 파일 없음·허용 폴더 밖·네트워크 경로, 사진 형식 아님(jpg·jpeg·png·gif·webp·bmp 만), 장당 10MB 초과, 한글 등 파일명, 한 묶음 10장 초과, 모르는 그룹 방식.
- **거절(내주지 않음)**: 위치·기기 정보·덧붙은 데이터가 남은 파일 — 4.4. 묶음의 `거절: [{"이름","경로","이유":[…]}]`, 맨 위 `거절수`. 확장은 거절이 하나라도 있으면 '준비'에서 `개인정보`로 멈춤.
- 파일: 패키지에 적힌 사진·동영상만, 허용 폴더(9절) 안만. 요청 `경로` 로 파일 시스템을 직접 열지 않고 패키지에서 만든 표에서만 찾음(Windows 는 대소문자 무시). `..`·`.`·빈 조각·`\`·`:`·`/`로 시작·널 문자 → 403.

### 4.2 파일 제공 — Range·스트리밍

- `Range: bytes=a-b` · `bytes=a-` · `bytes=-n`(한 구간) → **206** + `Content-Range: bytes a-b/전체`. 끝을 넘으면 끝까지로 줄임. 파일 밖이면 **416** + `Content-Range: bytes */전체`. 여러 구간은 무시하고 전체 200(RFC 9110 허용).
- 16MB 넘는 파일과 모든 Range 응답은 **메모리에 올리지 않고 1MB씩 나눠** 보냄(`Response.file·start·length`). 서버 접착 코드는 `r.write_to(wfile)` 로 본문을 써야 함(10절) — `r.body` 만 쓰면 큰 파일이 빈 채로 나감.
- 모든 파일 응답에 `Accept-Ranges: bytes`, `Access-Control-Expose-Headers: Content-Length, Content-Range, Accept-Ranges`.

### 4.4 메타가 남은 파일은 내주지 않음 (검수 M5 — fail-closed)

업로드 사본은 위치·기기 정보 없이 다시 만든 것이어야 합니다. 서버는 내주기 전에 파일을 **끝까지** 읽어 아래가 남아 있으면 그 파일을 허용 목록에서 빼고(주소를 알아도 404 `목록에_없음`) 묶음의 `거절`에 적습니다. 결과는 크기·수정 시각이 같으면 다시 읽지 않음(`upload_meta_problems(경로)`).

| 형식 | 거절하는 것 |
|---|---|
| JPEG | EXIF 의 GPS·촬영기기(Make/Model), XMP 의 GPS·기기·모션 포토(`MotionPhoto`·`MicroVideo`), MPF(심도·HDR 보조 이미지), **EOI 뒤에 덧붙은 데이터**(모션 포토 동영상 등), 구조가 깨진 파일 |
| PNG | `eXIf`·`tEXt`·`iTXt`·`zTXt` 청크, IEND 뒤 데이터 |
| WebP | `EXIF`·`XMP ` 청크, 파일 뒤 데이터 |
| MP4·MOV·3GP | `mdat` 밖 상자의 위치(`©xyz`·`com.apple.quicktime.location`·`loci`)·기기(`©mak`·`©mod`·`…make/model`) 꼬리표 |
| GIF·BMP·그 밖의 영상 | 이 서버가 읽지 않음(업로드 사본을 만드는 쪽 책임 — 스튜디오는 재인코딩으로 지움) |

EXIF 의 방향(Orientation)만 있는 JPEG 은 내줍니다. 사람이 할 일: 업로드 사본을 다시 만든 뒤(메타 지우기) 패널의 [이 단계부터 다시].

### 4.3 동영상 묶음과 네이버 기준

| 항목 | 값(도움말 #15530·#15491, 조사 01) | 서버가 하는 일 |
|---|---|---|
| 형식 | avi, wmv, mpg, mpeg, mov, mkv, asf, skm, k3g, flv, mp4, 3gp, webm (+ m4v) | 다른 형식은 빼고 경고 |
| 1회 개수 | 최대 10개 | 10개씩 `업로드묶음` 번호, 넘으면 경고(확장이 나눠 올림) |
| 크기 | 본인인증 8GB · 미인증 1GB | 8GB 넘으면 **뺌**, 1GB 넘으면 경고 |
| 길이 | 본인인증 7시간 · 미인증 15분 | `길이초`로 15분·7시간 넘으면 경고(넘는 부분은 네이버가 잘라 올림) |

동영상 블록 예(패키지): `{"종류":"영상","영상":"p0100","제목":"협재 바다","설명":"…","업로드":"작업/업로드사본/p0100.mp4"}` — `제목`·`설명`은 네이버의 동영상 정보 창이 뜨면 확장이 넣음(없으면 그대로 둠).

## 5. 발행 작업 API

| 요청 | 부르는 쪽 | 하는 일 |
|---|---|---|
| `POST /api/발행/작업` | **로컬만** | `{"패키지":"…"}` 또는 `{"여행ID":"…","편ID":"…"}` + `"모드":"임시저장"`(기본)·`"예약발행"`, `"예약시각"`, (예약을 사람이 확인한 뒤 같은 글을 다시 예약할 때만) `"다시예약":true` → **201** `{"작업":요약}`. **`예약발행`은 사람 경로에서만**(5.4 — 아니면 403 `사람확인필요`) |
| `GET /api/발행/작업?상태=` | 로컬·확장 | `{"작업":[요약…]}` (만든 순) |
| `GET /api/발행/작업/<작업ID>` | 로컬·확장 | `{"작업":작업 파일 전체}` |
| `POST /api/발행/작업/<작업ID>/재시도` | 로컬·확장 | `{"단계"?, "사람"?}` → 상태 `대기`, `시작단계` = 준 단계 또는 실패한 단계. `"사람":true` 면 그 단계는 '사람이 했음'으로 처리(`시작단계사람`, 화면을 새로고침해도 남음). `예약확인누름`이 있는 작업은 409 `예약확인필요` |
| `POST /api/발행/작업/<작업ID>/취소` | 로컬·확장 | 상태 `취소` |
| `GET /api/발행/대기작업` | **확장만** | 다음 작업을 받음(6절) → `{"작업":받은작업\|null,"사유":"","다음가능":null,"서버":"…"}` |
| `GET /api/발행/대기작업?작업ID=<id>` | **확장만** | **그 작업만** 받음(글이 있는 화면의 [작업 확인]·[이 단계부터 다시] — 더 오래된 다른 대기 작업을 받지 않게). 그 작업이 `대기`가 아니면 `작업:null, 사유:"없음"`. 다른 작업이 `채우는중`이면 `다른작업진행중`, 간격 규칙도 그대로. ID 모양이 틀리면 400 |
| `POST /api/발행/결과` | **확장만**(그 작업을 받은 확장) | 단계 보고(7절) → `{"작업":요약}` |
| `POST /api/발행/진단` | **확장만** | (실측용) 화면 구조 진단 저장(5.3) → **201** `{"경로","개요","파일","크기","요소수"}` |
| `GET /api/발행/진단` | **로컬만** | 최근 진단 목록 `{"폴더","진단":[{"파일","경로","개요","시각","크기"}]}` (새것부터 20개) |

### 5.1 상태

```
대기 ──(확장이 받음)──▶ 채우는중 ──(최종 보고)──▶ 임시저장완료 | 예약발행완료
  ▲                        │
  └──── 재시도 ◀── 실패 ◀──┘ (실패 보고, 또는 '중단판정분' 동안 보고 없음 → 코드 '중단됨'
  │                          — 예약 확인 버튼을 누른 뒤 끊겼으면 '예약확인필요')
  └──── 재시도 ◀── 취소 ◀── (대기·채우는중·실패에서)
```

- **한 번에 한 편**: `채우는중` 작업이 있으면 다른 작업을 내주지 않음(사유 `다른작업진행중`). 같은 확장이 다시 물으면 그 작업을 다시 줌(사유 `재개` — 화면을 새로고침한 경우).
- **간격**: 마지막으로 끝난(`임시저장완료`·`예약발행완료`) 작업의 `끝` + `편사이간격분` 전에는 내주지 않음(사유 `간격`, `다음가능` 시각).
- 한 글(패키지)에 `대기`·`채우는중` 작업은 하나만(409 `진행중작업`).
- 작업 ID: `n`+`YYYYMMDD-HHMMSS`+`-`+16진 4자리(예 `n20261007-101233-a3f9`). 이 모양이 아니면 404.

### 5.2 작업 파일 `발행/작업_<작업ID>.json` (패키지 JSON 옆)

```json
{"버전":2,"작업ID":"n20261007-101233-a3f9","패키지":"패키지_1일차","패키지파일":"패키지_1일차.json",
 "여행ID":"2026-09_제주","편ID":"1일차","제목":"…","모드":"임시저장","예약시각":null,
 "상태":"실패","시작단계":null,"담당":"chrome-extension://…",
 "만든시각":"…","시작":"…","끝":"…","마지막신호":"…","현재단계":"블록 3","재시도횟수":0,
 "시작단계사람":false,"예약확인누름":null,
 "단계목록":["준비","제목","블록 1",…,"저장"],"예약허용":false,
 "실패":{"단계":"블록 3","코드":"선택자없음","메시지":"사진 버튼을 찾지 못함"},
 "단계":[{"이름":"제목","상태":"완료","메시지":"","주의":[],"코드":null,"시각":"…","시도":1}],
 "기록":[{"이름":"제목","상태":"진행","메시지":"","시각":"…"}]}
```

- `단계`: 단계 이름마다 마지막 상태 1줄(처음 나온 순서). `기록`: 모든 보고(최근 500개).
- 작업의 패키지는 **작업 파일 옆의 `패키지파일`** 로 찾습니다(표시 이름 `패키지`는 서버를 다시 켜면 `-2` 같은 꼬리가 바뀔 수 있음).
- `단계목록`·`예약허용`: 확장이 **받을 때 고정한 계획**. 그 뒤 보고·`최종`은 이 고정본으로 확인합니다(채우는 데 오래 걸려 예약 여유가 줄어도 '예약발행' 보고가 400 이 되지 않음 — 여유는 확장이 누르기 직전에 다시 확인). 재시도하면 `null` 로 비우고 다시 받을 때 새로 정함. 이 두 값이 없는 예전 작업은 보고 때 계획을 새로 계산.
- `중단판정분`은 최소 7분(사진 단계 최대 6분보다 길게)으로 맞춥니다. 동영상처럼 오래 걸리는 단계는 확장이 `처리중` 신호(7절)를 보내 중단으로 보지 않게 합니다.
- 작업 파일을 바꿀 때는 프로세스 사이 잠금(`<상태폴더>/.작업.lock`)을 씁니다(서버와 명령줄이 함께 써도 안전). 잠금 파일이 30초 넘게 남아 있으면 버려진 것으로 보고 지움 — 한 번의 잠금 안 작업은 보통 1초 안이지만, 디스크가 아주 느려 30초를 넘기면 두 프로세스가 겹칠 수 있음(알려진 한계. 서버 하나만 켜 두면 문제없음).
- `on_event` 는 **잠금을 푼 뒤에** 불립니다(알림 안에서 `jobs.get()`·`jobs.list()` 를 불러도 막히지 않음). 알림 쪽 오류는 서버 로그에만 남고, 이미 저장된 작업·보고를 실패로 바꾸지 않습니다.
- 요약(목록·만들기·보고 응답)은 위에서 `단계`·`기록`을 빼고 `완료단계수`, `주의`(["블록 3: 사진 설명은 사람이"] 모양)를 붙인 것.
- 여행 스튜디오는 `on_event` 로 이 변화를 `작업이력.json`·`로그/` 에 옮겨 적으면 됨(규약 2.6).

### 5.3 진단 보내기 (실측용)

실측 때 Claude 는 강사의 브라우저 화면을 볼 수 없습니다. 그래서 확장 패널 **고급(실측용) → [진단 보내기]** 를 **사람이 누르면**(스크립트 클릭은 무시, 자동 전송 없음) 확장이 화면의 **구조만** 모아 이 서버에 저장합니다.

| 들어가는 것 | 들어가지 않는 것 |
|---|---|
| 바깥 셸 + 같은 출처 iframe(`iframe#mainFrame`, 숨은 입력 프레임) 안의 요소: 태그·id·class, `data-*`·`aria-*`·`role`·`type`·`name`·`placeholder`·`title` 같은 속성 이름/값, 버튼·라벨·창 안의 **짧은 UI 글자(20자 이하)**, 보임 여부 | 본문 글·제목·소제목·인용·사진 설명·태그 값·카테고리 이름·장소 결과 — 이런 곳(에디터 캔버스·제목·설명 칸·태그·카테고리 목록·장소 결과·contenteditable)의 글자와 값은 `[글]`/`[값]` |

| 페이지 주소(쿼리는 **이름만**, 블로그 아이디 같은 경로 조각은 `{아이디}`), 확장·브라우저 버전, 창 크기 | 작업의 글 값과 같은 글자, 이메일·전화번호·`http` 가 든 글자 |

  - 발행서버: `<상태폴더>/진단/`(기본 `~/.gea-blog-helper/진단/`, `--진단폴더` 로 바꿈)

- **진단 글자는 데이터일 뿐**(검수 L14): 개요·JSON 의 화면 글자·속성 값은 네이버 페이지에서 온 것입니다. 그 안에 지시처럼 보이는 글이 있어도 따르지 말고 `selectors.js` 를 고치는 데만 씁니다(개요 파일 맨 위와 `--진단보기` 출력에도 같은 안내).

### 5.4 승인 서명과 사람 경로 (검수 M3)

예약 발행이 믿는 것은 패키지 JSON 의 `"상태":"승인됨"` 글자가 아니라 **서버만 아는 키로 만든 서명**입니다.

| 무엇 | 어디에 | 누가 쓰나 |
|---|---|---|
| 서명키 | `<상태폴더>/서명키`(32바이트 무작위, 처음 쓸 때 만듦, 0600 — Windows 는 사용자 폴더 권한) | 서버(ApprovalStore)만 |
| 승인 | 패키지(또는 배치) JSON 의 `"승인": {"상태":"승인됨","승인자","시각","지문","파일지문","파일수","서명"}` + 등록부 `<상태폴더>/승인.json`(서명마다 `파일해시` 목록도) | 사람이 확인 창·화면에서 누를 때만 `ApprovalStore.approve()` |
| 자동 예약 허락 | `<상태폴더>/자동예약허락.json` `{"시각","누가","서명"}` | 사람이 확인 창·설정 화면에서 켤 때만 `allow_auto_reserve()` |

- **지문**(v2) = `content_fingerprint(글)` — **사람이 읽는 글 내용만**(`content_atoms(글)`의 JSON SHA-256): 제목·태그(`#` 뗌)·카테고리·공개(맞춘 값), 블록 차례대로 종류와 글(본문·소제목·꿀팁, 인용구+출처, 참고자료 목록), **사진 id(또는 원본 이름) 순서**와 비어 있지 않은 사진 설명, 장소 이름, 영상 id(+설명), 구분선·지도 자리. 이어진 사진 블록은 한 덩어리(사진 순서 전체 → 설명은 처음 나온 순서로 한 번씩)로 봄.
  - 넣지 않는 것(패키지 도구가 더하는 기술 필드): 업로드 사본 경로(`업로드`·`업로드사본`·`업로드묶음`·`파일`·`업로드영상`), 지도의 `이미지`·`출처표시`, 빈 `설명`, 그룹 `방식`·`대표`, `AI활용표시`, 맨 위 `패키지`·`편ID`, 그리고 **`--나누기`로 사진 묶음을 쪼갠 블록 경계**.
  - 그래서 배치와 그 배치로 만든 패키지는 **글 지문이 같습니다**(위 필드가 붙고 큰 묶음이 쪼개져도) — 스튜디오가 '같은 글인가'를 볼 때 씀.
- **파일지문**(검수 N1) = `files_fingerprint(upload_file_hashes(pkg))`: 그 글이 **실제로 내줄 업로드 파일**(사진·그룹사진·지도 그림·동영상 — `build_bundles` 와 같은 파일, 허용 폴더 안)의 **SHA-256 목록**(블록 순서·파일 순서, **경로는 넣지 않음**, 못 찾은 파일은 `없음`)의 해시. 묶음 쪼개기·경로 바뀜과는 상관없고, 사진·지도 그림·동영상의 **바이트**가 하나라도 바뀌면 달라짐. 해시는 (경로·크기·수정시각)이 같으면 캐시(큰 동영상) — 누르기 직전·파일을 내줄 때는 캐시를 쓰지 않음.
- **서명**(v3) = HMAC-SHA256(서명키, `"승인|v3|<편ID>|<지문>|<파일지문>|<시각>"`). 편ID 는 `편ID` 키, 없으면 파일 이름(`패키지_<편ID>`·`배치_<편ID>`). 예전(v2) 서명은 무효 — 다시 승인.
- `verify(pkg, fresh=False, require_files=None)` 가 참이려면: 상태 `승인됨` · 서명 있음 · **지금 글의 지문 = 승인 때 지문**(승인 뒤 글이 바뀌면 무효) · 서명이 맞음 · 등록부에 있음(**취소한 옛 승인을 되살려도 무효**) · 그리고 **패키지(업로드 사본이 적힌 글)면 지금 파일의 파일지문 = 승인 때 파일지문**. 패키지는 `load_package(경로)`로 읽은 Package 로 확인해야 함(경로 없이 data 만 주면 패키지는 무효로 봄 — 파일을 확인할 수 없으므로).
- **배치 승인 → 패키지 흐름**: 배치에는 업로드 파일이 없어 배치로 한 승인은 **패키지의 파일을 묶지 못합니다**(패키지에 그대로 복사하면 무효). 그래서 사람이 승인할 때(또는 예약 작업을 만들 때) **그 글의 패키지 파일로 `approve(패키지경로)`** 하세요 — 스튜디오: 미리보기 [이 글 승인]에서 배치를 승인하고, 같은 글(글 지문 같음)의 패키지가 있으면 그 자리에서 패키지도 `approve()`, 패키지를 나중에 만들면 [네이버 예약 발행] 등 사람이 누르는 때에 `approve(패키지)`. 패키지를 다시 만들 때 파일 내용이 같으면(경로·묶음 쪼개기만 다름) 패키지의 `승인`을 그대로 옮겨도 유효.
- **예약 작업 중 파일 확인**: 확장이 `예약발행` 작업을 채우는 동안 `/api/발행/파일` 은 내줄 때마다 해시를 다시 계산해 **승인에 묶인 해시가 아니면 409 `승인과다른파일`**(64MB 까지는 읽은 바이트 그대로 해시하고 보냄, 더 큰 동영상은 다시 계산한 뒤 나눠 보냄). 누르기 직전(`확인누름`) 재확인도 캐시 없이 파일지문을 다시 계산 — 작업 중에 사진을 바꿨다 되돌려도 잡음.
- `reserve_check`(작업 만들 때·받을 때·`확인누름` 때 모두): 설정 `자동예약발행: true` **그리고** 허락 기록의 서명이 맞음 **그리고** `verify(pkg)` + 공개·시각 조건. 설정 글자만 바꿔서는 켜지지 않음.
- **사람 경로**: `예약발행` 작업은 `JobStore.create(…, human=True)` 일 때만 만들어짐(아니면 403 `사람확인필요`).
  - 여행 스튜디오: 화면의 세션 비밀값(예: `X-Studio-Key`)을 확인한 요청에서만 `api.handle(method, target, headers, body, human=True)`. 로컬 호출일 때만 효력(확장 요청은 human 을 줘도 무시).
  - **화면 클릭만으로는 사람 증명이 약함**(재검수 N2 — 다른 로컬 프로그램·브라우저 도구가 화면을 대신 누를 수 있음). 그래서 승인·예약 작업 만들기 직전에 공용 **데스크탑 확인 창**을 한 번 더: `confirm_approval(pkg)` → 참일 때만 `approve()`, `confirm_reserve_job([pkg], 예약시각)` → 참일 때만 `create(…, human=True)`(발행서버 `--승인`·`--작업 예약발행` 이 같은 함수를 씀). 쿠키·POST 열쇠 분리와 `/` 열쇠 심기 조건은 스튜디오 서버 쪽.
  - 스튜디오 화면(`http://localhost:8765`)을 Claude 의 브라우저 도구(Claude in Chrome·브라우저 창)로 열거나 누르지 않도록 안내(스튜디오 CLAUDE.md 10번).
  - 발행서버: `--작업 예약발행` 이 데스크탑 확인 창(tkinter)을 띄우고 사람이 [예약 작업 만들기]를 눌렀을 때만. 조건이 안 맞으면 창 없이 바로 이유를 알림. HTTP 로컬 요청으로는 못 만듦.
- 확인 창(`confirm_window`)은 마우스로 [확인 버튼]을 눌러야 참 — Enter 로는 안 눌리게 처음 초점은 [취소]. Claude 는 이 창을 누를 수 없음.

### 5.5 작업 중 파일 범위 (검수 M2)

- 서버: 어떤 확장이 `채우는중` 작업을 가지고 있으면, 그 확장의 `/api/발행/파일`·`/api/발행/묶음` 은 **그 작업의 패키지 것만**(다른 글은 403 `작업밖파일`), `/api/발행/패키지` 목록도 그 글만.
- 확장(background): 탭마다 '받은 파일' 목록 — 서버가 그 탭에 준 작업(`대기작업`)·묶음 응답에 있던 주소만 `파일`·`영상표`로 받을 수 있음. 패널 보조 도구('사진 묶음만 넣기')는 기본으로 숨기고, 팝업에서 사람이 켰을 때만 `목록`·`묶음`을 받음.

## 6. 받은 작업(`GET /api/발행/대기작업` 의 `작업`)

작업 파일(`기록` 제외) + 아래:

```json
{"글":{"제목":"…","블록":[{"종류":"소제목","글":"협재해변","번호":2,"묶음":null},
                         {"종류":"사진","사진":["p0001"],"설명":"…","대표":true,"번호":3,"묶음":1},
                         {"종류":"장소","장소":["협재해변"],"번호":7,"묶음":null}],
        "태그":["제주여행"],"카테고리":"여행","공개":"비공개","공개원문":"비공개","AI활용표시":true,"승인":"미승인"},
 "묶음":[…4.1 의 묶음…], "건너뜀":[…],
 "단계목록":["준비","제목","블록 1","블록 2",…,"태그","카테고리","공개설정","AI활용","저장"],
 "예약":{"허용":false,"사유":"","시각":null,"승인":"미승인","자동예약발행":false},
 "설정":{"편사이간격분":10,"예약최소여유분":15}}
```

- `글.블록`: 패키지 블록 그대로 + `번호`(1부터) + `묶음`(사진·동영상 블록이면 4.1 묶음 번호). 업로드 사본 경로·지도 원본 경로는 빼고 보냄.
- `공개`: `전체 공개`/`이웃 공개`/`서로이웃 공개`/`비공개` 로 맞춘 값(모르면 `null`).
- `AI활용표시`: `true`/`false`/`null`(값 없음·불리언이 아님). **확장은 `true` 일 때만 'AI 활용 설정'을 켜고**, `false` 면 건드리지 않음(`건너뜀`), `null` 이면 건드리지 않고 `주의`. 켜진 것을 끄지는 않음.
  - 기준: **AI로 만든(또는 바꾼) 이미지·영상이 있을 때 켬(네이버 기준), 글을 AI 도움으로 쓴 사실은 글 끝 문구로** 적음.
- **`예약.허용` 이 `true` 일 때만** `단계목록` 끝에 `예약발행` 이 붙음. 조건 모두: 작업 `모드: "예약발행"`(사람 경로로 만든 것) · 패키지의 **서명된 승인이 지금 글과 맞음**(5.4) · 서버 설정 `자동예약발행: true` **+ 사람이 켠 허락 기록** (+ 공개 값 있음, 예약시각이 10분 단위이고 지금부터 `예약최소여유분`(기본 15분) 이후). 작업을 만들 때와 **받을 때 두 번** 확인(받을 때 조건이 깨졌으면 그 작업은 실패 `예약불가`). 받은 뒤에는 계획을 고정(5.2): 다시 받을 때(`재개`) 조건이 지금은 안 맞아도 `허용`은 그대로이고 `사유`에 지금 상태를 적음.
- `시작단계` 가 있으면(재시도) 확장은 그 단계부터 함. 앞 단계 내용이 화면에 없으면 멈추고 `앞단계없음` 으로 보고.

## 7. 단계 보고(`POST /api/발행/결과`)

```json
{"작업ID":"n…","단계":"블록 3","상태":"완료","메시지":"사진 3장, 콜라주","주의":["사진 설명은 사람이"],"코드":null,"최종":null}
```

| 필드 | 값 |
|---|---|
| `단계` | `단계목록` 의 이름(40자 이하) |
| `상태` | `진행`(시작) · `완료` · `주의`(됐지만 사람이 볼 것) · `사람`(사람이 했다고 표시) · `건너뜀` · `실패` |
| `코드`(실패 때) | `로그인필요` · `보안확인`(캡차·보호조치) · `팝업`(모르는 창) · `선택자없음` · `확인필요`(결과 불확실) · `에디터비어있지않음` · `앞단계없음` · `카테고리없음` · `장소없음` · `사진없음` · `영상없음`(동영상을 서버에서 못 받음) · `영상전달`(확장의 동영상 다리 창이 안 열림) · `개인정보`(서버가 메타 때문에 내주지 않은 파일이 있음 — 4.4) · `예약불가` · `시간초과` · `사람이멈춤` · `설정오류` · `오류` (서버가 붙이는 것: `중단됨` · `예약확인필요` · `패키지없음`) |
| `코드`(진행 때, 살아 있음) | `처리중` — 오래 걸리는 단계(동영상 받기·네이버 업로드·인코딩)에서 약 1분마다 보냄. 서버는 `마지막신호`·그 단계의 `메시지`·`신호시각`만 바꾸고 `시도`·`기록`·알림은 늘리지 않음(중단 판정만 막음). 그 단계가 `진행` 중일 때만(아니면 409 `상태아님`), 그 단계의 `진행` 보고 뒤 **90분까지**(넘으면 409 `처리시간초과` — 신호로 작업을 끝없이 붙잡지 못하게, 곧 `중단됨`) |
| `코드`(진행 때) | `확인누름` — '예약발행' 단계에서 발행 확인 버튼을 **누르기 직전** 보냄. 서버는 이때 **지금 조건**(설정·승인·공개·예약 여유)을 다시 확인해 안 맞으면 **400 `예약불가`**(아무것도 기록하지 않음 — 확장은 누르지 않고 `예약불가` 실패로 보고). 맞으면 `예약확인누름`을 기록해, 뒤에서 보고가 끊겨도 같은 글을 두 번 예약하지 않게 재시도·새 예약을 막음 |
| `최종` | **계획의 마지막 단계**를 `완료`·`주의`·`사람`·`건너뜀`으로 끝낼 때만: `임시저장완료`(마지막이 '저장'), `예약발행완료`(마지막이 '예약발행'이고 예약 조건이 맞을 때만) |

- `실패` 를 보고하면 작업은 바로 `실패`로 끝남(확장은 그 단계에서 멈춤 — **추측 클릭 금지**). 재시도는 그 단계부터.
- 계획(`단계목록`)에 없는 단계 이름은 400.
- 단계 시간 초과: 확장은 그 단계의 동작을 멈추게 한 뒤(최대 30초 기다림) `시간초과`로 보고합니다(보고 뒤에 화면을 더 만지지 않음). 30초 안에 안 멈추면(예: 사진 받기가 아주 느림) 메시지에 '아직 멈추지 않음'을 붙이고, 그 단계가 끝날 때까지 그 화면에서는 새 작업을 시작하지 않습니다(받은 작업은 시작할 단계에 `확인필요` 실패로 바로 돌려줌). 늦게 깨어난 옛 단계는 다음 동작(기다림·클릭·사진 받기) 전에 멈춤.
- '예약발행' 단계에서 `확인누름`을 보낸 뒤 어떤 이유로든 멈추면 코드는 `확인필요`, 메시지에 '버튼이 눌렸을 수 있으니 네이버의 예약 발행 목록을 사람이 확인'을 붙입니다.
- 필수 동작이 안 되면 `실패`, 덜 중요한 동작(사진 설명·대표 지정)이 안 되면 `주의` 에 적고 계속.

## 8. 확장이 지키는 것(서버가 믿고 맡기는 약속)

- 로그인·비밀번호 입력, 캡차·보호조치 우회를 하지 않음. 그런 화면을 만나면 즉시 `실패`(`로그인필요`/`보안확인`).
- 기본 모드(`임시저장`)에서는 **발행 확인 버튼을 누르지 않음**(발행 설정 창을 여는 버튼은 태그·카테고리·공개를 넣으려고 누름 — 창을 여는 것만으로는 발행되지 않음). 작업 중에는 확인 버튼 클릭을 막는 안전장치를 켬.
- `예약발행` 단계는 `예약.허용` 이 `true` 이고 확장이 받은 값에서도 세 조건을 다시 확인한 뒤에만.
- 한 화면에서 한 작업만. 끝나면 서버의 간격 규칙을 따름. 빈 글쓰기 화면일 때만 저절로 작업을 받음(이미 글이 있는 화면은 사람이 [작업 확인]·[이 단계부터 다시]를 눌렀을 때 `?작업ID=` 로 **같은 작업**만 받음. 그래도 다른 작업이 오면 손대지 않고 '준비' `확인필요` 실패로 돌려줌).
- 작업 중에는 로그인·보호조치·캡차 화면을 약 2초마다 확인(단계 도중에도). 낱말은 화면 전체에서 세되, 글 내용(에디터 캔버스 `.se-canvas`)과 도우미 패널에 있는 것은 빼고 셈 — 글에 '보호조치'가 있어도 멈추지 않고, 에디터 위에 뜬 보호조치 창은 잡음.
- 예약 발행: 누르기 직전에 예약 시각이 아직 `예약최소여유분` 이상 남았는지 다시 확인, `확인누름` 보고 뒤 클릭, 성공은 '예약 발행 n건' 표시가 바뀐 것으로만 판정.
- 'AI 활용 설정': 글의 `AI활용표시`가 `true` 일 때만 켬(6절).
- 패널(검수 M2): **닫힌 그림자 루트** 안에 있어 네이버 페이지 스크립트가 패널 DOM·로그·목록을 보지 못하고, 패널은 **사람의 클릭·키보드(isTrusted)** 만 받음(스크립트의 `.click()`·`dispatchEvent`·`details.open` 무시). 동영상 다리 iframe 도 그 그림자 루트 안.
- 동영상 다리(검수 L4·L5): `web_accessible_resources` 는 `use_dynamic_url: true`(세션마다 바뀌는 주소 — 고정 확장 ID 로는 못 읽음) + `https://blog.naver.com/*`(Chrome 은 이 목록에 경로를 받지 않아 출처 단위가 최대). 다리 창은 자기를 품은 화면(부모 창, `https://blog.naver.com`)에서 온 메시지만 받음.
- 파일 칸 갈고리(검수 L6): `data-blog-helper-arm="만료ms:난수"` — 난수가 없거나 만료가 20초보다 먼 값은 무시, 가로챈 input 에는 `순번:난수`를 붙이고 확장은 이번 난수의 input 만 씀(같은 페이지 세계라 완전한 비밀은 아님 — 페이지가 할 수 있는 최악은 파일 선택 창을 막는 것).
- 동영상: **사람이 업로드 버튼을 누르지 않게** 확장이 '동영상' 업로드로 넣음. 큰 파일은 메시지(base64)로 옮기지 않고, 확장 출처의 숨은 iframe(`video-bridge.html`, web_accessible_resources)이 토큰으로 이 서버에서 스트리밍으로 받아 `File` 로 만든 뒤 **비공개 MessageChannel** 로 콘텐츠 스크립트에 넘김(복사 없음). 받을 파일 목록은 서비스 워커가 **일회용 표**(2분, 같은 탭, 이 서버의 `/api/발행/파일` 주소만)로 묶어 두므로 네이버 페이지 스크립트는 받기를 시키거나 파일을 엿볼 수 없고, 토큰은 iframe 밖으로 나가지 않음. 파일 선택 창은 열지 않음(가로챔). 업로드·인코딩이 끝날 때까지 기다리며(최대 30분, `처리중` 신호), 제목·설명 창이 뜨면 블록 값으로 채우고 이름이 정확히 '완료'인 버튼만 누름. 오류 표시·시간 초과·문서 끝이 아닌 곳에 들어가면 멈춤. 선택자·흐름은 **실측 필요**.

## 9. 발행서버가 읽는 패키지 형식(패키지를 만드는 쪽)

배치(규약 2.4) + 업로드 사본(2.5). 발행서버가 쓰는 필드:

| 필드 | 쓰임 |
|---|---|
| `제목`·`블록`(필수)·`편ID`·`여행ID`·`일차` | 글. `편ID` 없으면 파일 이름 `패키지_<편ID>.json` 에서 |
| `태그`(최대 30)·`카테고리`·`공개`·`AI활용표시` | 6절 |
| `승인` | `{"상태":"승인됨","승인자","시각","지문","파일지문","파일수","서명"}` — **서버가 확인 창·화면 클릭 뒤 써 넣는 값**(5.4). 직접 쓴 `승인됨`은 무효, 예약 발행할 패키지는 패키지 파일로 승인해야 업로드 파일이 묶임 |
| 사진·동영상 블록의 **`업로드`**(권장) | 경로 문자열(목록) 또는 `{"파일"(또는 "경로"),"id","업로드묶음"}`. 같은 뜻으로 `업로드사본`, `파일` 도 받음. `지도` 블록에 업로드가 없으면 `이미지`. 동영상 id 는 블록의 `영상` |
| `업로드묶음` | 항목 안, 또는 블록의 번호 목록·숫자 하나. 없으면 계산 |
| 경로 기준 | **패키지 JSON 폴더 기준 상대 경로**(권장). 폴더 이름이 `발행`이면 그 위 폴더 기준도 받음(규약 `작업/지도/1일차.png`) |
| 허용 폴더 | 패키지 폴더(이름이 `발행`이면 그 위 폴더). 밖을 가리키는 경로·네트워크 경로(`\\서버\…`)는 열지 않고 제외+경고 |
| `여행ID` 추정 | 없으면 `여행/<여행ID>/발행/` 이고 그 위에 `여행정보.json` 이 있을 때만 폴더 이름 |

## 10. 여행 스튜디오 서버에 붙이기(모듈 인터페이스)

```python
import sys
from pathlib import Path
sys.path.insert(0, str(Path(__file__).resolve().parents[2] / "공용"))  # 참고구현/공용
import 발행서버 as 공용   # 표준 라이브러리만

설정 = 공용.load_settings_file(스튜디오폴더 / "설정.json")   # 공통 키(2.3). 함수로 줘도 됨 — 옛 키도 읽음
api = 공용.PublishAPI(
    공용.TripFolderSource(스튜디오폴더),                  # 여행/*/발행/패키지_*.json, 키 '<여행ID>/패키지_<편ID>'
    port=8765, server_name="여행스튜디오",
    settings=lambda: 설정,
    on_event=lambda 종류, 작업: 로그에_적기(종류, 작업),     # 작업이력.json·로그/ 연결
)

# 요청 처리기 안에서(GET·POST·OPTIONS 모두):
if 공용.PublishAPI.handles(self.path):
    본문 = self.rfile.read(int(self.headers.get("Content-Length") or 0))
    r = api.handle(self.command, self.path, self.headers, 본문)   # → Response(status, headers, body)
    self.send_response(r.status); [self.send_header(k, v) for k, v in r.headers]; self.end_headers()
    r.write_to(self.wfile)          # ← r.body 대신(큰 동영상·Range 응답은 나눠 보냄, 4.2)

# 화면의 [확장 연결]: api.pairing.issue_code() / api.pairing.connections()
# 화면의 [네이버 임시저장]: api.jobs.create(패키지, "임시저장") 후 공용.open_in_browser(공용.write_url(api.settings()["블로그ID"]), api.settings()["브라우저"])
```

## 11. 발행서버(단체 블로그) 명령

학습자 프로젝트 폴더에서(공용 도구가 `도구/`에 복사되어 있음. 참고구현 안에서는 `공용/발행서버.py`):

```bash
python 도구/발행서버.py --연결만                                        # (8회차) 글 없이 연결만 — 3.1
python 도구/발행서버.py --연결코드                                      # 이미 켜진 서버로 연결할 코드(5분)
python 도구/발행서버.py --설정 블로그설정.json --패키지 발행/패키지_칼럼.json --작업 임시저장 --열기
python 도구/발행서버.py --작업보기 n20261007-101233-a3f9 --패키지 발행/    # 결과(JSON)
python 도구/발행서버.py --패키지 발행/ --확인                             # 서버 없이 묶음만
python 도구/발행서버.py --진단보기                                      # (실측) 확장이 보낸 최근 진단 요약·경로 — 5.3
python 도구/발행서버.py --승인 발행/패키지_칼럼.json                     # (사람) 확인 창으로 글 승인(서명) — 5.4
python 도구/발행서버.py --설정 블로그설정.json --자동예약켜기             # (사람) 확인 창으로 자동 예약 허락
python 도구/발행서버.py --설정 블로그설정.json --패키지 발행/ --카테고리확인  # (네이버 공개 목록 조회, 선택)
```

옵션: `--설정 블로그설정.json`(2.3 — `블로그ID`·`브라우저`·`자동예약발행`·`편사이간격분`·`예약최소여유분`·`중단판정분`) · `--열기 [블로그ID]`(빼면 설정의 `블로그ID`) · `--브라우저 chrome|edge|default` · `--편사이간격분` · `--예약최소여유분` · `--중단판정분` · `--승인 <패키지>`·`--승인취소 <패키지>` · `--자동예약켜기`·`--자동예약끄기`(켜기는 확인 창, 옛 `--자동예약발행` 옵션은 없앰 — 설정 파일의 false 를 이길 수 없게) · `--예약시각 2026-10-08T09:00:00+09:00` · `--만들기만` · `--포트 8765` · `--상태폴더` · `--연결만 [--연결되면종료]` · `--연결목록` · `--연결해제` · `--진단보기` · `--진단폴더`. 명령줄 옵션이 설정 파일 값보다 이김.
